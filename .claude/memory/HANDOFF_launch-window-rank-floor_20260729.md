## §4 이 세션에서 밝혀진 구조적 사실

1. **소재(ad) 레벨 이력이 전혀 없다** — `naver_entity_snapshot`은 adgroup 8,070행/campaign 362행뿐, ad는 0행. 쇼핑 그룹은 `use_group_bid_amt=0`이라 **실제 작동 레버가 소재 입찰**인데 그 이력이 없어 "어제 왜 이랬나"를 원리적으로 못 푼다.
2. **avg_rank가 머리 키워드를 가린다** — 07-29 오전 그룹 avg_rank 3.04인데 Jino 육안 확인 머리 키워드 7위. 07-28 검색어별 실측은 1.70~2.16위였다.
3. **일예산 통제가 지출을 못 막는다** — 300,000원은 네이버 실제 설정값이 맞지만, 우리 가드레일은 "증액 제안 차단" 전용이고 **이미 나가는 지출을 멈추는 자동 규칙이 코드에 없다**(07-28 507,299원 = 예산의 169%). 네이버 측 `CAMPAIGN_LIMITED_BY_BUDGET` 하드컷도 이 계정에서 관측되지 않음.
4. **당일 그룹 grain 광고 데이터가 없다** — `naver_keyword_hourly`는 그룹×시간 grain인데 **전날치만 00:18에 일괄 적재**. `naver_hourly_snapshot`은 캠페인 grain·전환 컬럼 없음. 그래서 "오늘 그룹별 성과"를 API 직접 호출 없이는 못 낸다.
5. **07-29 07:37 그룹 예산 외부 변경** — `grp-…070523564` 자체 일예산 200,000→300,000. `naver_change_log` 0건, `naver_sa_writer`에 그룹 단위 예산 쓰기 함수 자체가 없음 → 우리 시스템 아님 확정, 주체는 특정 불가.
6. **검색어 데이터는 `/stat-reports` = 일 단위** — 머리 키워드 시간별 CPC 실측은 네이버가 제공하지 않는다.
