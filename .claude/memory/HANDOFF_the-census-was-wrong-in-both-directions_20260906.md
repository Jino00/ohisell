## 2. ★★ 이 세션의 발견 — 계기판이 «반대 방향으로도» 틀렸다

어제(09-05) C1·C2·C3가 찾은 「계기판 지체」 네 건은 **전부 같은 방향**이었다 —

그런데 09-03 census가 이 행을 **「손이 아예 없다」**로 세었다.

★**이쪽이 더 비싸다.** 「됐는데 표가 낡음」은 자랑을 못 하고 끝나지만,
**「안 됐다고 적혀서 아무도 안 보는 것」은 이미 있는 걸 다시 만들게 한다.**

## 6. ★★ 내 실수 — 등록부를 두 번 지웠다 (교훈을 낱말로 좁게 쓴 대가)

- **09-05(n=88 종결)**: `git checkout <다른브랜치> -- <체인파일>` 이 방금 쓴 `close`를 지웠다.
  그때 교훈을 이렇게 적었다 — *「등록부는 `chain.sh`로 쓴 직후에 커밋하고 그 사이에 어떤 **checkout**도 끼우지 않는다」*
- **09-06(n=90 착수)**: 같은 일이 **`git reset --hard origin/main`**으로 재발했다.
  등록 행이 커밋 전에 날아가 **n=90이 등록부에 없는 채로 한 시간을 돌았다.**
  잡은 건 훅도 자기검증도 아니고 **Jino의 질문**(*「이 내용을 체인 n=90에서 이어가야 하는데, 어떻게 옮겨?」*)에
  답하려고 등록부를 실측한 순간이었다.

★**일반형**: **교훈을 «낱말»로 쓰면 그 낱말만 피한다.** `checkout`이라 적었더니 `reset`이 그대로 빠져나갔다.
고친 모양 —

> 등록부는 **쓰기와 커밋을 한 명령 안에 붙인다.** 그 사이에 워킹카피를 다시 쓰는
> 어떤 git 명령도(`checkout` · `reset` · `switch -f` · `stash`) 끼우지 않는다.

두 번 다 **잃은 것은 0**이다(첫 번째는 `origin/main`에서 복구, 두 번째는 재등록).
그러나 두 번 다 **바깥의 무언가가 잡았지 내 규율이 잡은 게 아니다.**
