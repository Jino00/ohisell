## 6. ★적대 리뷰가 짚은 것 — 이 세션의 진짜 산출물

리뷰는 **1R FAIL(P1 3) → 2R PASS**였고, 세 P1이 전부 같은 뿌리였다: **계약 §4가 이름으로 지목한 표면 셋 중 둘이 테스트로 하나도 안 지켜졌다.**

| 살아남은 변이 | 뜻 |
|---|---|
| `schemas.py`의 `cost_guard` 선언 **1줄** 삭제 → 백엔드 **7,441 전건 초록** | `response_model`이 키를 지워 **배너가 영영 침묵**하는데 아무도 모른다 |
| `<CostPriceHistoryPanel/>` 호출부 삭제 → 프론트 **1,261 전건 초록** | 이력이 DB엔 쌓이는데 **원가 메뉴엔 없다** |
| 매핑 시트 경로 기록 호출 2개 삭제 → 전건 초록 | 「4경로 어느 것으로 바뀌어도」 중 한 경로가 무방비 |

★★**리뷰어의 한 문단이 핵심이다**: *"규율을 세워 두고 그 규율을 좁게 집행했다."* 나는 테스트 파일 헤더에 **「★HTTP body를 단언한다」·「★표면 절단 변이를 상정한다」**고 직접 써 놓고 **세 자리 중 한 곳에만 적용**했다. 형제 신호 `cost_drift`엔 같은 단언이 **이미 있었고** 그 docstring이 *"이 단언이 P1-1을 잡는다"*라고 적어 두기까지 했다. ⇒ **D-NAO-227의 일반형 「집행 지점을 좁게 쓰면, 규칙을 지켜도 목적이 샌다」의 재발.**

- 1R 생존 변이 **12종 → 전건 사살**(앵커 1회 매치 assert → 치환 확인 → 실행 → SHA-256 복원 확인)
- 2R이 **자기충족 검사**를 따로 했다: 새 단언이 mock 문자열을 되읽는 척만 하는지 재는 변이 4종 — 전건 KILLED. 특히 `data={priceHistory}`를 빈 리터럴로 치환해도 죽으므로, SUR-7b는 「패널이 있다」가 아니라 **「API → state → 패널까지 데이터가 흘렀다」**를 잰다.
- P2 처분: **9 채택 / 1 이월 / 1 기각**(alembic heads 10개 주장 — 2회 측정 모두 단일 head `cphist1s1a`로 재현 불가) / 2R 신규 P2-13 **채택**
