## 3. 확정된 결정사항
- **「거래명세서확인」은 SellC에서 누를 수 있다** — 카나리로 실증됨. 요청 규격(ref 106 §3)이 실제로 통했다.
- **사전 GET 게이트가 멱등성 `[미상]`의 유일한 방벽이다** — 실험으로 답하지 않는다. 「이미 CI인 건에 POST」는 **영구히 안 한다**(계약 §1 비목표).
- **자동 재시도는 층 불문 금지** — TTL 초과는 재임대가 아니라 `unknown` 종결 + 잠금.
- **`unknown`을 `failed`로 접지 않는다** — 「안 됐다」와 「갔는지 모른다」는 다른 사실이고, 접으면 그게 재시도 경로가 된다.
- **원장 미반영 종결(`unknown`·`succeeded`·`already_confirmed`)은 재수집 전까지 잠근다.** `failed`만 예외(= `success:false` 확정 = 아무 일도 안 일어났음이 확인된 유일한 상태).
- ★**신선도 축 문구에 「확인」을 쓰지 않는다** — 이 화면에서 「확인」은 「거래명세서확인」(누르는 동작)이다.
- **성공 응답은 구조화돼 있다**(`returnMessage`·`code`·`result`). **실패 응답의 모양은 미상** — 원문 보존이 유일한 재료.
