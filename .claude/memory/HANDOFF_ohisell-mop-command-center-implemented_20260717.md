## 4. ★★ 이번 세션의 교훈 (다음 세션이 반복하지 말 것)

1. **`npx tsc --noEmit`은 이 저장소에서 아무것도 검사하지 않는다.** `tsconfig.json`이 `{"files": [], "references": [...]}`(solution-style)라 파일 0개를 보고 조용히 성공한다. **실측**: `const x: number = "string"` 주입 → `--noEmit` 출력 없음(통과) / `tsc -b` → TS2322 검출. **타입 검증은 반드시 `npx tsc -b`.** (내 계획서가 `--noEmit`을 지시했고 서브에이전트가 "통과"라고 보고했는데 **둘 다 무의미**했다.) → `format.test.ts` 주석에 영구 기록.
2. **`alembic/env.py`의 `fileConfig()`는 기본이 `disable_existing_loggers=True`** → 이미 만들어진 **모든 로거를 벙어리로** 만든다. `test_migration_one_running_index.py`가 그 경로를 타서 뒤 테스트의 로그 단언이 전부 실패("격리는 통과, 전체는 실패"의 정체). **전체 스위트를 돌려서 발견 — 격리만 봤으면 못 잡음.** 수정함(`disable_existing_loggers=False`). prod는 무사 실측.
3. **격리 통과는 필요조건일 뿐**(원칙22). 밸브를 **뮤테이션 테스트로 검증**했다 — `_norm_bid`를 passthrough로 고의 파괴 → 5,000행 폭증 테스트가 실제로 FAIL → 복구 후 통과. 통과만 보고 넘어가지 않음.
4. **"조회 실패 → 빈 데이터"는 거짓말이다.** `.catch(() => setData({total:0, rows:[]}))`가 **7곳**에서 반복됐고, 실패가 "최근 30일 우리가 집행한 변경이 없습니다"로 렌더됐다. D-47-h는 "0이면 0이라 말하라"이지 "모르면 0이라 말하라"가 아니다. 개별 수정 대신 `useAsyncData` 훅으로 **기본값을 바꿔** 재발 차단.

## 5. codex 대화형 검증 (원칙19 — 일방 수용/기각 안 함)

주요 지적과 내 대응:
- **[P2] 콤마 형식 `"1,450"`** → **부분 동의**: prod 실측(91,005행 전부 integer·비수치 0)상 미관측이라 콤마 파싱은 추정(추정 금지) → 넣지 않음. 진짜 문제인 "조용함"만 `log.warning`으로 해소(None=수집누락은 정상 경로라 제외 — 장애 시 91,005건 경고 폭증 방지).
- **[P2] 되돌림 레이스** → **동의, 단 codex의 순진한 수정은 행마다 조회 = 91,005 쿼리/일**(쓰기 폭증을 읽기 폭증으로 치환) → 루프 전 1회 배치 적재로 O(1).
- **[P2] 3값 케이스** → **동의, 내가 놓침**. 규칙 단순화: 직전 관측 이후 우리가 썼다면 before는 언제나 `our_target`.
- **★[P2] "우리 조작 N회"가 외부 변경 감지를 우리 실적으로 셌다** → **동의, 이 화면의 중심 원칙을 정반대로 뒤집는 결함.** prod의 dry_run=False 15건이 **전부 외부 감지**라 "우리 조작 15회"가 떴을 것(실제 0). 게다가 내 밸브가 이 거짓말을 매일 키운다. → `EXECUTION_ACTIONS`(harness 매핑에서 **파생**, 하드코딩 금지) + `actor` 필터.
- **[P2] 실패한 쓰기 집계** → 동의. `after_value IS NOT NULL` 추가(이 코드베이스가 이미 정한 성공 판별 규약인데 내 밸브와 불일치였음).
- **[P2] 캠페인별 아닌 계정 합계** → 동의. **D-47-c 정면 위반** — 오늘 N=1이라 우연히 맞아 보일 뿐 카나리 확대 순간 틀림.
- **[P2] 광고비 0 → "캠페인 없음" 단언** → 동의. **자기모순 화면**(위에선 없다는데 아래 리스트엔 04가 보임). reason은 측정한 것만 말하도록 수정.
