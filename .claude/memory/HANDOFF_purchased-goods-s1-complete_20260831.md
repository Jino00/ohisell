### 4-2. ★★대상 판별은 시스템이 «원리적으로» 못 한다 — 그래서 안 한다

prod 실측:
```
assembly / approved / 구성 있음    19레시피  392 SKU   ← 조립품(확정)
assembly / draft    / 구성 0줄     77레시피  473 SKU   ← 후보
imported_goods / approved          3레시피   58 SKU   ← 수입품
```
계약이 말한 「매입품 50레시피 318 SKU」는 **구성 0줄 473 SKU의 부분집합**이다. 나머지는 **조립품인데 아직 구성을 안 세운 것들**(r99 종이질감 44 · r11 강화유리코팅 31 · r83 유리코팅 25 · r66 빛반사매트 18 · r36 오픽스 15)이고 — **`form_factor`가 둘 다 `bar`, 파서 `note` 모양도 같아 가르는 신호가 없다.**

⇒ 묶음은 「대상」이 아니라 **「분류 필요」**이고, **레시피명이 묶음의 얼굴**이며, 화면이 *「필름 같은 조립품 초안도 섞여 있다」*를 문장으로 말한다. **이름으로 자동 배제하지 않는다** — 그게 곧 「시스템이 고르는」 것이다.

### 4-6. ★★변이표의 SURVIVED를 그대로 믿지 마라

재주입에서 N9·N10·N12가 전부 SURVIVED로 읽혔는데, 실제로는 **치환 문자열이 한 번도 매치되지 않았다**(`JSON.stringify(body)`가 파일에 두 번 나와 엉뚱한 함수를 건드렸다). 줄 번호를 `assert`로 못 박고 다시 돌리니 **셋 다 KILLED**였다.
