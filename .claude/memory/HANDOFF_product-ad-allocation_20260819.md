## 5. ★이 세션이 배운 것 (교훈 후보 — L1 등재 필요)
1. **「컴포넌트 테스트가 초록」 ≠ 「페이지가 그 컴포넌트를 쓴다」.** 변이 M11·M12(배너·미배분 행 호출을 페이지에서 삭제)가 렌더 테스트 11종을 전부 통과하고 살아남았다. 이 저장소가 세 번 당한 «백엔드는 세는데 화면이 안 읽음»의 컴포넌트판. 배선 자체를 고정하는 테스트가 필요하다.
2. **`npx tsc --noEmit -p tsconfig.json`은 이 저장소에서 아무것도 검사하지 않는다.** `tsconfig.json`이 `"files": []` + references만 있는 **솔루션 파일**이라 `-p`로는 0개 파일을 검사하고 exit 0을 낸다. 세 번 「초록」을 확인하는 동안 타입 검사는 한 번도 안 돌았고, 배포 직전 `npm run build`(=`tsc -b`)에서야 드러났다. **검증 명령이 정말 무언가를 재는지부터 재라.**
3. **잔차(residual) 정의가 fail-safe이려면 «분자»가 화면에 실제로 실린 것이어야 한다.** 「전체 − 배분합」의 배분합을 다른 모집단으로 세면 잔차 정의의 안전성이 그 경로에서만 사라진다.
4. **변이 주입은 커밋된 상태에서만 안전하다** — D-NAO-203이 이미 기록한 교훈을 같은 세션에서 재현했다(미커밋 P1 수정이 `git checkout --`로 날아감).
