## 3. ★다음 세션이 반드시 알아야 할 함정 5개

1. **`created_at`은 UTC다.** KST 날짜로 자르면 이 세션 작업이 «없는» 것처럼 보인다(QA에서 실제로
   45행이 0행으로 나왔다). 이 세션 입력분 = `created_at >= '2026-08-11 16:00'`.
2. **원가 조인은 `channel_id IN (1,3)`이 아니다.** 엔진은 `Channel.platform='coupang'` 전체를 본다
   (`intelligence._cost_master` 716-720). **합격 판정은 라이브 API `by_option.has_cost`로 한다.**
3. **커버리지는 창을 밝혀야 한다**(교훈 #263). 「0%」만 말하면 거짓말이 된다.
4. **정산 `coupang_rg_settlement_fee`는 sentinel(`vendor_item_id=''`) 행만 센다.** 전부 SUM하면 이중계상.
5. **파생 master는 `memo LIKE '%D-CPP-41%'`로 찾는다.** `LIKE '%SET'`은 도어락 master 6건을 같이 잡는다.

정정 경로: 생성한 master 7 + 매핑 55(45+10)의 id 전량이 세션 scratchpad `rollback.json`에 있다.

## 5. Jino 결정 대기 — D-16 재검토 (결정 4)

**확정된 것**: D-16의 근거 「`sell_type=2P` 0행 → 이중계상 없음」은 **무효**다. 2P는 지금도 0행인데
PA 광고비의 **97.28%가 RG로 팔리는 옵션**에 쓰이고 광고비 상위 5개 옵션의 **3P 주문은 전부 0건**이다.
라벨이 판매경로를 뜻하지 않는다(교훈 #261). D-16의 감시 장치(`ad_xlsx_rg_overlap>0`)는 2P 라벨을
보므로 **이 형태를 원리적으로 못 잡는다.**

**미확정**: 그래서 「전액 차감」을 바꿔야 하는지. 지지 7 / 반박 6(ref 56 §6).
- 지지: 70일 총액비 1.0359 · 누적차 0 주변 진동 · ID 공간 동일(81/91) · 그로스 캠페인 실재
- 반박: PA 있는데 정산 0인 주 4주 · PA 없던 시기에도 정산 90,841원 · 주간비율 0.44~1.98
- ★**1차 출처**(ref 17 §7, 2026-06-08 윙 라이브) 검산: 판매수수료 102,950 **정확 일치** ·
  풀필먼트 206,254 **일치** · **광고비만 338,648 vs 245,655 = −92,993 불일치**
  → 수집이 틀린 게 아니라 `totalAdSalesDeductionAmount`가 담는 것이 미특정

**금액**: 정렬 창 기준 −1,496,728원 적자 ↔ +2,529,277원 흑자가 이 하나로 갈린다.

**질문을 닫는 단 하나의 행동**: 윙 > 정산 > 로켓그로스 정산현황 > **「광고비 내역」 탭**을 열어
07-13~08-09 명세가 광고센터 PA와 같은 캠페인/옵션/일자인지 본다.
- 이번 세션이 안 연 이유: 상주 데몬들이 Chrome 수명에 로그인을 걸고 있어 세션을 깨면 광고비·정산
  파이프라인이 멈추는데 Jino 출장 중이라 재로그인 불가. (지금은 어차피 로그인이 필요한 상태다 —
  §4(1)을 하고 나면 이 조사도 같이 가능해진다.)
- 대안: 데몬 쿠키를 재사용하는 **읽기 전용 수집기**를 별도 계약으로(내부 API
  `POST /tenants/rfm/v2/settlements/...`, 경로는 ref 17 §7에 있다).

## 7. 교훈 #259~#264

- **#259** 「감시 규칙이 있다」와 「임계값이 지켜진다」는 다르다 — `max_age_days` 3.0→999 변이가
  종전 테스트 49건을 전부 통과했다. 감시 테스트는 세 겹(존재·자기 테이블·임계값).
- **#260** «없다»는 관찰에서 «전체를 뺀다»는 결론이 안 나온다 — 「3P가 비었다」로 계정 전체를
  자동수집에서 뺐는데, 같은 소스가 나르는 RG축이 63일 3,931만원이었다.
- **#261** 라벨이 실질을 뜻한다고 가정한 감시는 실질이 바뀌면 원리적으로 못 잡는다(D-16).
- **#262** 파생 원가는 «값»이 아니라 «식»으로 기록한다.
- **#263** 커버리지 «0%»는 창을 밝히지 않으면 거짓말이 된다(적대 리뷰 P1-2).
- **#264** 접근 차단은 «호스트 단위»가 아니라 «경로 단위»일 수 있다 — 한 경로로 호스트 전체를
  판정하지 말고 문제 파이프라인이 **실제로 쓰는 경로**를 재고 **클라이언트 로그를 직접 봐라**.
