## 5. 알려진 이슈 / 주의사항

### 5-A. ★왜 같은 지시가 4번 반복됐나 (기제 — 다음 세션이 반드시 알 것)

*"성과 등급별로 모든 api"* 지시가 최소 4회 반복됐다(2026-07-23 · 08-17 23:46 · 08-18 09:11 · 08-18 11:40). **잊어서가 아니다.**

- 08-17 지시 원문은 *"모든 api"*였는데, 그 세션이 **합격기준을 자기가 쓰면서** 범위를 광고(SA)로 좁혔다.
- 완료 QA는 §2 규정상 **«약속(합격기준) 대비 관측»만** 잰다 → 좁혀진 약속에 정직하게 대조해 **「달성」**을 줬다.
- 그 「달성」이 MEMORY 인덱스에 *"매트릭스 조립 완료"*로 올라갔다 → 이후 세션들이 미결 목록에서 뺐다. **잊었으면 미결로 계속 보였을 것이다. 완료로 닫혀서 아무도 안 본다.**
- 실측: ref 68 문서에 「스마트스토어·커머스」 언급 **0건**, ref 71 문서에 「등급·band」 언급 **0건**. 하루 차이로 만들어진 두 문서가 서로를 한 번도 참조하지 않았다.
- 거드는 요인: ref 68 제목이 「성과 등급 × API **『전 자료』** 조립표」인데 내용은 SA뿐 — **제목이 전체를 주장하면서 범위는 절반**이라 다음 독자를 속인다.

→ 이 구조는 **D-NAO-194에서도 그대로 재발했다**(§2-2 ⚠️). 잡은 것은 모델의 절차가 아니라 **Jino의 재점검**이다.

### 5-B. ★`__backfill__` 센티널 함정 — 하루에 2번 발생

이 저장소는 `__backfill__` 센티널을 **판정 경로마다 개별 배제**하며 **공용 필터가 없다.** 새로 쓰는 집계 SQL은 매번 배제를 다시 적어야 하고, 잊으면 **에러 없이 조용히 틀린다.**

- **1회차**: 코디네이터의 C-2 쿼리 → SHOPPING 매핑 비용 점유율을 60.0%로 오산(정답 **96.7%**). 90일 창에서 센티널 1행이 **31,550,746원/2,062행**. Fable의 발견 F5가 이 오류 위에 서 있었다 → F5 재작성.
- **2회차**: CROSS_ads A10의 「밴드 미부여」 그룹 → Fable이 재실측해 **센티널과 원 단위까지 일치**, 「신규 그룹」 추정 기각.
- ★기존 좌표를 따라간 실측 2건은 안 걸렸고 **새로 쓴 SQL만 걸렸다.** 공용 필터층 신설은 범위 밖으로 기록만 함.

### 5-C. 그 밖

- **커머스 축은 파워링크(WEB_SITE)에 원리적으로 못 붙는다** — 상품 매핑이 쇼핑 전용(파워링크 소재엔 `mallProductId` 없음). 90일 WEB_SITE 256그룹 매핑 **0개**, 비용 1,831만원 전량 교차 불가. 매핑 부실이 아니라 **지면 구조**다.
- **커머스×등급은 개선 축이 아니라 검증 축** — 상한 프록시는 0쪽에서만 결정적이라 「흑자 판정인데 스토어 매출 0」 **모순 탐지**만 성립. F12 실행 결과 band1/2 매핑 108그룹 **전수 모순 0건**, band3 4그룹만 상한=0.
- **커머스 렌즈는 좋은 밴드로 기운 표본** — 관측불가율 band1 7.8% vs band3 37.5%. 생존편향 각주 의무.
- **fan-out은 커머스만의 문제가 아니다** — 상품↔광고그룹 82.6%(580/702), 캠페인↔밴드 89.7%(39 중 35). 팽창률이 밴드마다 달라(band3 1.93x·band1 1.64x·band2 1.25x) **raw 합산은 밴드 순서를 뒤집는다**(raw band3>band1 → dedupe **band1 118.5M > band3 105.5M**).
- **`naver_entity`에 `entity_type='ad'` 행이 없다** — ad 롤업은 문서가 적은 「naver_entity 부모링크」가 아니라 `naver_adgroup_product.ad_id` 경유여야 한다(CROSS_ads B4가 정정).
- **PAO 완전 정지 유지** — `optimizer` 7/7 `none`, `auto_operate` 7/7 `0`.
