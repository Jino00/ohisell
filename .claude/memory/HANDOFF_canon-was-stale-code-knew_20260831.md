## §1. 한 것 — 계약 **5/38 → 9/38** (P1 4항목 전부)

### ★★ 라이브가 정본을 두 번 반증했다

**① `changed_at` 시간대 (P1-c) — 답이 「KST냐 UTC냐」가 아니었다**

정본 §14는 「`naver_proposals.created_at`·`naver_change_log.changed_at` = **UTC**(SQLite now())」로 단정하고 있었다. prod 전건 카운트 결과 **둘 다 틀렸다** — 시간대는 컬럼이 아니라 **«쓰는 주체»가 정한다**:

| 컬럼 | KST(소수점 O) | UTC(소수점 X) | UTC 쪽의 정체 |
|---|---:|---:|---|
| `naver_change_log.changed_at` | **7,786** | **8** | optimizer_change 3 · auto_operate_change 3 · set_user_lock 2 (전부 08-10 이전 레거시) |
| `naver_proposals.created_at` | **5,043** | **2,127** | KST 쪽은 trigger_pacing 5,039 + trigger_cpc_spike 2 + bid_down 2 |

**판별 규칙(기계적)**: 값에 **소수점이 있으면 `kst_now()` 명시 스탬프 = KST**, **없으면 `server_default=func.now()` = UTC**. SQLite `CURRENT_TIMESTAMP`엔 소수점이 없기 때문이다.

★**코드가 이미 답을 갖고 있었고 정본만 낡아 있었다** — `improvement_events.py`(*"writer는 전부 `changed_at=kst_now()`"*) · `trigger_watch.py`(*"`created_at=kst_now()`로 명시 스탬프하는 **유일한**"*) · `budget_envelope.py`. 다만 **그 주석들의 단정어에도 반례가 있다** — 「전부」에 8건, 「유일한」에 4건. 그래서 문장을 옮기지 않고 숫자로 적었다.

⇒ 계약 v6의 「`changed_at`=KST」 주장이 **옳았다**. 고친 쪽은 **정본**이다(§14 경고문 전면 개정 + §11 8행 신설).

**② §14 「부품 생존」 레시피 (P1-b) — 반증에 붙은 «수정안»도 틀려 있었다**
