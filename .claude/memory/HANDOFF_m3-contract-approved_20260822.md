## 5. 알려진 이슈 / 주의사항

### 5-1. ★★M2는 08-28 전엔 원리적으로 못 닫는다
계약 §6 권장 순서가 `a → (b∥c) → **d** → z`이고 **S2 ①~⑤는 M2-d의 산출물**인데 진입 조건이 「M2-a 배포(08-21 11:0x) +7일 = **2026-08-28**」이다. ref 88 §4 관측표도 S2 행을 「08-28 이후」로 적어 뒀다.
⇒ **직전 인계 §9-5가 M2-z를 우선순위 2번으로 올린 것과, 그 인계가 지정한 입력 정본(ref 88 §4)이 서로 어긋났다.** 이번 세션은 관측 가능한 11항목만 **「M2-z 1차」**로 판정했다. **전체 M2-z는 M2-d 완료 후.**

### 5-2. ★ref 88 §4 표의 기대값 「≈871」은 오기 — 인용 전 알고 갈 것
871은 「`pc_bid_weight` **비-100 값**의 서브셋」이고 `IS NOT NULL` 총계는 원래부터 **≈1,013**이다. 표를 문자 그대로 읽었으면 M2-b2 ①이 **달성인데 미달로** 나왔다. (문서는 안 고쳤다 — 읽기 전용 세션이었다.)
같은 문서의 **§5-5는 존재하지 않는다**(§0~§5뿐). 「좁힌 카운트」 정의의 실제 위치는 **§3-2**이고, 그 §3-2의 SQL 스케치(`target_type='search_term'`)를 **문자 그대로 쓰면 오답**이다 — 그 20건은 전건 `proposal_type='search_term_promote'`(제외와 무관). 진짜 모집단은 `target_type='search_term_semantic' ∧ proposal_type='search_term_exclude'`.

### 5-3. ★★「광고 조작이 완전히 멈춰 있다」는 과장이다
§4-0 P2 실측: `dry_run=0` 행을 action으로 가르면 —
- **외부 변경 감지 514건**(`external_bid_change` 432 · `external_keyword_added` 72 · `external_status_change` 10) — `proposal_id`·`executed_at` **전건 없음** = 우리 집행이 아니다. **최신 08-21**.
- **제안 기반 실집행 72건**(`update_bid` 69 · `update_budget` 2 · `budget_down_pacing` 1) — **전건 2026-07-30**. ⇒ 「07-30 이후 0건」은 **참**.
- **비-제안 운영 조작 9건** — `manual_emergency_stop` 5(07-30) · **`update_guardrail_params` 2(08-11)** · **`set_user_lock` 2(08-10)**. ⇒ 이건 07-30 이후에도 있었다.
**「0건」이라 말할 때 무엇의 0건인지 밝힐 것.**
그리고 ★**`external_bid_change` 432건이 08-21까지 살아 있다** = 대행사가 계속 입찰을 바꾸는 중 ⇒ ref 91 §7-2 **M4-b 「대조군 분할」의 원료가 라이브로 확인됐다**(소관: M4 계약).

### 5-4. ★`naver_search_term_exclusion.match_type`은 정수 코드다
**1=exact · 2=phrase** (문자열 아님). `WHERE match_type='exact'`로 조회하면 **헛것을 본다**. NULL 잔존 **1,587/3,990(39.8%)** — 정상적 부분 커버리지인지 스윕 누락인지 **미확인**(§6 ⑧).
