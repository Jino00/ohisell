## 1. 먼저 답한 것 — 「마스터 버튼」과 배너 버튼은 다른 층이다

| | 위치 | 무엇을 깨우나 |
|---|---|---|
| **전체 갱신** (7a716d5, 08-05) | 대시보드 **페이지 안** | 수동 수집 **6큐 전부**(`ALL_REFRESH_SPECS`) |
| 🔴 광고비 배너 「지금 갱신」 | **전역** 배너 (08-03~) | ofix 광고비 하나 |

### 「안 되는 것처럼 보인」 원인은 전부 버튼 밖에 있었다
1. **낡은 에러 문구** — 배너의 *"ofix 판매분석 갱신 실패 · 로그인 필요"*는 **08-05 23:03의**
   에러였다. 33시간 동안 시도 자체가 없었을 뿐, 눌러 보니 47초 만에 성공했다. → §3이 이걸 고쳤다.
2. **테더링 IP 403** — Jino가 외부에서 아이폰 테더링 중이라 nginx 허용목록 밖(`211.234.196.158`).
   페처 데몬은 살아 있는데 폴링이 전부 403이었다. **정책상 모바일 IP는 허용목록에 넣지 않는다**
   (스니펫 주석: ISP 재할당 위험). 사무실 회선(`183.99.236.174`) 복귀로 자동 해소.
3. **Wing 로그인 만료** — Chrome 창(CDP 9222·9223)이 쿠팡 로그인 페이지에 멈춰 있었다.
   Jino가 로그인하자 즉시 성공. ⚠️ **그 창을 닫으면 안 된다**(`JSESSIONID`=세션 쿠키).

### ⚠️ 내가 한 오독 — "RG 정산 4일치 밀렸다"는 **틀렸다**
`last_success_at`이 08-03에 멈춘 걸 밀림으로 읽었으나, 로그는 `RG: 열거 5개 / prod 결손 0`.
정산은 **주간 캐던스**라 08-03이 마지막 회차인 게 정상이다. 오늘 받아온 건 정산이 아니라
`PRODUCT_SIZE_COMPARISON`이고, 페처가 그건 **다른 엔드포인트**로 push한다(`_rg_push_xlsx`).

## 3. 무엇을 고쳤나

**PR #237** — 광고비 배너에서 `stale` 갈래 제거(신선도 배너가 24h에 먼저 뜨므로) + 실패 문구에
**시각**과 **실제 사유** 표기. 빨강 배너는 「버튼으로 못 고치는 것」(쿠키 만료·크론 꺼짐) 전용이 됐다.

**PR #244** — 맥락 없는 Opus 리뷰어 1기의 적대 리뷰가 **P1 2건**을 더 찾았다:
- `failed` 항목에서 **경과가 통째로 사라졌다** → `· 마지막 성공 N일 전` 추가
- `/collection-status` 하나가 죽으면 **전면 실명** → 스트림별 try + `state='unknown'`
- 파생: 워치독이 `unknown`을 조용히 버렸다(`age_hours=None`) → 나이 무관 즉시 알림

되돌림 시뮬레이션으로 거짓 초록이 아님을 확인(P1-1 되돌리면 5건 실패 / P1-2 되돌리면 1건 실패).
CI 전건 통과 · vitest 235 · pytest 4,974 · 백엔드 무중단 배포(다운타임 0초).

## 4. ⚠️ 아직 라이브로 못 본 것
- **실패 문구의 실제 렌더** — 4스트림이 전부 `fresh`라 배너가 안 뜬다. 다음에 실패/24h 경과가
  뜰 때 `(MM-DD HH:MM) · 마지막 성공 N일 전` 표기를 **눈으로** 확인해야 종결.
- **P1-2 가드의 prod 실동작** — 고의 장애를 낼 수 없어 **코드 해시 동일성**까지만 확인했다.

## 5. 이월

   `COUPANG_WING_RG` 08-03 15:22 · `RG2` 08-03 17:11). 화면이 **"정산 최신"과 "수집 실패"를

   RG 회차 계약(`refresh-complete`)을 건드려야 하므로 **계약 1장 필요**. 쿠팡 손익 정합 트랙.
2. **배포 스탬프 CAS를 내용 해시로** — 교훈 #171 참조. 오늘 **세 세션**이 같은 오탐에 막혔다.

4. **테스트 TZ 미고정** — `errAtText` 전문 고정 가드는 CI(ubuntu, UTC)라서 유효하다.
   누가 `TZ=Asia/Seoul`을 주면 **조용히 무력화**된다.

## 6. 이 세션에서 확정된 사실 (다음 세션이 다시 조사하지 말 것)
- 광고비 배너와 신선도 배너는 **같은 행·같은 필드**(`_cookie_row(db).last_success_at`)를 읽는다.
  코드로 확인(`ad_cost_sync.cookie_status` vs `refresh_status`) — 우연이 아니라 구조적 중복이었다.
- 임계는 신선도 **24h**(warn)/48h(critical), 광고비 stale **26h**. 신선도가 항상 먼저 뜬다.
- RG 최소간격 **3600초**(버튼 전용). 08-07 13:30 실행 후 14:30에 자동 실행됨을 실측.
- prod DB는 SQLite `backend/ohisell.db`(1.7GB), 백엔드는 pm2 `ohisell-backend-8011/8001` 블루-그린.
