- ❌**「A_제외키워드 그룹에서 그 외 모든 검색어를 제외」는 불가** — ⓐ쇼핑엔 **화이트리스트 개념이 없다**(키워드 엔티티 0건, 열거할 집합이 무한·미지) ⓑ**공식 타겟팅 12종에 「특정 검색어에만 노출」이 없다**(확인됨) ⓒ제외 칸에 상한이 있다

### 3-d. ★제외 키워드 운영 방법 (Jino 22:28 질문의 답 — ref 66 정본)

**핵심 전환: 개별 검색어를 하나씩 자르지 말고 «구문(phrase)»으로 묶어 자른다.**
우리·대행사가 전부 「일치」로 등록해 온 것은 **등록 습관**이었다(D-NAO-189). 예: 「짱구보호필름」·「짱구 보호 필름」·「짱구케이스」에 3칸 쓰는 대신 **「짱구」 1칸**.

**원칙 4**
1. **무엇을 자를지 = cost 순서.** 후보는 봉투 ①(전환 보호)을 통과해 **전부 전환 0**이므로 손실 = `−ad_profit` = **cost 그 자체**. 칸이 유한하니 「자를 만한 것 전부」가 아니라 **cost 큰 것부터 칸이 차는 데까지**(균일비용 배낭 → greedy 최적). 새 지표·새 문턱 **0**
2. **칸은 그룹별로 본다.** 평균 33.4건(48%)이지만 **그룹별 분포는 미상** — 이미 70에 붙은 그룹은 자르기 전에 **먼저 비워야** 한다
3. **반납(회수) 규칙이 반드시 있어야 한다.** 등록만 하고 안 빼면 100% 찬다. ★MOP 선례: 자동 등록은 주 1회인데 **복구는 「가장 최근 1건」만** → *"등록만 자동이고 회수가 빈약한 도구는 상한을 반드시 채운다."* 우리 `excluded → probation → restored` 상태기계가 이미 그 반대 설계. 비울 후보 = **검색어 사멸**(검색량 0)·**계절 경과**. ⚠️단 자르면 성과가 0행이라 「이제 괜찮아졌는지」를 알 수 없다 → **반납 판정은 인과 판정이 아니라 슬롯 예산 운영**으로만 쓴다
4. **대행사와 칸을 나눠야 한다.** 3,880칸이 이미 대행사 것이고 매주 늘어난다. 귀속 구분은 이미 가능(`console_excluded_at`·주체 구분·`source='console_import'`) — 안 나누면 자르려는 순간 칸이 없거나 서로 지운다

**순서 5단계** (1~3은 쓰기 0·승인 불요, 4부터 `optimizer` 해제 필요)
1. 그룹별 칸 사용률 실측 → 2. 쇼핑 후보 생성 복원(**버그 수리**) → 3. n-gram 집계로 **구문 후보** 산출(어느 구문 1칸이 몇 검색어·얼마 비용을 덮는지) → 4. **Jino 확인 경로로 몇 건 집행**(판정기가 옳은지는 집행 결과로만 확인된다) → 5. 유입률 관측 후 반납 규칙 가동(지금은 「언제 찬다」의 **분모가 없다**)
