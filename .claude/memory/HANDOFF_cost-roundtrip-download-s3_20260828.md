### 4-2. ★「같은 행·열」을 무엇이 지키는가 (S4가 이 위에 선다)

파일은 백엔드가 만들고 표는 프론트가 그린다 ⇒ 열 스펙이 두 벌이 된다. 이 저장소의 상습 결함이다(직렬화기 두 벌 `standard_cost.py`↔`recipes.py:standard_payload`는 **지금도 부채**).

| 축 | 어떻게 지키나 |
|---|---|
| **열** | `backend/app/services/cost_menu/round_trip_columns.json`이 정본이고 백엔드가 **런타임에 읽는다**. 픽스처가 아니라 생성기의 입력이라 낡으면 파일이 낡게 나온다. 프론트는 그 JSON을 **사본 없이 import**해 대조(`frontend/src/lib/costHomeColumnParity.test.ts`) |
| **값** | `materials.list_materials(db)` 산출 그대로. 재조회하면 `choose_price`·`resolve_inc_vat`의 두 번째 사본이 생긴다 |
| **파일** | 스냅샷에서만 만든다. 파일과 스냅샷이 각자 DB를 읽으면 그 사이 변경이 끼어들어 **무수정 재업로드가 「변경 N건」으로 서는 유령 diff**가 난다 |

★`tsconfig.app.json`에 `resolveJsonModule: true`를 켰다 — 파리티 테스트가 백엔드 JSON을 사본 없이 들여오기 위해서다. `node:fs`를 쓰려면 `types`에 `node`를 얹어야 하는데 그건 앱 코드 전체에 Node API 타입을 여는 훨씬 넓은 변경이다.

### 4-3. ★★★최대 함정 — 필터 (Fable 구조 검증이 찾았다)

### 4-4. 실측이 설계 문서를 정정했다

설계 `docs/PLAN_cost_menu_s2_screen.md` Q3는 출처 라벨을 「원장 / **수동**」이라 적었지만 **라이브 화면은 「원장 / 등록가」**다(`CostPage.tsx:127 priceSourceLabel` · D-CPP-56, Jino 2026-08-24 *"지금 등록이 되어 있는 엑셀값을 공식 가격으로 쓰자"*).

계약 §2가 *"왕복 파일의 모양은 항상 **화면의 표를 따른다**"*이므로 **화면이 정본**이다. 파리티 테스트가 **TS 함수를 실제로 호출해** 스펙과 대조한다. ⇒ **설계 문서가 라이브보다 낡을 수 있다. 인용 전에 코드를 봐라.**

### 4-5. 설계 Q3와 다르게 간 것 1건 (선언)

12번째 열의 **파일 셀은 비고만** 싣는다. 화면의 그 칸은 「상태 + 라이브 배지 + 비고」의 **합성**이라 왕복이 원리적으로 불가능하다 — 배지까지 쓰면 S4가 파생값 변화를 «사람의 수정»으로 오독하고, 「승인 · 비고」로 합치면 그 문자열을 다시 파싱해야 한다(깨지기 쉽다).

잃어버린 「상태」는 **파일 헤더가 자백한다**: `비고 (상태는 화면에서만)`. 상태는 어차피 파일에서 못 고치고 승인은 사람이 화면에서 누른다(계약 §2). 스펙의 `file_label` 필드가 「화면과 다르다」는 사실 자체를 말하고, 파리티 테스트가 **`file_label`을 가진 열이 이 하나뿐임**을 단언한다 — 조용히 늘어나면 「화면과 같은 열」이라는 말이 하나씩 거짓이 된다.

### 4-6. 스냅샷 설계 (S4가 여기 붙는다)

`cost_roundtrip_snapshot` **1개 테이블 + JSON blob**. 행 테이블을 안 만든 이유 둘: ①열 스펙이 진화하면 정규화 스키마가 따라 바뀌고 **구 스냅샷이 마이그레이션 부채**가 된다(blob은 `column_spec`을 품어 **자기서술적** — 구 파일 업로드 시 라벨→키 매핑의 정본이 그 파일의 스냅샷이다) ②정규화된 스냅샷 행 테이블은 생김새가 **단가 이력의 두 번째 사본**이라 반드시 갈라진다.

- `content_hash` 같으면 **같은 스냅샷 재발급** — 다운로드가 사실상 멱등, 같은 상태를 두 번 받아도 S4에서 가짜 충돌이 없다
- `created_at`은 **앱에서 KST 명시**. `func.now()`는 이 저장소에서 UTC이고, 파일에 9시간 어긋난 시각이 찍히면 사람이 「어느 게 최신인가」를 그 자리에서 다시 묻는다 — 그 질문을 없애는 것이 이 계약이다
- 스냅샷 ID는 `_meta` 시트(설계 Q3 확정). 파일명은 **편의 사본**이다(다른 이름으로 저장하면 사라진다)

### 4-7. ★★다른 세션이 내 배포 1분 뒤에 배포했다 — 안 깨졌다

`fix/stale-wording`(커밋 `87c889f2`)이 **06:02~06:03 UTC(15:02~15:03 KST)**에 배포하며 블루-그린을 **8001 → 8011로 되돌렸다.** 그 세션은 `mrg1po9rt3a_merge_po_change_and_roundtrip` — 이름 그대로 **내 `rtsnap1s3a`와 자기 마이그를 합치는 병합 리비전**을 만들었고 `models.py`도 함께 올렸다.

**클로버 없음을 라이브로 확인**: 실서비스 포트 8011에서 `POST /roundtrip/download` → 200 · `CRT-1` · 139행 · 12,510 bytes · 스냅샷 행 수 1 유지.

⚠️**교훈: 배포 직후의 「활성 포트」를 기억해 두지 마라.** 내 배포 로그는 「활성 :8001」이라 했는데 몇 분 뒤 8001은 죽어 있었다. **`pm2 jlist`로 그때그때 재라.** (관련: `blue-green-deploy-moves-the-log-file`)

### 4-8. ★★「사람이 눌렀다」는 nginx 로그가 증명한다

완료 QA 1차가 S3를 미달로 낸 이유가 *"스냅샷 테이블엔 검증성 호출인지 실제 클릭인지 구분 불가능한 행 1건만 있다"*였다. **DB로는 못 가른다.** 가르는 것은 접근 로그다:

```
203.239.246.21 - dgfrty [28/Aug/2026:06:52:24 +0000] "POST /api/cost/roundtrip/download" 200 12916
  Referer: https://sellc.ohitech.co.kr/cost    ← 원가 화면에서 눌렀다
  Chrome/151 macOS
```
내 검증 호출은 `127.0.0.1`. pm2 로그에 두 줄이 나란히 있어 구분된다.
⇒ **표면 사건(「Jino가 ~한다」) 합격기준은 접근 로그로 증명하라.** DB 행만으로는 안 된다.

⚠️nginx `12916` vs 파일 `12510` — 차이 406은 **chunked 전송 프레이밍**이다. 같은 스냅샷으로 서버에서 3회 생성하니 `[12510, 12510, 12510]`으로 **결정적**이었다. 내용 차이가 아니다.
