## §0 가장 먼저 알아야 할 것

1. **대시보드 산술 자체는 틀린 적이 없다.** 매출−원가−수수료−배송비−광고비 계산은 매번
   원 단위로 맞았다. 틀린 것은 **입력**이었다 — 안 물어본 API, 잘못 매핑한 상태, 복사된 필드.
2. **수수료는 주문 API = 정산 실측, 오차 0원**(delivered 617건 476,380 = 476,380). 이 축은 믿어도 된다.
3. **정산 성숙 = D+12.** 최근 1주일은 커버리지 0~46%라 정산 대조가 **원리적으로 불가능**하다.
   대조창은 항상 `오늘−14일` 이전.
4. 살아있는 사실은 메모리 토픽 2개에 있다:
   `naver-settlement-maturity-and-cost-model.md` / `naver-commerce-api-settlement-surface.md`

## §2 N배송 배송비 구조 (Jino 확인 + API 실증)

`deliveryFeeAmount`는 N배송 전 건 **3,000원 고정**이고, `deliveryDiscountAmount`가 갈린다:

| 할인 | 건수 | 비중 | 누가 내나 | 우리 수입 |
|---:|---:|---:|---|---:|
| 3,000 | 270 | 61.6% | 네이버가 멤버십 회원에게 면제 → **네이버가 우리에게 지급** | 3,000 |
| 0 | 165 | 37.7% | 고객이 우리에게 지급 | 3,000 |

**어느 쪽이든 3,000원**이라 코드는 할인 필드를 볼 필요가 없다. 정산 `DELIVERY` 행 3,000원
109건으로 실증. 우리가 품고(PG)에 내는 단가는 **3,020원**(Jino 확인).

```
N배송   +3,000(수취) −81(수수료 2.724% 절사) −3,020(품고) = −101원/건
일반         0(무료배송)  0                  −1,900(한진) = −1,900원/건
                                      → N배송이 건당 1,799원 유리
```

★배송비 수수료 원 단위는 **절사(ROUND_DOWN)**. 라이브 1,652건 전수 대조에서 절사 99.5% vs
반올림 92.1%이고, **N배송의 유일한 금액 3,000원은 절사(81)만 맞다**(반올림이면 매 건 +1원 과대).
