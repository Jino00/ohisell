## §2 D-NAO-122 구현 내용 (요약)

- 문제: `naver_keyword_hourly`는 전날치만 09:10에 일괄 적재. `naver_hourly_snapshot`은 캠페인 grain인데 대상 캠페인 하나에 애드그룹이 60개 섞여 개별 제품 대용치가 못 됨. 07-29 오전 입찰을 올리고도 효과를 당일에 볼 방법이 없었다 — 순위 서보·이탈 경보 등 관측 루프 전부가 이 구멍 위에 있었다.
- 해결: 신규 테이블 `naver_adgroup_hourly_today` + 매시 :57 크론 `sweep_naver_today_hourly`. 수집 함수(`fetch_entity_hh24`, `GET /stats?breakdown=hh24&datePreset=today`)와 타깃 grain 규약은 기존 것 재사용 — 없던 것은 당일 타깃 도출·매시 실행·전용 저장뿐.
- ★전용 테이블인 이유(codex 리뷰 P1): 당일 진행분을 `naver_keyword_hourly`에 섞으면 그 테이블의 완결 불변식("행이 있다 = 그 날이 통째로 스윕됐다")이 깨진다. 자정을 넘기면 당일 행이 "어제 행"이 되어 `auto_operator._exploration_yesterday_flow` ①의 판정을 통과하는데 23시는 구조적으로 못 담아(`hour < now.hour`) 롤링 24h clk가 과소계상 → 잠겨야 할 확장·입찰상향이 열린다. 변경 전엔 어제 행이 0건이라 fail-toward-hold로 안전했으므로 섞는 것은 순수 퇴행. 완결을 hour=23 존재로 판정할 수도 없다(hh24는 실적 있는 시간대만 반환).
- 타깃 = 어제 `naver_ad_daily` adgroup grain imp>0 ∪ 살아있는 출시창 소재의 그룹. **키워드 grain 제외**(Jino 확정 2026-07-29 — 매시 실행 시 콜 폭증, 쇼핑은 그룹이 실효 레버). 실행기와 독립 도출(실행기가 손댄 것만 저장하면 관측 집합이 실행 선택에 종속돼 선택 편향).
- 진행 중인 시간 버킷은 저장 안 함. 상한 초과 시 자르지 않고 시각으로 회전(그냥 자르면 뒤쪽 그룹이 영원히 미조회). 킬스위치 `TODAY_HOURLY_SWEEP_ENABLED`, 콜 상한 800/실행, 14일 롤링.
- 라이브 실측: 네이버 당일 hh24에 **1.4시간 이상 반영 지연**(07-29 12:24에 11시 버킷 미도착) — 지연분은 다음 실행의 교체 upsert가 보완.

## §3 D-NAO-123 구현 내용 (요약)

- ★사다리 position 오프바이원: `_ladder_bid`가 `position == rank - 1`로 조회하고 docstring에 "0-베이스"라 적혀 있었으나 실제 규약은 `position 1~4 = 순위별 필요 입찰가 / 0 = 최소노출입찰가`(models.NaverBidEstimateDaily). 목표 4위가 3위 가격을 강제하고, 1위 목표는 최소노출입찰가를 읽어 순위를 잃는 상태였다.
- **라이브 실측 확인**: 어제 기록된 하한 와이드 1,390 / 울트라 1,390 / 플립8 2,640이 셋 다 정확히 position 3 행 값이었다. 정정 후 1,360 / 1,360 / 2,640(−30원·−2.2% / 0원) — 금액 영향 자체는 작다.

  | 소재 | position 3 (구, 오독) | position 4 (신, 정확) | 변화 |
  |---|---|---|---|
  | 폴드8와이드 | 1,390원 | 1,360원 | −30원 (−2.2%) |
  | 폴드8울트라 | 1,390원 | 1,360원 | −30원 (−2.2%) |
  | 플립8 | 2,640원 | 2,640원 | 0원 (우연히 동일) |

  ⚠️전체 사다리(position 0~4)의 raw 값은 이 세션 인계 자료에 남아있지 않아 표에 담지 않았다 — 필요하면 `naver_bid_estimate_daily`(date=07-28, ad_id=해당 3건)를 직접 조회.
- ★`is_floor` 행 미제외: 시세 무의미 표식을 하한으로 쓰면 신제품 사다리에서 하한이 50원으로 무너질 수 있었다. `bep_breakdown.py:91`이 같은 이유로 이미 제외하고 있었다.
- ★그룹 입찰 경로 우회: `useGroupBidAmt=true` 소재의 실효 레버는 그룹 입찰인데 하한이 `target_type='ad'` 분기에만 있어 그 경로로 하한 밑으로 밀릴 수 있었다. `group_floor_for()` 신설 — 그룹 입찰을 쓰는 출시창 소재들의 **최대** 하한. `use_group_bid_amt`가 NULL(미수집)이면 포함(오탐 대가="인하 한 번 못함" < 누락 대가="1페이지 이탈"). 현재 3개 소재는 전부 `use_group_bid_amt=0`이라 예방적 수정.
- ★교훈: 기존 테스트 헬퍼 `_ladder_row`가 코드와 **똑같이** `position=rank-1`로 저장해 버그를 가리고 있었다. 테스트가 구현의 가정을 복제하면 통과는 무의미하다.
- 출처: codex review 2R (2026-07-29). **PR #164의 codex 리뷰 부채는 이것으로 회수됨.**

## §4 D-NAO-124 — 순위 서보 설계 (미구현)

- Jino 원문: *"4위를 기준으로 운영을 하자는거지, 꼭 4등에 고정하자는것은 아니야. 4등이어야지 최소한 1페이지에 노출이 되니까 말이야. 4등을 기준으로 해서 우리가 생각했던 이익보다 더 많은 이익이 나오면 순위를 올리고 적게 나오면 낮추되, 최대한 4등에 가장 큰 가산점을 두는거지"*
- 구조: 결정 변수 = 목표 순위 r(고정 아님) / 목적 = 총이익(전환매출×공헌이익률 − 광고비) / 사전분포 = r=4에 가장 큰 가산점(1페이지 노출 보장 최소 자리) / 입찰 = 종속 변수.
- **하향 바닥: 없음 — 가산점만 두고 아래도 허용(Jino 확정 2026-07-29).** D-NAO-120의 "출시 21일 하한 4위"라는 경성 하한이 **가중 선호**로 개정된다.
- ★새 목적함수가 아니라 D-NAO-59(총이익 최대화)를 순위 축에서 실행하는 것이다.
- ★사다리를 서보 입력으로 쓸 수 없다(07-29 실측): 최소노출입찰가 2,040 > 1위 1,600, 플립8은 1위 2,570 < 2위 2,680, 3위=4위=2,640. 게다가 플립8은 실제 1,900원에서 2.35~3.04위 — 사다리가 "4위=2,640"이라는데 700원 싸게 3위 안에 있다. 자기 관측(입찰 → 실제 avg_rank → 이익)으로 곡선을 만들어야 하며, 그 원료가 D-NAO-122다.
- 선행 조건: ①관측 개통(D-NAO-122, 완료) ②순위→가격 사상 정확화(D-NAO-123, 완료) ③순위별 이익 곡선 적립(며칠) ④서보 가동.
