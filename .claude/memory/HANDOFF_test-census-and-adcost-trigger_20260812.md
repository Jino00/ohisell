## 2. D-CPP-44 — 테스트 인구조사 가드

### 무엇이 문제였나
vitest가 **5개 파일을 실행조차 못 한 채** `Test Files 19 passed (19)`를 찍고 있었다.
실행 못 한 파일은 **분모에서도 빠지므로** 화면 어디에도 5라는 숫자가 없다 — 완전한 초록이다.

### 근본 원인 — css-tree/jsdom 버그가 아니라 iCloud Drive
`node_modules` 파일이 dataless(`st_size > 0 && st_blocks == 0`)가 되면
**Node의 CJS 로더가 에러 없이 «빈 문자열»로 읽는다** → 모듈이 조용히 `{}` →
`matchGraph.buildMatchGraph is not a function` / `generatedInterface.install is not a function` /
`Linter is not a constructor`가 **원인에서 몇 겹 떨어진 곳**에서 터진다.

실측 19,825개 중 **2,046개**. 대조 실험: 같은 `jsdom@29.1.1`을 iCloud 밖에 새로 깔면 정상이고
**파일 md5는 동일**하다 — 내용이 아니라 «내려와 있는가»의 문제다.

★진단 중에 증상이 옮겨 다닌다 — **읽으면 내려받아지므로** 한 번 확인한 파일은 그 다음부터 정상이다.

### 만든 것 (`frontend/`)
| 파일 | 역할 |
|---|---|
| `scripts/test-census.mjs` | 순수 판정기. `censusVerdict` · **`exitCodeFor`** · `isDataless` · `healIsComplete` |

## 3. ★★적대 리뷰가 잡은 것 — 가드가 «조용히 가드를 그만두는» 회귀

리뷰어가 변이 M8을 넣었다: `run-tests.mjs`의 `if (ok)` → `if (true)`.
**아무 테스트도 안 죽었다.** 이어서 내가 M9를 찾았다: vitest 실패 전파 줄 삭제 →
«전부 돌았는데 테스트 실패»가 통째로 초록. 역시 안 죽었다.

뿌리는 같다 — 판정 «로직»은 순수 모듈에 있어 덮이는데, 그 판정을 **exit 코드로 바꾸는 분기**가
껍데기에 흩어져 통째로 사각지대였다.

**리뷰어는 P2로 냈다. 등급에 동의하지 않고 P1으로 올려 채택했다.**
「미래 회귀 보험은 계약 밖」이라는 논거는 일반적으론 옳지만, 그 «미래 회귀»가 이 변경의
존재 이유 자체일 땐 안 통한다.

**고친 방법이 핵심**: 테스트를 더 쓰는 대신 **사각지대를 없앴다.** 판정 분기를 순수 함수
`exitCodeFor` 하나로 모으고, 껍데기엔 `process.exit(exitCodeFor(...))` **한 줄만** 남겼다.
(인구조사 «이전» 조기 중단 `die()`는 의도된 예외 — 2R에서 확인됨.)

2R **RESOLVED** — 변이 5/5 KILLED · `process.exit` 판정 후 경로에 정확히 1개 · 재귀 없음 · 연속 2회 동일.
