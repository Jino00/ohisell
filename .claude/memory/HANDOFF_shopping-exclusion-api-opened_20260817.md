## 2. ★★새 세션이 할 일 (Jino 확인: 「위의 내용을 다음 세션에서 이어서 진행하자」)

### 순서가 중요하다 — ①을 건너뛰면 3,880건을 날릴 수 있다

```
①기존 보존 확인  →  ②읽기 배선(위험 없음·이득 큼)  →  ③쓰기 배선(별도 승인)
```

### ① 첫 일 — 「기존 것이 살아남는가」 확인 (필수·선행)

오늘 증명한 것은 **「빈 목록 그룹에 1건 추가」**뿐이다. 실제 대상은 **이미 제외가 든 116그룹(3,880건)**이고, `PUT`은 보통 **교체(replace)** 의미론이라 44건짜리에 1건만 보내면 **기존 43건이 사라진다.** 그 3,880건은 대행사가 2024년부터 쌓은 것이고 **우리 원장엔 43건(버디필름 1그룹분)만 있다 — 백업이 없다.**
★오늘 프로브는 빈 서랍에 넣었기 때문에 「교체」와 「추가」를 **원리적으로 구분할 수 없었다.**

절차:
1. 제외가 **가장 적은 그룹**(2~3건)을 고른다. 3,880건짜리로 시험하지 않는다.
2. 그 그룹 목록 **전문을 파일로 저장**(유일한 안전망).
3. **기존 목록 + 더미 1건**을 통째로 PUT.
4. 재조회 — 기존이 살아 있고 더미만 늘었나? 사라졌으면 **저장 파일로 즉시 복구**.
5. 더미 제거 후 원복.

### ② 읽기 배선 — 위험 없이 얻는 게 크다

`GET /ncc/targets?ownerId=…` → `RESTRICT_KEYWORD_TARGET`을 원장에 편입.
이것만 해도 **S5 캡처 소멸 + 생존감시 정상화 + 원장 43건 → 3,900건대**가 된다. 네이버에 쓰지 않으므로 승인 문제도 없다.

### ③ 쓰기 배선 — 별개 결정이다

PAO는 완전 정지(`optimizer='none'`) 상태이고, 쓰기를 여는 것은 「자동으로 검색어를 자른다」는 뜻이라 **Jino 승인이 따로 필요**하다.

### 재검토 대상 4곳 (②③에서 손대는 곳)

| 곳 | 지금 | 바뀔 것 |
|---|---|---|
| **S5 콘솔 캡처** | 그룹당 화면 3장 캡처(8/13 버디필름 43건 완료, 다음 `Z폴드8와이드` 17건 대기) | **존재 이유 소멸** — 116그룹이 남아 있었다 |
| `detect_new_exclusions` | `adgroup_type != "WEB_SITE"`면 스킵 — **오늘 실측 195그룹** | 쇼핑도 자동 발견 |
| `exclusion_survival` | 쇼핑 43건이 `STATE_UNVERIFIABLE`(볼 수 없음) | 실제 라이브 대조 |

★**편입분은 학습 사슬에 넣지 않는다**(오늘 아침 합격기준 ③이 지킨 것): 파워링크 105건도 쇼핑 3,880건도 「우리가 한 조치」가 아니라 「남이 이미 해 둔 것」이다. `source='console_import'`로 넣고 일기는 0건이어야 한다. 남의 조치를 우리 승률로 세지 않기 위해서다.
