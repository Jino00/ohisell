★**보존 방식 교체 — 처음 고친 것에 결함이 있었다(07:35 라이브 실측으로 발견).**
`b894807`이 쓴 `-mtime +7`은 이 크론이 **매일 같은 시각(18:30:0x UTC)** 에 도는 탓에
삭제 대상 파일의 나이가 실행 순간 **정확히 8.000일 경계에 얹힌다**. `-mtime`은 소수부를
버리므로 판정이 갈린다 — 실측: 08-03 18:31 크론 실행에서 **8일 1분 된 07-26 파일이
안 지워졌다**(4시간 뒤 dry-run에선 매칭). "보존 7일"이라 적어놓고 8개가 남는 조용한 어긋남.
→ **개수 기반**으로 교체: 경계가 없고, 하루에 여러 번 돌아도 상한이 보장된다. 이 스크립트의
목적이 '디스크를 묶는 것'이므로 개수가 목적에 직접 대응한다. 정리를 백업 **전**에 하므로
`KEEP-1`로 줄인 뒤 하나를 더해 정확히 `KEEP`개가 된다.
**라이브 합격: 9개 → 정리 3개 → 백업 1개 → 정확히 `보관 7/7개`.** 수동 스냅샷

★서버 실측으로 발견해 고친 것: `df -P --output=avail`는 GNU df에서 **상호배타**(에러) → `-B1`로 교체.
그대로 뒀으면 사전 공간확인이 통째로 깨졌다.

★디스크 감시를 넣은 이유: 기존 세 감시선(잡·쿠키·데이터 나이)은 **전부 사후 지표**다 —
