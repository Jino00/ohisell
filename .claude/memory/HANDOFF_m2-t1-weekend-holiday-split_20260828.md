## ★항등식 검산 — readonly SQL 1줄 (계약 §4-C S2-① 요구)

「평시+주말+공휴일 = 전체」를 prod에서 직접 재는 명령이다. **읽기 전용**이다.

```bash
ssh sellc.ohitech.co.kr "cd /home/ubuntu/ohisell/backend && sqlite3 ohisell.db \"SELECT CASE WHEN strftime('%w',ad_date) IN ('0','6') THEN 'weekend' ELSE 'weekday_or_holiday' END AS day_class, COUNT(DISTINCT ad_date) AS days, SUM(cost) AS cost, SUM(conv_direct_amt+conv_indirect_amt) AS conv FROM naver_ad_daily WHERE ad_date BETWEEN date('now','-21 day') AND date('now','-1 day') AND adgroup_id <> '__backfill__' GROUP BY 1 UNION ALL SELECT 'TOTAL', COUNT(DISTINCT ad_date), SUM(cost), SUM(conv_direct_amt+conv_indirect_amt) FROM naver_ad_daily WHERE ad_date BETWEEN date('now','-21 day') AND date('now','-1 day') AND adgroup_id <> '__backfill__';\""
```

**합격 조건**: 칸들의 `cost` 합 == `TOTAL` 행의 `cost` (다른 열도 같다).

⚠️ **이 SQL은 2분할이다** — SQLite엔 한국 공휴일 달력이 없어 `strftime('%w')`로는 토·일만 가른다. 앱은 `holidays.SouthKorea()`로 **3분할**(평시/주말/공휴일)한다. 3분할 항등식은 API 응답이 스스로 검산해 싣는다:

```bash
ssh sellc.ohitech.co.kr "curl -s 'http://127.0.0.1:8011/api/naver/ad/scope/roster?days=21'" | python3 -c "import sys,json; w=json.load(sys.stdin)['weekend_holiday']; print(w['identity'])"
```

**2026-08-28 14:3x 실측**: `identity.ok = True` · `total == sum_of_parts == 집계기 totals` (cost **12,845,989** 전건 일치).

## 4. ★다음 세션이 알아야 할 것

1. **X9 라벨은 ref 63보다 «적게» 붙는다.** ref 63의 평시는 휴가창·출시창·mature도 배제하는데 그 축들은 미확정이라 §3이 막는다 ⇒ ref 63이 X9를 **발견한 사례(TPU3, 휴가창이 평시를 통째로 먹은 경우)를 재현하지 못한다**. 코드 docstring이 이 대가를 자백한다. 라이브 사례 **0건**(404그룹 전건 `ok`)은 그 귀결이다.
2. **사유 우선순위 `bep_unknown` > `ramp_up`은 계약에 근거가 없는 이번 세션의 판단이다**(적대 리뷰 P2-1이 그 사실을 지적했고 채택했다). 「애초에 못 잰다」가 「재도 의미 없다」보다 먼저 풀 막힘이라서다. 재론하려면 근거를 새로 대야 한다.
3. **retro 분리를 「주말 성과」로 읽지 마라.** 응답의 `measures` 필드가 *"그 날 내린 «판단»의 정확도. 그 날의 «성과»가 아니다"*라고 스스로 말한다. d7은 분리가 **원리적으로 0**이고(7일 연속은 어느 발신일이든 주말 2일 포함) d3은 부분적으로 **뒤집혀** 있다(일요일 발신 0/3 vs 목·금 2/3).
4. **`_baseline_days_by_adgroup`의 prod 응답시간 미실측**(리뷰 P2-2 이월). `build_roster`는 BEP 사다리로 10.1초가 난 전례가 있는 핫패스다.
5. ★★**이 HANDOFF 최상단의 SQL은 항진명제다 — 먼저 고쳐라.** 재판정이 잡았다(위 §1). 2분할(`strftime('%w')`)이라 **공휴일 오분류를 원리적으로 못 잡고**, 3분할 검증이 앱 자기보고(curl)에만 걸려 있다. **고치는 법**: 창 안의 한국 공휴일 날짜를 **SQL에 리터럴로 열거**해 3분할하고 앱의 세 칸과 대조하라 — 리터럴 날짜는 사람이 달력으로 검증할 수 있으므로 앱과 독립이다. 그러면 앱이 공휴일을 잘못 분류할 때 숫자가 갈라진다(지금은 조용히 흡수된다). ⚠️**이 항목은 판정 «이후»에 적은 것이라 아직 판정을 안 받았다** — 다음 세션이 고치고 그때 판정받을 것.
6. **`NaverAdScope.tsx` 캠페인 합계 `ProfitCell`이 `status="ok"` 하드코딩**(리뷰 P2-3 이월, 이 diff 밖). 캠페인 전체가 값 없는 그룹만이면 화면이 「모름」에 `title="ok"`를 보인다.
