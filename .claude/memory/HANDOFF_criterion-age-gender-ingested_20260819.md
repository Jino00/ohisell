**#325 — 변이 주입은 «커밋된 상태»에서만 안전하다.**
변이를 되돌리는 수단이 `git checkout --`이므로, 미커밋 수정 위에서 변이를 돌리면 그 수정이 통째로 날아간다. 2026-08-19 D-NAO-203에서 1차 주입(커밋 후)은 안전했고 2차 주입(미커밋)은 P1-2 수정을 지웠다. **집행 지점**: 변이 스크립트 첫 줄에서 `git diff --quiet -- <대상파일>`을 확인하고, 더러우면 거부한다.

**#326 — 크론 슬롯 결함은 «배포 전»에만 무료로 고칠 수 있다.**
`_ensure_default_states`는 기존 `scheduler_state` 행의 cron을 **절대 조정하지 않는다**(예외는 `_CRON_OWNED_BY_CODE` 명단뿐, 그건 이미 잘못 seed된 것을 고치는 용도). 한 번 seed되면 **정본이 prod DB로 넘어가** 코드 수정이 안 먹는다. 교훈 #297의 세 번째 사례가 될 뻔했다. **집행 지점**: 새 크론을 등록하는 PR의 적대 리뷰 체크리스트에 「분 슬롯 전수 grep(매시 발화·`*/N` 포함)」 한 줄.

**#327 — 하루치 관측을 축의 정체로 승격하지 마라.**
교훈 #316의 세 번째 재현이고 이번엔 **관측자 쪽에서** 났다. AD 「1종뿐」(실제 13종) · SD 「4,008원·사실상 탈락 재확인」(실제 21,653,088원 = 계정의 10.6%)이 둘 다 2026-08-17 하루치의 일반화였다. **가장 나쁜 것은 틀린 근거로 기존 판정을 「재확인」했다고 적어 옛 판정을 보강한 것**이다. **집행 지점**: 축 분포를 말할 때 창을 병기하고, 창이 하루면 「이 축이 작다」로 승격하지 않는다. 그리고 다축 분해 테이블의 집계 SQL엔 **「합계 == 단일 축 총계」 검산**을 붙인다(축 무통제 group-by는 에러 없이 **정상 형식의 틀린 숫자**를 돌려준다 — 같은 세션에서 `extract.sql`이 실제로 그랬다).

**#328 — 「[미상]」이라 쓰기 전에 그 답이 이미 적재돼 있지 않은가부터 물어라.**
「추정 등재 0건」 규율을 지키려고 코드 사전 2,202행을 적재해 놓고, **그 사전을 조회하지 않은 채** AD 12종을 [미상]으로 뒀다(완료 QA가 잡음). 규율을 지키려고 만든 자산을 쓰지 않은 것이다. **집행 지점**: [미상] 태그를 다는 순간 「이 프로젝트에 이 질문의 답을 담은 표가 있나」를 grep한다.
