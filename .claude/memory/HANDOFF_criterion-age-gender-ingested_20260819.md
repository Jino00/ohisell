### 「매시간·매분」의 정직한 번역 — 3속도 루프 (ref 82 §5)
- ⓐ운영 일기·지혜(D-NAO-54, **광고 운영 행위와 결과**)와 ⓑ개발 지혜층(`docs/wiki`, 하네스 교훈)은 **다른 기제다** — 섞지 않는다. Jino가 원하는 「자가개선」의 몸통은 **ⓐ**.
- **매분짜리 총이익 신호는 존재하지 않는다** — 키워드·그룹 성과(전환 포함)는 **D-1**(네이버 API 공통 제약) · 전환 확정은 D+1~7(성숙 컷 D-8) · 캠페인 당일 누적은 ≤1시간.
- ⇒ **3속도 루프**: `[매시간] 시도(시간당 레인) → [D-1~D+7] 채점(outcome 백필→소급채점→GAVE) → [14일/3회] 승격(독립 판사→«제안»으로 반영)`.
- ⓐ에 더 필요한 부품 3(새 시스템이 아니라 조인·배선): ①**지혜 성적표**(승격 지혜 id로 GAVE·retro 점수를 롤업하는 조인 하나) ②**A/B 확정 지식만 판정면 주입**(C 미검증 가설 주입 금지) ③**탐침 예산**(매시간 시도에 필요, L3 재개 폭에 종속).
- ★금지선 유지: 지혜의 출구는 «제안»까지(자동 적용 절대 금지) — 「매시간 개선」은 파라미터를 스스로 바꾸는 게 아니라 **매시간 시도하고 배운 것을 승인 경로로 반영**하는 것.

### 금지선 핵심 (ref 82 §7)

- **되돌릴 수 없는 액션은 승인 지점을 상속한다**: 신규 캠페인 생성·재구축·예산 상한 인상은 항상 사람 Confirm · 위임 스위치는 Jino만 · `optimizer='ours'` 아닌 캠페인 쓰기 절대 금지. 지혜의 출구는 제안까지.

- 「전수 조사 완료」·「연관 규명 완료」라고 쓰지 않는다.

**#325 — 변이 주입은 «커밋된 상태»에서만 안전하다.**
변이를 되돌리는 수단이 `git checkout --`이므로, 미커밋 수정 위에서 변이를 돌리면 그 수정이 통째로 날아간다. 2026-08-19 D-NAO-203에서 1차 주입(커밋 후)은 안전했고 2차 주입(미커밋)은 P1-2 수정을 지웠다. **집행 지점**: 변이 스크립트 첫 줄에서 `git diff --quiet -- <대상파일>`을 확인하고, 더러우면 거부한다.

**#326 — 크론 슬롯 결함은 «배포 전»에만 무료로 고칠 수 있다.**
`_ensure_default_states`는 기존 `scheduler_state` 행의 cron을 **절대 조정하지 않는다**(예외는 `_CRON_OWNED_BY_CODE` 명단뿐, 그건 이미 잘못 seed된 것을 고치는 용도). 한 번 seed되면 **정본이 prod DB로 넘어가** 코드 수정이 안 먹는다. 교훈 #297의 세 번째 사례가 될 뻔했다. **집행 지점**: 새 크론을 등록하는 PR의 적대 리뷰 체크리스트에 「분 슬롯 전수 grep(매시 발화·`*/N` 포함)」 한 줄.

**#327 — 하루치 관측을 축의 정체로 승격하지 마라.**
교훈 #316의 세 번째 재현이고 이번엔 **관측자 쪽에서** 났다. AD 「1종뿐」(실제 13종) · SD 「4,008원·사실상 탈락 재확인」(실제 21,653,088원 = 계정의 10.6%)이 둘 다 2026-08-17 하루치의 일반화였다. **가장 나쁜 것은 틀린 근거로 기존 판정을 「재확인」했다고 적어 옛 판정을 보강한 것**이다. **집행 지점**: 축 분포를 말할 때 창을 병기하고, 창이 하루면 「이 축이 작다」로 승격하지 않는다. 그리고 다축 분해 테이블의 집계 SQL엔 **「합계 == 단일 축 총계」 검산**을 붙인다(축 무통제 group-by는 에러 없이 **정상 형식의 틀린 숫자**를 돌려준다 — 같은 세션에서 `extract.sql`이 실제로 그랬다).

**#328 — 「[미상]」이라 쓰기 전에 그 답이 이미 적재돼 있지 않은가부터 물어라.**
「추정 등재 0건」 규율을 지키려고 코드 사전 2,202행을 적재해 놓고, **그 사전을 조회하지 않은 채** AD 12종을 [미상]으로 뒀다(완료 QA가 잡음). 규율을 지키려고 만든 자산을 쓰지 않은 것이다. **집행 지점**: [미상] 태그를 다는 순간 「이 프로젝트에 이 질문의 답을 담은 표가 있나」를 grep한다.

**#329 — 「완성도」를 말할 땐 «자»를 먼저 밝혀라(적재 완료도 ≠ 연관 확인도).**
D-NAO-206의 본체다. 이 트랙은 「교차완료 19/36」으로 완성도를 보고해 왔는데 그건 **「등급별 «값»이 존재한다」**이지 목표인 **「등급과 «연관»이 있다」**가 아니었다. 같은 36축을 연관 확인도로 다시 세니 **A+B = 4/36 (11%)**이다. **격차의 원인은 게으름이 아니라 홀드아웃이 발견을 실제로 죽이기 때문**이고(ref 64 순위 8/8 미재현·ref 78 A5 유형 교락·ref 79 5건 강등) 그 규율이 옳다 — **틀린 것은 낮은 숫자가 아니라 높은 숫자를 완성도로 보고한 것**이다. **집행 지점**: 「몇 % 됐나」에 답할 때 **①어느 층의 분모**(ref 73 §0-A) + **②어느 자**(ref 73 §0-C)를 **둘 다** 병기하고, 하나라도 빠지면 그 숫자를 쓰지 않는다.
