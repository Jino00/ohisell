# HANDOFF — 쿠팡 RG 정산 층2 수집이 주기 전환마다 죽던 결함 — 업스트림 500을 로그아웃으로 오분류 (2026-08-03, 워크트리 `youthful-albattani-54e1e0`, 브랜치 `claude/rg-probe-delta`)

## §0 가장 먼저 알아야 할 것

**PR #178, 라이브 합격.** 세션 문제가 아니었다 — `wing.coupang.com`의 `status/api`가 상시 HTTP 500을
뱉는 업스트림 장애였고, 그 500의 본문은 로그인 페이지가 아니라 **로그인된 Wing 셸 HTML**
(`<title>Coupang Wing - 김진오, 오픽스</title>`, `__GLOBAL_DATA__ activeProfile:'production'`,
`server: istio-envoy`)이었다. 판정 함수가 그 둘을 똑같이 "로그아웃"으로 접었고, lease 계약상
`login_required`는 재시도 없이 요청을 소멸시켜 **버튼 1회 = 주기 1개**가 됐다 — RG 166시간 침묵의
실제 기전.

## §1 근본 원인

`_rg_json`이 "status != 200"과 "본문에 `<html`"을 똑같이 `None`으로 접었고, 호출자는 그 `None`을
"로그아웃"으로 번역했다. 실제로는 로그인된 세션이 멀쩡히 살아있는데 `status/api` 자체가 상시
장애였다. lease 계약(재시도 없이 요청 소멸)이 이 오분류를 치명적으로 만들었다 — 매 버튼 클릭이
`login_required`로 즉시 소멸하니 층2 결손이 절대 안 메워졌다.

## §3 "주기 전환에서만 죽는다"로 보였던 이유

그 지점이 특별해서가 아니라 재시도 예산 차이였다. 진입 프로브 `_rg_login_wait`(5초×180초)도 매
회차 똑같이 실패했지만 22~46초 두들겨 통과시켰다. 주기 전환 프로브는 2회·5초뿐이라 97% 실패율
앞에서 항상 죽었다 — 같은 코드, 다른 재시도 예산.

## §4 수정 (PR #178, 커밋 4건 = 병행 세션 2 + 이 세션 2)

**병행 세션(`fix/rg-session-probe-false-negative`, 로컬 전용)**:
- 3상태 판정(ok/auth/unknown) 도입
- 판정 불가를 로그아웃으로 승격 금지
- AUTH 사유에서 body 제거(토큰 노출 방지)

**이 세션 델타**:
1. 프로브 엔드포인트를 `status/api` → `download-list/api`로 교체
2. `_rg_fetch_status_raw`에 5xx 재시도(120초 예산, 반환을 (판정, raw) 튜플로 변경)
3. 오리진 이탈(xauth)을 로그아웃 확증으로 인정
4. `redirect:'manual'` — JSON API가 302로 로그인 페이지에 튕기면 `follow`는 크로스 오리진에서
   `TypeError: Failed to fetch`로 터져 명백한 로그아웃이 '판정 불가'로 뭉개진다

**판단기준**: 오분류 비용은 비대칭 — 정상→로그아웃 오판은 요청 영구 소멸, 로그아웃→정상 오판은
재시도 가능한 실패. 확증 없으면 AUTH로 부르지 않는다.

**테스트**: 4278 passed. 회귀 16건 추가.
