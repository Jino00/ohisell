## 1. ★★ 답 — 두 지시의 전제가 «둘 다» 실측에 반증됐다

지시를 문서에 옮겨 적기 전에 prod에서 직접 쟀고, **근거가 무너졌다.**

### A-7 — 「36일 정지」는 **산술 오류**다

| 관측 (2026-09-06 10:15:48 KST) | 값 |
|---|---|
| `optimizer_change` 누적 | **18건** (ref 137 §3과 일치) |
| 최신 | **2026-08-29 12:53:11.896466 KST** · `none → ours` |
| 08-29 → 09-06 | **8일** (「36일」이 아니다) |
| 현재 분포 | `none` 8행 · `ours` **2행** |

**「36일」은 `ref 137` 2곳 + n=90 HANDOFF 2곳에 있고 넷 다 같은 한 숫자에서 나왔다. 출처가 없다.**
그리고 마지막 발화는 **«켜는» 방향**이다 — 「정지」의 그림과 부호가 반대다.

★**그럼에도 결론(A에서 내린다)은 유지했다. 근거만 바꿨다** —
A의 나머지 8행은 «시스템이 스스로 도는» 것이라 「오늘 몇 건」을 물을 수 있는데,
`optimizer` 전환은 **사람이 누르는 스위치**라 기회가 없으면 0이 정상이다. **같은 칸에 두면 0이 고장으로 읽힌다.**

### B-11 — 「측정 수단이 없다」는 **반증됐고, 그건 돌았다**

1. **DB로 «하한»이 잰다.** `ignition_preflight.check()`는 켜는 방향 쓰기 2경로에서
   **쓰기보다 먼저·같은 함수 안에서** 돈다(`backend/app/routers/naver_ad.py:1007`·`:1097`).
   두 경로 다 `naver_change_log`에 행을 남기므로 「몇 번 돌았나」의 하한이 원장에서 파생된다.
2. **로그도 측정 수단이다.** pm2 접근 로그(`ohisell-backend-{8001,8011}-out*.log`)가 살아 있었다 —
   **「측정 수단이 없다」가 아니라 「아무도 안 봤다」였다.**
3. ★**재보니 돌았다.** preflight prod 최초 배포 `2026-08-27T21:32:56Z` = **2026-08-28 06:32:56 KST**

   **그 1번에 동반 실행 — 발화율 1/1.**

⇒ **판정 「판정불능」 → 「발화 확인 — 하한 1건 / 상한 3건」.**
상한 3은 배선 이후 창의 `PUT optimizer` 3건이고, 접근 로그가 요청 바디를 안 남겨 내역은 **미상**이다.

## 4. ⚠️ 하네스 함정 — 이 세션이 새로 겪은 것 2건

1. **iCloud 공유 폴더에선 워크트리를 못 만든다**(`fatal: mmap failed` **재현**) + 그 폴더는 `origin/main`보다

   `--depth 1`은 쓰지 않았다 — shallow는 배포 CAS를 거짓 거부한다(`memory: shallow-clone-breaks-deploy-cas`).
2. ★**셸 cwd가 클론과 공유 폴더 사이를 오갔다.** 착지 명령 한 번이 **공유 폴더에서** 돌았고
   `git pull --ff-only`가 **분기 거부로 멈춰** 쓰기 0건으로 끝났다(운이 좋았다 — 공유 폴더는 로컬 1커밋 ahead).
   ⇒ **이후 전 명령에 클론 절대경로를 명시**했다. **공유 폴더엔 아무것도 쓰지 않았다.**
   **다음 세션도 매 명령에 클론 경로를 붙여라** — 「cd 한 번 했으니 유지된다」는 이 하네스에서 성립하지 않는다.
3. ★★**앵커가 «두 곳»에 산다 — 그 결과 완료 QA 판정을 훅이 안 읽는 쪽에 적었다.**

   `~/ohisell-clones/pao-n91/.claude/anchors/<id>.md`(훅이 읽는 정본 · `대조:` 3항목) vs `<iCloud 공유폴더>/.claude/anchors/<id>.md`(내가 잘못 쓴 쪽).

   ★**잡은 방법 = 훅 메시지를 믿지 않고 훅의 계산을 그대로 재현한 것**(`grep -cE '^판정(\([^)]*\))?:'` = 0 · `대조:` 3항목).
