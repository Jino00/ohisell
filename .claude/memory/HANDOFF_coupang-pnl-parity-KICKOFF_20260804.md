## 5. 계약 초안 (§7 승인 후 착수 — 아직 승인 전)

**목표** — 쿠팡 2계정 4채널의 매출·비용·광고비가 쿠팡 정산 원장과 라인 단위로 맞는지 검증하고
어긋난 것을 고친다. 스마트스토어와 **목적은 같고 경로는 채널별로 다르다**.

**단계**(앞 단계 결과가 뒤를 정한다 — 한 번에 못 박는다)
- **P0 진단** — 화면의 쿠팡 숫자가 어느 코드 경로에서 나오는지 채널별 지도. ★첫 질문 =
  "RG·로켓 매출을 같은 엔진에 넣을 것인가, 채널별 평행 엔진을 각각 정합시킬 것인가"(Jino 결정 사항).
- **P1 신선도** — 대조 전에 수집 생존 확인. 쿠팡은 Wing 쿠키·Mac 페처 IP·크론에 의존해 **조용히
  끊긴 이력이 반복**된다(RG 26일 침묵, 쿠팡 광고비 크론). 네이버 때도 "정산 크론이 한 번도 성공한
  적 없었다"가 나왔다.
- **P2 라인 대조** — 성숙창 기준 채널별 전수 대조(매출→수수료→배송비→반품→광고비).
- **P3 수정·배포** — 확정된 것만.

**이번에 안 하는 것** — 로켓 1P 원가 매핑(별도 트랙 `ohitech-ad`, ★Jino 몫 옵션↔마스터 연결 4건
미결) · 쿠팡 광고 최적화 · 네이버 트랙 · 쿠팡을 `profit_calculator`로 통합하는 리팩터(P0 결과 후 판단).

**판단기준** — 항상 원장(정산서)을 정본으로 쓴다 / 항상 라인 단위(총액은 상쇄로 오류를 숨긴다,
네이버 실증) / 성숙창만 / 어긋나면 숫자를 대사에 쓰지 않고 보류.

**합격기준** — 채널별 "우리 숫자 vs 쿠팡 정산" 일치율을 건수·금액으로 제시. 불일치는 건별 원인까지.
최소 합격: **오픽스 −17,342,298원이 실제 손익으로 교체된다.**

**예산** — P0+P1 조사 반나절, P2~P3은 발견량에 따라(네이버는 3세션 걸렸다).
