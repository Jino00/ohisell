## 5. 알려진 이슈 / 주의사항

### 5-A. ★★왜 「완료」가 세 번이나 잘못 보고됐나 (기제 — 반드시 알 것)
매트릭스 36축은 **ref 68 머리말이 직접 밝히듯 「이미 있던 값을 옮겨 조립한 것」**이지 API 표면에서 연역한 것이 아니다. 즉 **「우리가 이미 본 것」의 목록**인데 제목이 「전 자료」를 주장해 다음 독자를 속였다. 그 위에서 「36축 중 몇 축 완료」를 세면 **분모가 이미 틀렸다.**
→ 개정 4가 **3층 깔때기**로 그 층위를 갈랐다. 앞으로 「완료됐나」에 답할 때는 **어느 층의 분모인지 먼저 밝힌다.**
→ 잡은 것은 세 번 다 **Jino의 재점검**이었지 모델의 절차가 아니다. 「지시 대장」 기능은 별도 트랙(Jino 착수).

### 5-B. ★「크론이 있다」와 「그 결정이 실행됐다」는 다르다
D-NAO-186 ①은 미실행인 줄 알았는데 `sync_naver_keyword_volume`(`"0 9 * * sun"`)이 **이미 있었다.** 그런데 그 잡은 **저클릭 키워드(30일 클릭<10)만** 대상으로 `NaverEntity.monthly_volume`을 **덮어쓴다** — 승인 의도(기준선 시계열)를 충족하지 않는다. prod 실측: `on` 키워드 **90,253개 중 값 보유 5,000(5.5%)**, 1회전 **약 90주**, ★**돈이 닿은 1,193개(비용 4,070,471원)는 필터에 걸려 구조적으로 대상 밖**.

### 5-C. ★★검색량 기준선은 쇼핑을 원리적으로 못 잰다 (새 제약)
`naver_ad_daily.keyword_id`가 SHOPPING 캠페인 **66,695행 전건에서 빈 문자열**(QA가 직접 100.0% 확인)이고 `naver_entity(entity_type='keyword')`는 **전량 WEB_SITE**다. 쇼핑검색광고는 등록 키워드가 아니라 상품 기반이라 구조상 그렇다. ⇒ **밴드 비용의 92.5%인 쇼핑의 수요를 이 기준선이 못 본다.**
**해결 경로**: keywordstool은 **임의 텍스트 조회가 되므로** `naver_search_term_daily.search_term`을 시드로 쓰면 쇼핑 수요도 잴 수 있다(미착수).

### 5-D. ★교훈 #313·#314 — 내가 반복한 두 실패
- **#313**: 커밋 메시지에 「벽시계로 읽으면 안 된다」고 써 놓고 **같은 함수의 지름길 분기**에서 그걸 했다. 잡은 것은 통찰이 아니라 **역변이**(「옳게 고쳐도 통과한다」= 테스트가 그 경계에 아무 말도 안 한다). 수정 패턴 = 조건을 고치지 말고 **분기를 소거**한다.
