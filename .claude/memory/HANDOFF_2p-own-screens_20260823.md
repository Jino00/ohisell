## 3. 확정된 결정사항
- **D-CPP-54** — 계약 `docs/contracts/CONTRACT_2p_own_screens.md` 승인(Jino 2026-08-23 13:51 *"그러자"*). 열린 질문 3건 확정: 화면 B **포함** · 라벨 **「쿠팡 로켓그로스(2P)」** · **3P 제외**.
- **메뉴는 최상위가 아니라 대시보드 하위·1P 그룹과 같은 층** — `Layout.tsx:236-240`에 Jino 승인(2026-08-06)으로 못 박힌 규칙 「채널과 그 안의 판매방식 그레인을 같은 줄에 섞지 않는다」가 실재하고, RG는 쿠팡 아래 판매방식이다.
- **1P의 4화면을 베끼지 않는다 — 신설 2 + 기존 완비 화면 딥링크 1.** 근거: 1P 4화면은 1P 고유 업무(발주·납품·계산서)에서 나왔고 2P엔 그 업무가 없다. ★**반례**: `InventoryPage.tsx:99-137`에서 **RG 탭은 완비인데 1P·Wing은 「준비 중」**이다. 원가 커버리지 게이트(2P에만 있음)에 이은 두 번째 사례 — **「1P/3P와 똑같이」를 목표로 잡으면 후퇴다.**
- **새 손익 계산 0** — 기존 SA를 「날짜×옵션」 grain으로 조립·표시만. 새 계산이 필요해 보이면 중단 신호다.
- **보존식 `ok`는 «완전 일치»가 아니라 «원 단위 일치»**(ROUND_HALF_UP). 계약 §4 ⓓ 문언이 「원 단위 일치」라서. **`diff`는 반올림 없이 그대로 낸다 — 드리프트를 숨기는 게 아니다**(1원 이상이면 여전히 「어긋남」).
- **증거 좌표에 «절대값 일치»를 쓰지 않는다.** 계약 §4 ⓔ가 그렇게 개정됐다 — 「배포 전후 같은 창 동일성」으로 잰다.

## 5. 알려진 이슈 / 주의사항

### ★★이 세션이 남기는 가장 값진 것 — 같은 병이 «네 번» 나왔다
**「모름」이 「0 / 아니다」로 접히는 자리:**
1. **적대 리뷰 1R P1** — 보존식 다섯 칸 중 두 칸만 null 가드가 빠져 「모름」을 **0원**으로
2. **prod 화면** — `diff == 0`(완전 일치) 판정 + 1E-25 잔차 → 숫자는 같은데 배지만 **「⚠️ 어긋남」**
3. **prod 화면** — `cons.ok ? A : B`에서 `null`이 falsy로 접혀 전 칸이 「—」인데 배지는 **「어긋남」**
4. **완료 QA** — 화면이 `rows.reduce`로 **직접 더한** 소계가 0으로 접혀, 표 하단 「0원」과 보존식 박스 「1,915,331원」이 **같은 라벨로 다른 숫자**

★**앞의 셋을 고치면서도 넷째는 안 보였다** — 국소 수리로는 안 끝나는 모양이다. 그래서 넷째는 값을 고치지 않고 **진실의 원천을 둘에서 하나로 줄였다**(`conservation.options_net_sum`). **원천이 하나면 갈라질 수 없다.**

★**②와 ④는 테스트 636종·변이 26종이 «전부 초록인 채로» 통과시켰다.** 특히 ②는 **단위 테스트가 원리적으로 못 잡는 자리** — 조립 코드가 같은 잔차를 «양쪽에» 만들어 테스트 입력에선 정확히 상쇄되고 **실데이터에서만 갈린다.** 격리 성공은 필요조건이지 충분조건이 아니다.

### ★증거 좌표가 «세 번» 썩었다 (ⓝ)
−409,639.09(n=5 08:0x) → −494,006.55(13:3x) → **−436,868.18**(17:5x). 그 창은 `정산 인식일 축`이라 **정산 수수료 재동기화에 계속 노출되는 구조**다. ⇒ **합격기준 자체가 재검증 불가능한 형태로 쓰였다** — 결함이 아니라 «기준 작성»의 문제. 후속 계약은 절대값 대신 **재현 가능한 좌표**로 쓸 것.
