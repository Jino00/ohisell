## §3 ★★적대 리뷰가 찾은 것 — 이 슬라이스의 본체

**1R FAIL(P1 3) → 2R PASS(P1 0)**. 리뷰가 변이 30종을 주입했고 그중 9종이 살아남았다.

**P1-1 항등식 파괴(+67)**: `ours/agency/other`는 못 센 그룹까지 더하는데 `unattributed`는 센 그룹만 더했다 ⇒ `2+3984+0+1838 = 5,824 ≠ 5,757`. **막대는 flex라 폭 합 101%여도 눌려서 정상으로 보인다.** ★그 자리를 지키는 «척»하던 내 테스트가 이미 있었고, **원장 행이 없는** 못 센 그룹만 넣어 **원리적으로 실패할 수 없었다.**

**P1-2 순액이 두 사실을 상계**: 그룹별 `used − 원장`은 부호가 둘이고 뜻이 **정반대**다 — **+3,662**(모르는 남의 칸) vs **−1,824(58그룹, 우리가 건 제외가 라이브에 안 보인다)**. 화면은 순액 1,838에 「남의 칸」이라는 한쪽 이름만 붙였다. **절반이 상계된 값이다.**
⇒ ★**이 수리로 새로 드러난 운영 사실**: 우리 원장엔 있는데 라이브엔 없는 제외가 **1,824칸(58그룹)**. 지워졌을 수 있다.

**P1-3 URL 배선 미검사**: `adgroupId → adgroup_id` 한 줄을 지워도 **1,395건 전건 초록**이었다. 기존 테스트는 래퍼의 **함수 인자**만 쟀다. 끊기면 계정 전체 200건을 그 그룹 것으로 그리며 「전부 압니다」를 자신 있게 낸다. ⇒ `lib/exclusionsQuery.test.ts`가 **나가는 URL**을 잰다.

## §7 ⚠️ 이 세션이 낸 prod 사고 2건 — 뿌리가 같다

화면을 보여주려고 **`localhost:8000` → prod 생 SSH 터널**을 열어 둔 채 테스트를 돌렸다. 이 저장소 프론트는 DEV에서 API 주소가 정확히 그 포트이고 **vitest도 mock 안 된 호출을 실제로 보낸다**.
1. **`POST /api/cost/cutover`가 prod에서 200 실행** — `product_master.cost_price`를 쓰는 유일한 문. `cost_price_history` 변경 **0건**(멱등 no-op, 이미 그날 적용돼 쓸 값이 없었다). **운이 좋았다** — 상태가 달랐으면 963 SKU가 움직일 수 있었다.
2. **커넥션 풀 고갈로 prod API 약 40분 무응답**(🧠 20:1x~20:55 추정) — pm2 자가 재시작으로 복구. 데이터 손상 없음.

**둘 다 「화면 확인 때문에 운영에 손을 댄」 것이 원인이다.** `failures.jsonl` 2건 기록. 지금은 **외부 요청 0인 오프라인 뷰어**(`scratchpad/stub_server.py`)로만 본다 — dist를 정적 서빙하고 저장해 둔 실측 응답으로 답하며, 쓰기는 405로 막는다.

★**다음 세션도 이 규율을 지킬 것**: prod 백엔드를 로컬 8000에 붙이지 마라. 붙였다면 절대 테스트를 돌리지 마라.
