## 5. ★다음 세션의 일 (Jino 지시)

> **"다음 세션에서 너가 생성 기능을 네이버 공식api로 만들어봐"**

### 5-1. 현재 우리 쓰기 능력 — 전수 8건, 전부 «수정»

| 메서드 | 경로 |
|---|---|
| `PUT` | `/ncc/adgroups/{id}` (입찰가·잠금) |
| `PUT` | `/ncc/keywords/{id}` |
| `PUT` | `/ncc/targets/{id}` (쇼핑 제외) |
| `POST` | `/ncc/adgroups/{id}/restricted-keywords` |
| `DELETE` | 〃 |

**생성 0건.** `/ncc/ads`는 fetcher에서 전부 `_get`. `tools/`의 브라우저 자동화도 전부 수집이다.

### 5-2. 순서

**① `POST /ncc/adgroups`** — 자족적. 캠페인 ID·이름·입찰가면 된다.
**② `POST /ncc/ads`** — **선행 과제 있음**: `referenceKey`(네이버쇼핑 상품ID, 예 `13687558206` → `91232069492`)가 필요한데 **그 조회 표면을 우리가 안 갖고 있다.** 그 ID는 이미 광고에 실린 소재의 raw JSON 안에만 있고, `naver_adgroup_product`·`naver_entity`·`naver_entity_snapshot` 어디에도 컬럼이 없다. 공식 도움말(`ads.naver.com/help/faq/520`)이 *「네이버 쇼핑에 등록된 상품을 «조회»하여 광고로 등록」*이라 명시 ⇒ **조회 엔드포인트 발굴·검증이 먼저**.

### 5-3. 첫 실전 대상 (Jino가 캠페인을 이미 만들어 뒀다)

**캠페인 `[PAO] 외부 사생활_내부 지문방지필름 플립/폴드`** (Jino 콘솔 생성 22:5x. 우리 DB엔 아직 없다 — **엔티티 동기화 필요**).

★**기종별로 나눈다** — 광고그룹이 키워드·타겟팅 단위이고 폴드8과 플립7은 검색어가 다르다.

### 5-4. 반드시 지킬 것

- **광고 계정에 «처음» 하는 생성 쓰기다.** 북극성 §7·D-NAO-5·42가 사람 Confirm으로 묶어 둔 축 ⇒ **계약 1장 + 적대 리뷰 필수**
- **중복 생성 가드가 핵심** — 수정은 멱등이지만 생성은 아니다. 같은 이름 그룹이 두 번 생기면 되돌리기가 삭제다
- **롤백 경로를 먼저 적는다** (생성한 ID 기록 → 실패 시 삭제/off)
- prod `.env`에 `NAVER_CS_DRY_RUN=0`(실쓰기 허용)이 살아 있다 — 코드 기본값만 보면 틀린다
- **새 캠페인을 PAO 스코프에 넣을 땐 `auto_operate=0`으로 시작** — 데이터 0에서 시작하므로 §4-2의 14클릭 문제가 더 심해진다

## 11. 하네스 관측

- **트랙 확인줄 훅이 세션당 22회 오탐** — `$CWD`(공유 메인 폴더)를 읽는데 그게 `origin/main`보다 **1,028커밋** 뒤처져 있다. 확인줄 17개는 전부 origin/main에 실재. 공유 폴더엔 쓰지 않았다(남의 미추적 파일이 쓸려 들어간다)
- **서브에이전트 판정이 저장소에 안 남는다** — 완료 QA가 적대 리뷰를 **판정불능**으로 처리했다. PR #631 코멘트로 상환했고, **「적대 리뷰 판정문은 PR 코멘트로」를 관례화**할 것을 제안한다
- `ops_diary_entries.created_at`은 **UTC**, `scheduler_state.last_run_at`은 **KST**(9시간 차). UTC로 읽으면 시각 분석이 통째로 오독된다
- prod 포트가 배포마다 8001↔8011로 뒤집힌다 — 조회 스크립트는 **활성 포트를 스스로 찾아야** 한다
- **bare SSH 셸에서 `naver_sa_writer`를 쓰려면 `set -a; . ./.env; set +a`가 필수** — 안 하면 전 엔드포인트 403(서명 키 빈 값). `app.database`를 import하면 우연히 실려서 **같은 명령 모양인데 결과가 갈린다**
