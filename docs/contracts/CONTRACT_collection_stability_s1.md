## 2. 판단기준

1. **항상 판정의 정본은 prod 상태다, 클라이언트 타이머가 아니다** — 왜냐하면 타이머 판정은 같은 사건을
   보고 도착 순서에 따라 두 병명으로 가르기 때문이다(10:47 「응답 없음」 ↔ 10:50 「실패」가 같은 사건).
2. **「로그인 필요」는 항상 상태로 저장·전파한다** — 왜냐하면 이벤트로만 두면 레인마다 재발견하고
   (오늘 9건/계정) 사람은 실패를 겪어야만 알게 되기 때문이다.
3. **사람 대기는 항상 논블로킹이다** — 창을 남기고 즉시 실패를 보고한다. 왜냐하면 블로킹 180초는 폰
   트리거에선 순수 낭비이고, 공유 루프를 점유해 옆 레인을 굶기기 때문이다.
4. **같은 확증(AUTH)에는 항상 같은 처분** — 왜냐하면 경로마다 처분이 다르면(진입 프로브 재시도 ↔
   status/api 소멸) 같은 병이 화면에 다른 이름으로 나오기 때문이다.
5. **「창을 남긴다」는 항상 탭 층에서 검증한다**(CDP page 타겟 ≥ 1) — 왜냐하면 프로세스 생존만 보면
   로그인할 곳 없는 유령 Chrome이 남기 때문이다(12:55 실측).
6. **수리는 항상 4개 페처 사본 전부에 착지시킨다**(대조표로 확인) — 왜냐하면 사본 구조에서 한 곳
   수리가 재발의 기제였기 때문이다(`_notify_mac`은 2/4에만, 쿨다운 면제는 wing RG에만).
7. **배포 전 항상 repo와 Mac 가동본을 대조한다** — 왜냐하면 repo main이 가동본보다 뒤처진 파일이
   현재 5개 있고(§3 S1-0), 그대로 배포하면 교훈 #288(Basic Auth 누락 3.5일 정체)을 재현하기 때문이다.

## 3. 작업 (S1-0 선행 + W1~W5)

### S1-0 (선행 조건 — 착수 중 발견, 2026-08-22 13:0x)
데몬은 repo가 아니라 **`/Users/jino/.ohisell/tools/`의 설치 사본**을 돌린다(launchd plist 실측).
그 가동본 6개 페처 전부에 prod Basic Auth 배선이 있는데 **repo main엔 `wing_browser_fetcher.py` 하나만**
있다(커밋 `07030022`가 wing만 되돌렸다). 남은 5개(`ad_cost_browser_fetcher` · `ohitech_ad_fetcher` ·
`rocket_supplier_fetcher` · `scheduler_watchdog_poll` · `promo_file_fetcher`)를 **가동본 → repo로
역이식**한다. 안 하면 W3 배포가 Basic Auth를 지운다.

### W1 — 세션 상태 영속화·전파
`CoupangWingCookie.last_error_kind`(String, nullable) 추가. `report_failure`가 kind를 기록,
성공·재로그인 시 클리어. `refresh-status` 응답과 `collection_status`에 노출(+**RG 2큐를 전역 배너
대상에 편입** — 현재 `collection_status.py:25-30`은 4스트림뿐이라 RG가 배너에 아예 안 뜬다).
대시보드 상주 배너: 「오픽스(A01564720) WING 로그인 필요 — Mac Chrome에서」.

### W2 — fail-fast 통일
RG 진입 프로브 AUTH의 `return 1`(`wing_browser_fetcher.py:2345`)을 `RC_LOGIN_REQUIRED`로.
데몬 경로의 180초 블로킹 대기(VS `:1160-1173` · RG `:2339-2346`) 제거 — 창을 띄우고 **즉시 보고**.
`cmd_login` CLI 수동 경로의 대기는 **유지**(사람이 그 자리에 있는 경로다).

### W3 — 로그인 탭 실존 + 논블로킹 로그인 워치
`keep_open`일 때 `page.close()` 생략하고 탭을 로그인 URL에 남긴다 — **4개 페처 사본 전부**
(`wing_browser_fetcher.py:757-759` · `ohitech_ad_fetcher.py:593-601` · `rocket_supplier_fetcher.py` ·
`ad_cost_browser_fetcher.py`). 폴 루프가 `needs_login` 상태에서 **기존 탭으로**(새 창 0) 폴 주기마다
세션 회복을 확인 → 회복 시 state 저장 · prod 상태 클리어 · **로그아웃 이후 login_required로 소멸됐던
요청을 자동 재요청**(★Jino 결정 2026-08-22: **켬**).

### W4 — 화면 어휘 재설계
`streamRefresh.ts:284`의 무조건 `no_response`를 마지막 status 기반 3분할로:
`attempt_count==0` → 「Mac이 요청을 집지 않음(데몬 확인)」 / `in_flight` → 「수집 진행 중 —
백그라운드에서 계속됨」 / 그 외 → 기존 문구. `last_error_kind=login_required`면 즉시 🔑 안내.

### W5 — 도달 대등화
wing/wing2에 `_notify_mac` 추가(ad_cost와 대등). 폰 푸시는 비목표.
