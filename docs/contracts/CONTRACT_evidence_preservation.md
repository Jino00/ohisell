## §2. 판단기준

1. **항상 판정을 코드가 뒤집지 않는다** — 재개방은 «같은 판사에게 다시 묻는 것»까지다,
   왜냐하면 북극성 §6-b M5가 판정기 증식·지름길 신설을 막는다.
2. **항상 증거 집계와 판정 상태를 분리한다** — tally는 status와 무관하게 흐른다,
   왜냐하면 관측이 멈추면 「표본 부족」 기각이 자기충족 함정이 된다(결함 ①의 본체).
3. **항상 skip 경로엔 이유 카운터를 단다** — 왜냐하면 「대조를 안 했다」와 「대조군 0건」은 다르고,
   같은 모양의 침묵이 이미 두 번 재발했다(P2-1 → 조기반환).
4. **항상 주기가 아니라 처리량을 고친다** — 크론은 1일 1회 08:45 그대로,
   왜냐하면 북극성 §5-2 원문: *"주기를 부풀리는 것은 5,403배 오류와 같은 부류"*.
5. **항상 수리 효과를 「기존 재료의 재소화」까지로만 주장한다** — 왜냐하면 실집행 0 = 새 재료 0이고,
   과대 주장이 ④자동화 공백을 «학습층 진행 중»으로 덮는 경로다(§8).
6. **항상 새 상수는 근거 없는 초깃값임을 주석에 병기한다**(2배·+5·캡 15·재심 2회) —
   왜냐하면 표본이 준 결정을 전수로 굳히지 않는다. 주기 감사 재심 안건이다.

## §4. 설계 결정 3건

### ① 재개방 규칙 — 채택: **B안(증거 2배 재개방) + 판정 스냅샷 컬럼**

| 안 | 내용 | 판정 |
|---|---|---|
| A. 기각 사유 분류(«표본 부족»만 재개방) | 판사 스키마에 `reject_reason` enum | **기각** — 기존 26건 판정문이 자유 텍스트라 소급 분류에 **또 하나의 판정기**(LLM 재분류)가 필요. §6-b M5 정면. 신규분만 적용하면 26건이 함정에 남는다 |
| **B. 증거 2배 재개방(사유 무관)** | rejected도 tally 지속, `occurrences ≥ 2×판정시점 ∧ +5` 도달 시 pending 복귀 | **채택** — 판정기 신설 0, 26건 소급 적용 가능, 재심 횟수가 log₂로 자연 상한 |
| C. TTL 재개방 | 기각 후 N일 지나면 재개방 | **기각** — 재료가 얼어 있는 지금 시간은 새 증거를 안 만든다. 같은 증거로 같은 판정을 반복하는 순수 LLM 비용 |
| D. 판사가 재개방 조건을 판정문에 명시 | "N회 더 쌓이면 다시 보라"를 기계 판독 | **기각** — LLM 출력에 제어 조건을 싣는 파싱 취약성 + 프롬프트 비대화. B가 같은 효과를 결정론적으로 낸다 |

- **형태**: `ops_wisdom_candidates`에 nullable 컬럼 3개 마이그레이션 —
  `judged_at` · `judged_occurrences` · `rejudge_count`(default 0).
  `judge_verdict_json`에 끼워 넣는 무마이그 안은 기각(수확층이 판정문 컬럼에 쓰면 소유권이 흐려지고,
  재개방 조건을 SQL로 관측·검증할 수 없다).
- **기존 26건 소급**: 마이그 시점에 `judged_occurrences := 현재 occurrences`로 백필
  (관측값 기록이지 발명이 아님).
- **비용 상한 이중**: (a) 2배 게이트 ⇒ 시그니처당 재심 ≤ log₂(총관찰)
  (b) `rejudge_count ≥ 2`면 부활 중단 — 종전 skip_terminal로 복귀(tally도 멈춤, 행 비대 방지).
  재심분도 `_MAX_PER_RUN` 안에서만 소화된다(별도 슬롯 없음).
- **promoted는 재개방 대상이 아니다** — 답이 달라야 한다: 승격 지혜의 사후 성적은 성적표가
  «집행 결과»로 재는 것이지 관찰 tally로 재는 게 아니고, 승격↔기각 플립플롭은 브리핑 주입
  (`active_wisdom_prefix`)을 흔든다. promoted는 오늘과 동일하게 완전 terminal.
- **재심 재료**: 프롬프트 view에 `prior_judgments`(시각·verdict·rationale·당시 표본 수) 병기 —
  재료만, 판정 강제 아님. 이전 판정문은 이력으로 보존(append, 덮어쓰기 금지).

### ② `action=None` — 채택: **카운터 신설 + 소비층 방어. None 매칭은 하지 않는다**

- (a) None을 형제 매칭 값으로 인정 → **기각**: action은 패턴의 의미 축 그 자체다.
  «미상»끼리 묶으면 서로 다른 액션이 가짜 대조군이 되어 판사 재료를 오염시킨다(§7 학습 오염과 같은 결).
- (b) **채택**:
  ⓐ `_sibling_buckets` 조기반환을 `excluded_from_controls`에 새 키(`no_action`)로 센다
    — 4키 dict의 «빈 값과 키 부재는 다르다» 관례 유지
  ⓑ 수확이 action 없는 일기 행을 `skipped_no_action` 카운터로 skip하고 **새 후보를 만들지 않는다**
  ⓒ 기존 None 후보 5~6건은 hidden 처분 + 사유 기록(삭제 금지 — 수확이 막히므로 재부활 경로 없음)
  ⓓ 판사 대기열에서 action 없는 후보 제외 + 카운터
- **선행 1보**: 구현 착수 전 «어느 일기 행이 action 없이 오나» 원인 실측 1회(읽기 전용).
  결과는 기록·이월만 — 생성층 수리는 §1 안함 ②(추정 금지의 집행이지 스코프 확장이 아니다).

1. **이 계약 자체가 «④자동화 26세션째 0»의 정당한 얼굴일 수 있다.** 「학습층은 진행 중」이라는
