## §2. 범위 — 3슬라이스, 이 순서로

**S1 (가) `PAO_OPS.md` 전수 재검증** — 별도 읽기 전용 기 1기 위임. §0~§12의 사실 주장을 항목화하고 각각 「주장 → 실행한 명령 → 관측값(시각) → 판정(재현/반증/미상)」. §11 「재는 법」의 명령들을 그대로 재사용한다(그 절이 이미 자동 검사의 씨앗이다 — 살린다).

## §3. 판단기준 (항상 A, 왜냐하면)

1. **항상 재현된 사실만 정본에 무표기로 싣는다**, 왜냐하면 이 작업의 존재 이유가 「그럴듯하지만 낡은 문서」의 제거인데 미재현 주장을 옮기면 낡음을 이사시키는 것이기 때문. 미재현은 `[미상]`+출처·날짜로만.
2. **좌표는 항상 심볼로 쓰고 줄 번호를 쓰지 않는다**(`파일경로::심볼`), 왜냐하면 줄 번호는 커밋 하나에 낡아서 검사기가 「살아있는 좌표」를 죽었다고 하거나 그 반대를 말하게 되기 때문.
3. **검사기는 repo 정적 사실만 본다 — prod DB·네이버 API 호출 0**, 왜냐하면 좌표의 실재는 repo가 정본이고, 검사가 외부를 부르면 감시가 부하가 된다. prod 신선도는 이 검사기의 질문이 아니다(그건 ② 대시보드 계약의 몫).
4. **실측값에는 항상 관측 시각(KST)을 병기하고 검사 대상에서 제외한다**, 왜냐하면 값은 매일 변해 원리적으로 자동 검사가 불가능하고, 시각 없는 값이 곧 「조용히 낡는 문서」의 정체이기 때문.
5. **미분류 백틱은 침묵 스킵하지 않고 카운트로 표면화한다**, 왜냐하면 발견 0건과 검사 안 됨은 같은 숫자로 보이면 안 되기 때문(교훈 #123).
6. **검사기에 강제층을 세우지 않는다**(훅·머지 차단 없음), 왜냐하면 전역 §1 「게이트를 새로 세우지 않는다」이고, 실행 지점은 주간 감사라는 이미 있는 주기가 담당하기 때문.
