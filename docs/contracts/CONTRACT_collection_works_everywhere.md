## 2. 판단기준

1. **목표는 항상 «수집이 된다»로 재고, 화면 정합은 그 판정의 필요조건으로만 다룬다** — 왜냐하면
   어제·오늘 계약이 수리 묶음을 목표로 세워 «수리 합격·체감 실패»가 났다(목표 단위 오류의 실증).
2. **세션 복구는 항상 공용 모듈(`coupang_auth`) 배선으로 한다, 레인별 재발명 금지** — 왜냐하면 4사본
   구조에서 「한 곳만 수리」가 재발의 기제였고(어제 계약 판단기준 6), 오늘 로켓 레인이 이 모듈의
   유효성을 라이브로 증명했다(10:29:13→10:30:18→완주).
3. **AI는 항상 비밀번호를 입력·취급하지 않는다** — 왜냐하면 그것이 D-7의 실제 제약 전부이고,
   Keychain이 입력 주체가 되면 AI는 비번을 볼 일이 없다(등록은 Jino 터미널 1회).
4. **판정의 정본은 항상 prod `collection-status`다, 클라이언트 타이머가 아니다** — 왜냐하면 오늘
   227초 run이 prod엔 `fresh`, 화면엔 실패로 갈라졌고 맞은 쪽은 prod였다(S1 판단기준 1 상속).
5. **화면 타임아웃은 항상 «추적 중단»이지 «수집 종결»이 아니다** — 왜냐하면 수집은 Mac 데몬이 독립
   수행하므로 화면이 포기해도 수집은 계속되고, 종결로 말하면 성공한 run을 실패로 오보한다.
6. **회귀 방지는 항상 «표면을 끊는 변이가 죽이는 테스트»로 남긴다** — 왜냐하면 단위 테스트는
   「함수가 값을 만드나」만 묻고 「사람이 그걸 보나」를 못 묻는다(0-C-A: 단언 3곳 초록·화면 오답).
