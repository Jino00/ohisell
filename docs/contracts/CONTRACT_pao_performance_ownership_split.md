## 1. 목표 / 이번에 안 하는 것

**목표**: 지금 `/naver-ad/performance`는 전 캠페인 단일 합계다 — `metrics_aggregator.py:79-83`의
필터가 날짜와 백필 센티넬뿐이라 소유권 조건이 없다. 그래서 「PAO가 실제로 돌린 성과가 얼마인가」를
화면에서 읽을 수 없다.

되면: 각 날짜의 **당시 관할**(`naver_change_log` 재구성) 기준으로 **전체 / PAO 관할 / 비관할**이
금액·ROAS·**분모(캠페인 수·그룹 수)**까지 갈라져 보인다. 실측이 말하는 진짜 상태 — 「07-30 10:48
이후 08-28까지 PAO가 실제 맡은 광고비 **0원**」 — 이 처음으로 화면에 뜬다. 이 정직함이 이 계약의
가치다: 현재 관할 소급이었으면 같은 구간이 2,170,514원(11.1%)으로 잘못 떴을 자리다.

**이번에 안 하는 것** (인접하지만 범위 밖):

- 밴드 숫자에 근거한 최적화 판단·제안·입찰·제외·개방 → 소관: `track_naver-ad-optimization.md`
- `NaverHourlySnapshot` adgroup 그레인 추가 등 수집·스키마 변경 → 소관: `track_naver-ad-optimization.md`
- 2026-07-11 이전 관할 이력의 소급 복원(원천이 없다 — 화면은 「모름」 표기만) → 소관: `track_naver-ad-optimization.md`
- 밴드별 총이익 환산(전환매출은 네이버 신고치이지 총이익이 아니다) → 소관: `track_naver-ad-optimization.md`

## 2. 판단기준

- 항상 관할 판정은 **세 축의 ∧**이다 — `optimizer=='ours' ∧ auto_operate ∧ 그룹 진리표`,
  왜냐하면 코드가 실제로 셋 다 본다(`proposal_writer.py:113-118` · `auto_operator.py:309` ·
  `adgroup_scope.py`; ∧ 선례 `cold_start_bid_lane.py:57-63`). **실증**: 07-30 10:48 ~ 08-29 12:53은
  `auto_operate`가 ON인데 `optimizer='none'`이었다 — 진리표만 보면 이 한 달이 통째로 오답이 된다.
- 항상 각 날짜는 **그 날짜의 관할**로 판정한다(방법 B, Jino 선택), 왜냐하면 현재 상태 소급은
  「지금 맡은 것들의 과거 성과」라는 **다른 질문**에 답한다.
- 항상 재구성의 시각축은 `naver_change_log.changed_at`(**KST**)만 쓴다, 왜냐하면
  `naver_campaign_settings.updated_at`은 UTC라 섞으면 경계일이 9시간 어긋난다(실측 확인).
- 항상 「모름」은 모름으로 표기한다(이력 밖 구간·해석불가 행), 왜냐하면 0으로 적으면 화면이
  초록으로 거짓말한다.
- 항상 장중 전환일은 **어느 밴드에도 더하지 않고 「전환일」로 별도 표기**한다, 왜냐하면
  `naver_ad_daily`는 하루 통짜라 시각 분할이 원리적으로 불가하고, 임의 배정은 임의 오차를
  «정확한 숫자»의 얼굴로 내보낸다.
- 항상 밴드는 금액과 **분모**를 함께 낸다, 왜냐하면 분모 없이는 「얼마나 맡고 있나」가 안 읽힌다.
- 항상 집계는 `adgroup_id <> '__backfill__'`를 건다, 왜냐하면 센티넬을 안 빼면 금액이 배로
  부푼다(이 계약 착수 조사 중 실제로 한 번 밟았다 — 07-30 캠페인 비용 687,715 → 정정 343,859).
- 항상 화면용 대량 판정은 세션 커넥션 계열(`scope_rows_for_campaigns` 방식)로 한다, 왜냐하면
  `in_scope_now`의 독립 커넥션은 실쓰기 직전 재확인 전용 설계다.

## 3. 금지선

- **모름·전환일·이력 밖 구간을 0이나 어느 밴드 합계로 뭉개기 금지.** 항등식
  「전체 = PAO 관할 + 비관할 + 전환일 + 모름」이 항상 성립해야 한다 — 새는 돈이 없어야 뭉갠 게
  없다는 증거가 된다.
- `before_value`/`after_value` 해석 실패 행을 **조용히 건너뛰기 금지** — 「해석불가 N건」으로 세어
  화면에 노출한다. 포맷 3종 실측: 스칼라 문자열(`'none'`/`'true'`) · JSON(id 771
  `'{"optimizer": "ours", "auto_operate": true}'`) · scope 문자열(`'role=None enabled=True'`).
- `changed_at`(KST)과 `updated_at`(UTC) 혼용 금지.
- 판정·재구성 조건식을 하니스·프론트에 복제 금지 — 단일 모듈에만 둔다(D-NAO-125).
- `in_scope_now`를 그룹마다 반복 호출 금지(독립 커넥션 폭주 + 설계 의도 밖).
- 엔진 실행 경로(제안·실집행·입찰·제외) 코드 변경 금지 — 이 계약은 **읽기·표시만** 한다.
- 광고 계정 쓰기 0건 · `auto_operate`/`optimizer`/스코프 행 변경 0건.
- DB 스키마 변경 금지 — 재구성은 `naver_change_log` 읽기만으로 한다(마이그레이션 0건이 정상 상태).
- 배포는 `scripts/safe_deploy.sh`만(D-NAO-49). 프론트 CAS 거부 시 반드시 재빌드 후 재배포.
