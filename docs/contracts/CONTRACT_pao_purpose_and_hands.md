## §1. 목표 / 이번에 안 하는 것

**누가 뭘 못하나** — 네 겹:
- **엔진이 「나쁨」과 「알 수 없음」을 못 가른다.** 전환 0이면 `est_ROAS=0<BEP`가 자동 성립해 하향 트리거인데, 같은 무표본이 상향에선 판단 보류다(ref 116 §5 — DOWN 표본 하한 없음, UP 4중 요건). 표본 없는 그룹은 **내려갈 수만 있다.** ★v7 그리고 이 비대칭은 **판정 경로 «자체»에 있다**: `auto_operator.py:1149`의 `if p.proposal_type == "bid_up":` 분기만 `_check_bid_up_conditions`를 타고, **`bid_down`은 그 계열의 조건 검사층을 아예 안 탄다**(§2-A-3).
- **사람이 엔진을 만질 손이 없다.** 켜진 캠페인을 API로 못 끄고, 입찰 제안을 새로 만드는 입구가 없고(쓰기 엔드포인트는 승인·실행 둘뿐), 급한 불은 네이버 콘솔 직행 = 대행사와 같은 경로.
- **잘린 것을 되살리는 손이 통째로 없다.** 제외 재개방은 라이브 `probation` **0행** — 「14일 대기」가 아니라 「영영 안 열림」. 킬스위치 3종 중 2종이 배포·재시작으로만. 대행사가 내리면 보기만 하고 못 되돌린다(`feed_reapply`는 재적용기가 아니라 분류기).
- **올릴 때 «얼마로»를 정하는 로직이 없었다** — 그래서 리드가 개별 판단을 냈고, 그건 §4-7(전역 규칙)·D-NAO-65 ③의 정신에 어긋났다.

## §2. 극복방안 — 설계

### 2-A. 「성과가 나쁨」과 「성과를 알 수 없음」을 가르는 전역 규칙

**원리: 가시 노출 상태에서 잰 나쁨만이 나쁨이다.** 최소노출가 아래에서 잰 성과는 성과가 아니라 **결측**이다.

**상태 「판정불능(저노출)」의 정의** (전역 상수만 — 캠페인 id 하드코딩 0건, D-NAO-65 ③):
> ⓐ **노출이 구조적으로 눌려 있다** — (ⓐ1) 실효 입찰 < 당일 최소노출입찰가(`market_bid_probe.py::fetch_exposure_min` — ★**표본 없이도 판정 가능한 유일한 신호**, 매일 수집 중) **또는** (ⓐ2) 정착창 일평균 노출 < 자기 이전 정점 창의 전역 비율 하한(바닥 고착).
> ⓑ **전환 표본이 판정 하한 미만** — 정착창 전환 < 전역 하한.
>
> ★★v9 **결합자는 `ⓐ ∧ ⓑ`다** (독립 검사 F1 — v8까지 정의부에 결합자가 없었고 §3 P3 카운터만 `∨`로 써서 **두 곳이 반대로 읽혔다**). **∧인 이유**: 판정불능의 뜻은 「**노출이 눌려서** 전환을 못 재는 상태」다. ⓐ만이면 「보이진 않지만 이미 충분히 측정된 소재」(§0의 그룹 — 90일 클릭 2,508·전환 168·`confident=True`)까지 삼켜 **하향을 통째로 동결**해 버리고, ⓑ만이면 「잘 보이는데도 안 팔리는 진짜 나쁨」까지 감싼다. **둘 다 성립할 때만 «모른다»**이다.
> ⇒ ★**§0의 그룹은 판정불능이 «아니다»** — ⓐ1은 성립하나(입찰 810 < F 1,050) **ⓑ가 불성립**(전환 168, 표본 충분)이다. 따라서 P0-ⓒ의 기본값 **「축소」(하향)는 §2-A-1의 하향 동결·§5의 「판정불능 그룹에 자르는 제안 금지」에 걸리지 않는다.** 이 판정을 처분 기록에 근거로 적는다.
> ★v9 **그리고 카운터 둘은 다른 것이다** — 「최소노출가 미달 수」(ⓐ1 단독) **≠** 「판정불능 수」(ⓐ∧ⓑ). 전자는 상수 없이 오늘 셀 수 있고, 후자는 SPECS 등재가 선행이다(§3 P3).
> ★v7 (상수값은 **구현 세션이 근거를 대고 정해 SPECS로 등재한다** — §4-9의 적용례이고 P4가 「신설 상수는 태어날 때부터 SPECS」로 사후 가시성·정정 경로를 이미 갖췄다. **Jino 질문이 아니다** — 이 계약은 값만 발명하지 않을 뿐, 값을 정하는 주체와 절차는 여기 못박는다.)

**처분 규칙 넷**:
1. **성과 판정 기반 하향 동결** — 판정불능 상태에서 `est_ROAS<BEP`는 「나쁨」의 증거로 소비 금지. **단 지출 절대액 기반 백스톱(출혈밸브·예산 상한·킬스위치)은 그대로 산다** — 「모르면 올려라」가 위험한 이유가 이것이고, 돈이 새는 것은 표본 없이도 사실이다. **동결되는 것은 «성과의 해석»이지 «지출의 지혈»이 아니다.**
2. **탐침 후보 편입** — 판정불능은 방치가 아니라 정보 구매 대상(2-B). ★단 §0이 보였듯 **판정불능이 아닌 그룹(표본 충분)은 이 경로에 안 들어간다** — 그것이 이 규칙의 정확도다.
3. **「진짜 나쁨」의 판정면** — 정착창에서 (입찰 ≥ 최소노출가 ∧ 노출 ≥ 하한 ∧ 전환 표본 ≥ 하한)인데 보정ROAS < BEP → **나쁨 확정, 하향 허용**.
   ★v7 **DOWN 경로에 «승인층» 신설 — 판정 경로 자체의 비대칭 해소.** 실측: `auto_operator.py:1149-1150`의 `if p.proposal_type == "bid_up":` 분기만 `_check_bid_up_conditions`(4중 요건)를 타고, **`bid_down`은 조건 검사층을 아예 안 탄다**(`pause`는 외부 정지 검사만 별도). SPECS 7:0이 «학습 가능성»의 비대칭이라면 이것은 **판정 경로 «자체»의 비대칭**이고, 07-29 실패 5건 📄이라는 라이브 재현까지 있다. ⇒ P4에서 `bid_down`에 UP과 같은 자리의 검사 함수(가칭 `_check_bid_down_conditions`)를 신설한다 — 내용은 최소 두 겹: **표본 하한**(이 항의 판정면) + **판정불능 검사**(규칙 1). 기존 `_intraday_loss_leash`·CPC 급등 게이트는 «지출 지혈»층이라 별개로 존치한다. **§8의 「대칭 절단」 변이는 바로 이 승인층을 겨눈다**(제거 시 나선이 침묵 복귀하는지).
   기존 종료 판정(`not_rank` 소재 병리·`not_serving` 연속 무노출)은 유지 — 「올려도 소용없음」 확정 그룹은 탐침에서도 제외된다(**진짜 나쁜 것의 상향을 막는 두 번째 벽**).
4. **소급 적용** — 이 규칙은 **이미 생성된 pending 제안에도 적용**된다: 판정불능 그룹에 대한 절감·하향성 pending은 실행하지 않고 반려·보류하며 사유를 원장에 남긴다. 규칙이 제안보다 늦게 태어났다는 이유로 규칙 이전의 제안이 실행되면, 규칙은 앞으로만 좋고 지금 굶는 그룹은 못 지킨다.

### 2-D. 탐침 목표 입찰가 — 전역 산식 ★

**세 항 전부 기존 재료다 — 새 발명 0.**

| 항 | 정의 | 좌표 |
|---|---|---|
| **F** 가시성 하한 | 당일 최소노출입찰가 — 이 아래는 정보가 아예 안 사진다 | `market_bid_probe.py::fetch_exposure_min` |
| **R** 밴드 진입가 | 이익 스팟 밴드 하단(rank 4.0) 가격 — 탐침의 목적이 **전환 표본**이므로 목표는 F가 아니라 R | `market_bid_probe.py::fetch_position_ladder` + `exploration.py::_EXPLORATION_TARGET_BAND` |
| **E** 경제성 상한 | 클릭당 손익분기 CPC = 수축 rpc ÷ BEP. 굶은 창의 rpc 문제는 이미 풀려 있다 — `resolve_rpc`가 자기 실측과 상위 층 prior를 **연속 수축**으로 섞는다(D-NAO-119) | `bid_ceiling_calculator.py::ceiling_from`·`resolve_rpc`·`resolve_bep` |

**산식**: `target = min(E, R)`, 단 `target ≥ F`여야 발사.
1. **E ≥ R** → target = **R** (밴드 하단까지만 — 과열밴드 진입 금지).
2. **F ≤ E < R** → target = **E** (경제성 안에서 보이는 데까지).
3. **E < F** → ★**자동 탐침 금지.** 「보이게 하려면 손해」이므로 **«손해 구매 카드»로 사람에게 올린다.** 손해를 살 수 있는 것은 사람뿐이다.
4. **스텝**: 봉투 그대로 — 사이클당 탐색 상한 30%·쿨다운 2h로 **스텝 분할** 도달. **봉투 면제 신설 없음**(§5).
5. **정지**: `evidence_window` 종료 조건 재사용(클릭 15 확보 / 7일 5만원 소진 / 창 비활성) + 래더 `stop_observe`·`not_rank`·`not_serving`.
6. **되돌림**: 실패 판정 시 `probe_revert.py::run_settlement` 관례 재사용 — 탐침 «전» 입찰 복원. 복원값 < F면 「복원 = 판정불능 재진입」을 카드에 표기(사람 결정).
7. **사다리 미수집 그룹**: R 미상 → fail-closed, 기존 래더의 적응 스텝 경로만.
8. ★v7 **산출이 나가는 유형 지정** — 산식의 target은 **기존 탐색 스텝 유형 `bid_up_explore` 제안**으로 나간다(`exploration.py`에 실재하는 유형 — 새 proposal_type 신설 없음, §4-4). rationale에 target·F/R/E 세 항·분기 번호를 기록하고, 기존 승인→실행 경로·D-NAO-13 게이트·봉투를 그대로 통과한다. **카드까지만 있고 실집행으로 나가는 경로가 미지정이던 구멍을 여기서 닫는다.**

★**«손해 구매 카드»의 정보 가치 근거 3종 — 전부 네이버 자체 데이터**:
1. **과거 정점 실적 (직접 증거)** — 정점 창의 노출·전환·그때의 입찰·순위. **매핑이 필요 없는 자기 데이터이고 「보이면 팔린다」의 직접 증거**다.
2. **판정불능 지속 일수** — 오래 모를수록 기회비용 추정이 커진다.
3. **동류 대비 초과 낙폭** — 같은 기간 캠페인 전체 낙폭 대비 이 그룹의 낙폭. **시장 전체가 꺼진 게 아니라 이 그룹만 꺼졌다**면 회복 여지가 그룹 내부 요인에 있다는 신호다.

★**⚠️ 카드가 「사라」를 뜻하지 않는다** — §0이 실증했다: 근거 3종이 모두 성립해도(정점 실적 있음·지속 일수 큼·초과 낙폭 −92%), **E가 F보다 한참 낮으면 사지 않는 것이 정답**이다. 카드는 «사람이 판단할 재료»이지 «사라는 권고»가 아니다. **이 구분을 카드 문구에 명시한다.**
★v7 **③분기 카드가 놓이는 자리**: P4 코드화 «전»(P0 포함)에는 관측 일지 + 트랙 파일 1장이 그 자리다. P4 «후»에는 **콘솔 탐침 카드가 상설 슬롯**이다 — 다른 상품이 ③분기에 걸리면 같은 자리에 같은 형식으로 올라온다.

**Phase 배치**: P0 = 산식 1장 + 적용(규칙 층, 사람이 손으로 계산) → P4 = 산식의 코드화(기존 부품 조립).
