## 1. 목표 / 이번에 안 하는 것

**목표** — 대시보드 KPI 4칸(총매출·순이익·이익률·주문건수)을 누르면 **그 숫자가 어디서 나왔는지**를
채널별 구성과 검산식으로 보여주는 전용 페이지로 이동하고, 원래 화면(조회 기간·로켓 축 그대로)으로
돌아올 수 있다.

지금은 카드 숫자를 의심해도 **확인할 길이 화면 안에 없다.** 값은 `GET /dashboard/kpi` 한 곳에서
나오는데 응답에 실리는 건 최종 4값과 변화율뿐이고, 분해 항목(원가·수수료·광고비·고정비·부가세)과
채널별 기여는 **HTTP 경계를 못 넘는다.** 되면 달라지는 것: 「−285,507원이 왜 −285,507원인가」를
Jino가 화면에서 스스로 검산할 수 있고, 하한(`net_scope`)·이익률 분모 차이 같은 **이미 계산돼 있으나
화면 밖에 갇힌 자백**이 사용자에게 닿는다.

**이번에 안 하는 것** (인접하지만 범위 밖):
- **주문 단위 원장 드릴다운** — 채널을 다시 눌러 개별 주문·상품 줄로 내려가는 것. (Jino가 「채널별
  구성 + 검산식」을 골랐다. 로켓1P·RG는 `orders` 행이 없어 원리적으로 못 내려간다.)
- **숫자 자체를 고치는 것** — 이 작업은 **읽기·표시 전용**이다. 계산이 틀린 게 보이면 고치지 않고
  앵커 `## 이월`에 소관 트랙을 지목해 적는다. → 소관: `docs/tracks/active/track_coupang-2p-parity.md`
  (손익 계산) · `track_coupang-rg-replenishment.md`(RG 축)
- **요약표·상품표·차트의 근거화** — 이번엔 **KPI 4칸만**이다.
- **원가 미상 경고 배너 개편** — 이미 화면에 있다. 근거 페이지에서 링크만 건다.
- **다른 화면(콘솔·진단 보드 등)의 근거화** — 소관: 각 트랙.

## 2. 판단기준 (항상 A, 왜냐하면 ○○)

1. **근거는 카드와 «같은 경로»에서 나온다** — `_channel_rows()` → `_kpi_totals()`를 재사용하고,
   근거용으로 값을 다시 계산하지 않는다. 왜냐하면 **경로가 둘이면 언젠가 반드시 갈라지고**
   (D-22, 2026-08-19: 카드 569,635원 vs 표 −28,253원), 카드와 다른 숫자를 말하는 근거는
   근거가 아니라 두 번째 버그다.
2. **행이 «안 가진» 항목은 0으로 채우지 않고 「—」로 둔다** — 왜냐하면 RG·로켓1P 행은
   `calculate_channel_summary` 산출이 아니라 평행 엔진에서 오므로 분해 항목이 **원래 없다.**
   0으로 채우면 「원가 0원」이라는 거짓말이 되고, 그건 이 저장소가 이미 겪은 결함 모양이다
   (원가 미상 매출 = 순이익 부풀림).
3. **검산식은 항상 카드 값과 대조해 ✓/✗를 화면에 찍는다** — 왜냐하면 「합계 = 카드」를 사람이
   눈으로 맞춰 보게 두면 안 맞는 날 아무도 모른다. 불일치는 **화면이 스스로 말해야** 한다.
4. **하한(`net_scope`)·이익률 분모(`net_basis_revenue`)는 반드시 노출한다** — 왜냐하면 이 둘이
   이미 계산돼 있는데 카드에선 툴팁 한 줄로만 스치고, 근거 페이지의 존재 이유가 바로 이
   「화면 밖에 갇힌 자백」을 꺼내는 것이다(2026-08-23 QA 원문: *"그 숫자를 믿어도 되는지 사용자가
   확인할 길이 아직 화면 밖에 갇혀 있다"*).
5. **조회 조건은 URL이 나른다** — `date_from`·`date_to`·`rocket_basis`를 쿼리스트링에 싣는다.
   왜냐하면 Jino가 「돌아올 수도 있게」를 지시했고, 조건이 URL에 없으면 뒤로 가기가 조건을 잃거나
   근거 페이지 링크를 남에게 못 보낸다.
6. **새 백엔드 응답 필드는 `schemas.py`까지 손댄다** — 왜냐하면 서비스층이 정직하게 계산해도
   스키마에 칸이 없으면 **HTTP 경계에서 조용히 사라진다**(교훈 #321·#223, 저장소 상습 결함).
