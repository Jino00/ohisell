## 2. 판단기준 ("항상 A, 왜냐하면")

1. **항상 재고 정본은 한 곳이다**, 왜냐하면 두 곳에 숫자를 두면 어긋난 순간을 아무도 못 잡고, 틀린 원장이 발주 수량을 자동 생산한다.
2. **항상 자사창고를 허브로 모델링한다**, 왜냐하면 1P는 납품 후 쿠팡 소유라 우리가 운영할 수 없고, 우리가 결정하는 것은 자사창고에서 나가는 네 갈래(1P 납품·2P 발송·3P·스스 출고)뿐이다.
3. **항상 산출은 «제안»이고 실행은 사람이 한다**, 왜냐하면 재고는 대사 표면이 없어 틀린 자동 실행을 외부가 잡아주지 않는다.
4. **항상 매핑 확정 상품만 계산에 넣고 미확정은 「매핑 필요」로 표면에 드러낸다**, 왜냐하면 조용히 빼면 발주 누락이 되고 조용히 넣으면 발주 오염이 된다 — 둘 다 침묵이 병이다.
5. **항상 만료되는 자격증명(이카운트 키 1년·Wing 쿠키)은 감시와 함께 태어난다**, 왜냐하면 Wing 쿠키 61/72일 방치가 보여줬듯 만료는 배치를 조용히 죽인다.
6. **항상 폴링·배치 전제로 설계한다**, 왜냐하면 이카운트 웹훅은 공식 문서에서 확인되지 않았다.

## 3. 금지선

1. **재고 정본 이원화 금지** — A/B 갈래 확정 전에 이카운트·ohisell 양쪽에 자사창고 수량을 쓰기 시작하는 것.
2. **자동 실행 금지** — 발주·RG 발송·재고 수정의 자동 «실행». 시스템은 수량 제안·전표 기록까지만. (이카운트 자동 차감은 «판매 실적의 전기(轉記)»라 허용 — 임의 수정과 다르다.)
3. **실사 대조 장치 없이 자동 차감 가동 금지** — 스팟체크라도 대조 경로가 먼저 있어야 차감을 켠다.
4. **매핑 미확정 상품의 발주 수량 산출 금지** — 「매핑 필요」 표기로만 노출.
5. **감시 없는 자격증명 금지** — 이카운트 인증키·세션은 만료 감시(잔여일 표면화) 없이 배치에 연결하지 않는다.
6. **이카운트 엔드포인트를 «제3자 단서»로 구현 금지** — 공식 매뉴얼(계정 내) 확인 전 S5 코드 작성 불가.
