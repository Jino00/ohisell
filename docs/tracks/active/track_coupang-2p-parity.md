## 배경 — 왜 gross로는 안 되나 (ref 89, 2026-08-21)

우리 gross 주문 원장(`coupang_rg_order_item`)은 **틀리지 않았다**. 쿠팡 RG 주문 API와 원 단위로
일치한다. 어긋나는 것은 쿠팡의 **두 표면**이다:

| | |
|---|---|
| 주문 API | **gross** — 취소·반품 미반영. 그리고 **취소·상태 축이 아예 없다**(목록·단건 둘 다) |
| 콘솔 판매분석 | **net** — 반품은 반품일에 음수, 취소는 원 판매일에서 소급 제거 |

즉 gross에서 net을 빼는 길이 **원리적으로 없다.** 오픽스 30일 실측 **+694,070원(+11.8%)·34개**가
그 간극이고, 갭의 성격은 단가가 아니라 **건수**다(30일 중 9일은 원 단위 완전 일치).
⇒ net을 알고 싶으면 net을 주는 표면을 읽어야 한다.

선행 이력: 06-14 D-11이 「결함 아님(gross vs net)」으로 종결(갭 5.1%) → 08-12 재측정 8.10%(이월)
→ 08-20 12%(이월) → 08-21 확정. **D-11의 가설은 맞았고 「메울 소스가 없다」는 판단만 틀렸다.**
