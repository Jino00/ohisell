## 1. ref 28이 못 봤던 Pro 기능 — 문서로 밝혀진 실제 메커니즘

### 1-1. 캠페인 생성 (Pro 전용) — ⭐결정적 신규 사실: 스마트스토어 미지원 + 서비스 중단
- **메커니즘**(캠페인 생성 페이지): 네이버 커머스 연동 상품 목록(매출·재고·광고매출 4주 합계 등 커머스 정보 병기, 매일 갱신)에서 상품 선택 → 캠페인명·하루예산(50원~10억, 10원 단위, VAT 별도)·디바이스 선택 → 네이버에 캠페인·애드그룹·소재 자동 생성(상품×디바이스당 {애드그룹-소재} 1쌍) → **MOP 유닛 자동 등록**, 전환값은 '구매완료(직접)' 고정. 생성/검수 상태를 6색 아이콘으로 추적. 수정은 상품 추가·캠페인명·하루예산만(상품 제거·디바이스 변경 불가).
- **⭐그러나 전제인 네이버 커머스 데이터 연동이 ①현재 "서비스 일시 중단"(데이터 연동 페이지 명시) ②재개돼도 "네이버 브랜드스토어에 한하여 사용 가능 — 스마트스토어는 지원 대상에 포함되지 않습니다"(원문 그대로).**
- **시사점**: MOP의 G6는 우리 고객군(스마트스토어)에는 **원천적으로 제공 불가**이고 지금은 브랜드스토어에도 중단 상태. 우리가 G6를 만들면 스마트스토어 셀러에게는 시장 공백을 처음 메우는 것이 된다. 우리는 이미 orders·product_master·BEP를 보유 — MOP이 커머스 API로 가져오는 "매출·재고 기반 상품 선택" 원료를 이미 가진 셈. (단 신규 캠페인 생성은 영구 사람 Confirm — D-NAO-5 불변.)

### 1-2. 커머스 리포트 (Pro 전용)
- **메커니즘**: 스마트스토어 상품 실적(페이지뷰·구매건수·판매수량·총매출·환불 3종·쿠폰할인 2종, 매일 1회) × 쇼핑검색광고 실적(14개 지표, 시간대별 수시)을 상품 단위로 결합. 상품→광고 소재별 드릴다운, 최적화 ID 필터로 최적화 적용/미적용 소재 성과 비교. 직접전환 정의 = "광고 클릭 후 30분 내 구매"(명문화).
- **시사점**: 이것도 커머스 연동(중단·브랜드스토어 한정) 전제. 우리 손익 대시보드(actual_revenue 실주문 대조)는 이미 이 기능의 상위 호환 — ref 28 §3-8 우위가 문서로 **강화**됨(우리는 스마트스토어를 커버하고 MOP은 못 함). "직접전환=30분" 정의는 우리 D-NAO-7 3열 ROAS 해석에 참고 가치.

### 1-3. 예산 민감도 곡선 (Pro 전용, 최근 7일)
- **메커니즘**: Bid Opt 연동 최적화 아이템 대상. 가로축 = 현재 예산 100% 기준선(붉은 점선), 지표별(노출·클릭·전환·매출) 예측 곡선. 해석 규칙 명문화 — 우상향=증액 여력, 기울기 0=임계 도달. [더보기]로 최근 7일 민감도 트렌드 병행 제시.
- **시사점**: 실체 = **"예산 배수 → 지표" 응답곡선**. 우리 X2 T1 `response_curve_builder`(입찰배수 α → 비용·매출 곡선)와 수학적 동족이다. **G8은 X2 완료 후 그 부산물(곡선의 시각화)로 재분류 가능** — 별도 스프린트 원가가 크게 줄었다(§4·§5 권고).

### 1-4. 경쟁 심화도 (Pro 전용) — DEA의 실체
- **메커니즘**: ①CPC 효율성 지수 = DEA(자료포락분석) 0~1 상대효율. 구성 요소 서술: "실제 발생 CPC, 이전 기간 대비 운영 순위 달성 비용, 이전 기간 대비 성과 변화 등을 지수화"(계산식은 비공개). ②경쟁 현황 탐지 = CPC 효율성×CTR의 변화폭 큰 구간을 'High'(경쟁 치열, 주황)/'Low'(완화, 초록)로 구간화, 구간 클릭 시 지속기간+저효율 TOP3 키워드/소재 제시. ③CSV 다운로드. ④개선 액션 연결: 쇼핑=제외키워드 설정, 검색=순위 하향(캠페인 OFF는 매체에서 직접).
- **DEA는 MOP의 범용 엔진**: 같은 DEA가 3곳에 재사용됨 — 키워드 효율성(쇼핑 제외키워드 추천), CPC 효율성(경쟁 심화도), 소재 효율성(DA/VA). 전부 "최근 2주, 저효율 발굴 특화, 0에 가까울수록 나쁨".
- **시사점**: 신비감 제거 — 상대효율 랭킹으로 저효율 아이템을 찾는 진단 도구이지 입찰 산식이 아니다. 우리 진단보드(출혈·굶는승자 등 손익 절대 기준)와 목적 중복이라는 ref 28 §5 판단을 문서가 **지지**. 후순위 유지 타당.

### 1-5. 고급 설정 6종 — 각각의 규칙 확보
| 기능 | 플랜 | 규칙(문서) | 우리 대응물 |
|---|---|---|---|
| Average CPC/CPA | Lite+ | 아이템 **전체 평균**을 상한으로 운영(개별 키워드는 초과 가능), 당일 예측 기준 | target_ROAS가 상위 개념(우리는 마진 기반 자동 산출) |
| Max CPC | Lite+ | 키워드/소재 **개별** 최대 입찰가 하드캡, 10원 단위 | D-NAO-19 경제성 상한(min 산식)이 자동판 상위 호환 |
| Top Impression Boosting | Lite+ | 1~3위 상순위 노출 증대, **일 예산 초과 가능** | 공격성 다이얼+growth_sweeper |
| Rank Boosting | Lite+ | 성과 유지하며 일 평균 광고비 점진 확대 | growth_sweeper(이익 보장 볼륨 확장) |
| Budget Boosting | Pro | 단계 슬라이더로 단기 공격 입찰, **3일 이상 사용 시 과도 소진 경고** | 캠페인 모드(런칭) — 기간 한정 개념 동일 |
| CPC Rebooting | Pro | **1주일 재학습 탐색 부스트, 자동 종료.** Avg CPC/CPA와 동시 사용 불가(Max CPC는 가능). 용도: 예산 과다 장기 지속·신규 전략 탐색 | 미보유 — 탐색(exploration) 트리거. X2/X3 설계 참고(ref 28 §2-6 재확인) |
- **시사점**: 6종의 실체 = 목적함수 제약 2종(Avg/Max) + 확장 편향 3종(Boosting류) + 탐색 1종(Reboot). 우리 X1b 가드레일(±15%·쿨다운·스톱로스·BEP 하한)+공격성 다이얼이 같은 문제 공간을 다른 각도(손익 절대 기준)로 커버. **SA는 Basic도 2종 제공**(Avg CPC/CPA·Top Impression Boosting — sa-opt 페이지, SPA Basic은 0종): ref 24 §8 "Basic 고급설정 2종"과 정합, 이제 어떤 2종인지 확정.

### 1-6. 대용량 리포트 CSV (Pro 전용) — 스펙 확보
- 캠페인 또는 최적화 아이템 기준, 최대 90일(**시간 단위 또는 서치키워드 단위 선택 시 30일로 축소**), 하루 3회 생성 제한(시도 기준), 생성 후 7일 다운로드 만료, 대용량은 CSV 분할. GA4 연동 시 매체 데이터에 외부 전환툴 데이터를 키워드 단위까지 매핑 통합. 과거 데이터는 연동일 기준 직전 60일까지만.
- **시사점**: 우리는 DB를 직접 소유(180일 백필 완료)라 같은 기능이 export 버튼 하나 — §8 CSV export 추가 후보의 "저비용" 판단을 문서 스펙이 뒷받침. MOP의 90/30일·3회/일 제약이 우리에겐 없음.

### 1-7. 기여도 (Attribution)
- **메커니즘**: "Last Click 기준이 아님"(모델명 비공개), 최근 6개월 lookback, 전일자 기준. 목표 구분(구매/구매 외/전체), 채널별·매체별 비중 + **애드그룹 단위까지** 상세, CSV 다운로드. **전제 = 전환툴(GA4·에어브릿지·앱스플라이어) 연동 + UTM 규칙 등록**("연동된 성과 분석 툴 기반"). Budget Opt에 "기여도 반영 옵션"(GA4·에어브릿지 연동 시만) 존재.
- **플랜 게이팅**: 기여도 페이지 자체엔 플랜표 없음 — 단 GA4 연동이 Lite+ 전용이므로 사실상 Basic 배제(문서에서 직접 확인 안 됨 라벨).
- **시사점**: 기여도 페이지의 존재는 시장 수요 신호지만, **문서가 확인해준 전제(전환툴+UTM+다매체)가 전부 우리 스코프 밖**이다(네이버 단일 매체→스마트스토어 단일 랜딩, UTM 미사용). 우리에게 non-last-click이 의미를 가지려면 크로스미디어(G9, 쿠팡 교차)가 선행돼야 함 → **G7 후순위 유지를 문서가 오히려 강하게 지지**(§4).

### 1-8. 목표입찰 (Target Bidding) — 조정 규칙의 실체
- **메커니즘**: 쇼핑검색 소재 단위. 소재ID+입찰 기준 키워드 1개(또는 ALL=통합 실적) 지정, 목표 = Avg.Rank/ROAS/CPA 중 1택. **조정 규칙 = "설정 목표 vs 최근 7일 평균 실적" 비교 피드백**: Rank는 목표보다 낮으면 증액/높으면 감액, ROAS·CPA는 실적 저조 시 감액/양호 시 증액. 최대 입찰가+변동폭(10원 단위) 설정, 일 단위 실행, 설정 다음날 오후 2시 첫 입찰. Max CPC 도달 시 목표 미달 허용.
- **시사점**: 실체가 **단순 7일-평균 피드백 컨트롤러**로 확인 — 예측 모델이 아니라 규칙 기반이다. 우리 D-NAO-19 산식(경제성 상한×estimate 시뮬 min)+D-NAO-4(7일 평균 비교는 이미 이식)로 **상위 호환 구현이 가능**함이 명확해짐. ref 28의 "G5에 목표입찰 병합" 권고 유지, 신비감 제거로 난이도 하향.

### 1-9. 순위유지 (Rank Target) — 진동 알고리즘 + 실패 모드 문서화
- **메커니즘**: "목표 순위와 한 단계 낮은 순위를 5분 단위로 오가며 비용 효율을 확보"(예: 2위 목표 → 2~3위 진동 — **순위 보장 모듈이 아님을 문서가 자인**). 입찰 주기 5~20분(네이버 서버 상태 따라 조정). 키워드 순위 모니터링 1시간 단위(임의 지역 기준이라 실시간과 다를 수 있음), 경쟁사 모니터링(10위 내 노출 시만, 입찰가는 불가시). 노출 요일/시간 드래그 선택.
- **실패 모드 명문화**: 성별·연령 타겟팅(제외 포함)·'더보기' 지면 제외 시 **순위 데이터 미수집 → Max CPC까지 입찰가 폭주 가능**(문서가 경고). 디바이스 불일치 설정 시에도 동일. 순위유지 키워드는 입찰최적화 대상에서 자동 제외(자기충돌 방지).
- **⭐쇼핑검색 순위 타겟팅은 "서비스 일시 중단"** — 순위유지의 라이브 스코프는 현재 검색광고(파워링크)만.
- **시사점**: G4 구현 시 필요한 설계 재료(진동 폭·주기·상한 포기 규칙·타겟팅 제약·자기충돌 방지)가 문서로 확보돼 **설계 원가가 하락**. 스코프도 명확(검색광고 우선). §4 권고에 반영.

### 1-10. 제외키워드 (Beta, Pro) — ⭐자동 토글 발견 (ref 28 정정 대상)
- **메커니즘**: ①**자동 토글 ON = 알고리즘 추천이 매주 업데이트되어 제외키워드로 자동 등록·운영**(사람 개입 없음) / OFF = 추천 목록 확인 후 수동 등록. ②보수적/공격적 추천 2단(ref 28 §2-4 확정). ③제외이력보기(추가·삭제 이력, 수동/자동 구분) + **복구 버튼 — 단 "가장 최근에 변경된 이력에 한하여"** 롤백. ④키워드별 지난 한 달 실적 병기(주 1회 갱신), DEA 키워드 효율성(최근 2주, 매일 갱신) 근거. ⑤소재 단위 최대 70개, 네이버 즉시 반영.
- **시사점**: MOP도 제외키워드에 한해 "위임 자동실행"을 갖고 있다 — 우리 E2 위임(delegation_gate)과 동일 개념의 시장 선례. 비교하면 우리가 여전히 깊다: 우리=일 단위 파이프라인+Ava 평결 게이트+유형 단위 위임 스위치+전건 change_log+D+7/14 채점 vs MOP=주 1회 자동 등록+최근 1건만 복구. **단 ref 28 §3-4의 "MOP은 수동 등록(추천 리스트 제공 수준)" 서술은 문서와 배치 — 정정 필요**(§4-정정 1).

## 4. 우리 갭 그림 갱신 (ref 28 §3/§4/§5/§8 대비)

### 4-1. ref 28 명시 정정 (문서와 배치되는 서술)

1. **§3-4 "MOP은 Pro 전용+수동 등록(추천 리스트 제공 수준)" → 정정**: MOP Pro 제외키워드는 **자동 토글(주 1회 알고리즘 추천 자동 등록·운영)**과 이력·최근 1건 복구를 제공한다(negative-keyword 페이지). 우리 우위는 유지되나 근거를 재서술해야 정직하다: 우위의 실체 = **주기(일 vs 주)·감사 깊이(전건 change_log+D+7/14 채점 vs 최근 1건 복구)·게이트 구조(Ava 평결+유형 단위 위임 vs 단순 토글)**이지 "자동화 유무"가 아니다.
2. **§3-6 "MOP 이상감지는 설정오류(품절/URL/UTM) 계열만" → 정밀화**: 이상감지 '알림 기능'은 설정오류 계열이 맞으나, **대시보드 Smart Insight가 "광고 노출 변동·광고 효율성 변동 감지"를 표방**(대시보드 이해하기)하고 경쟁 심화도 High/Low가 효율 변화 구간을 탐지한다(competition). 메커니즘·임계값 미기술이라 깊이는 불명 — "성과 변동 감지가 전혀 없다"는 단정은 과했다. 우리 우위의 실체 = 급증/급감 임계+절대액 floor+매시 가동+**제안 생성으로 연결**되는 파이프라인(MOP은 표시/메일까지).
3. **§3-2 "입찰 이력/로그 화면 자체가 없음" → 스코프 한정**: **입찰(bid) 변경 이력 미노출은 문서로도 재확인**(최적화 리포트에 성과 지표만 — ref 24 §10-1 유지). 단 **제외키워드에는 이력 화면+복구가 존재**하므로 "이력 화면 자체가 없음"은 "입찰 변경 이력이 없음"으로 좁혀 써야 한다.
4. **§2-2 목표입찰 스펙 보강+MOP 문서 내부 불일치 발견**: Basic 1/Lite 20까지는 일치. Pro 한도는 목표입찰 페이지=50 vs 구독 페이지=제한없음으로 **MOP 문서끼리 모순**. 순위유지 Pro도 동일(순위유지 페이지=50 vs 구독 페이지=20). 우리 문서에는 "50(또는 무제한) — MOP 문서 불일치"로 기록.
5. **ref 24 §3 "ML모델 40개=유닛/캠페인급 grain" vs 문서 "광고별 수십~수백개 머신러닝 모델"(spa-opt 알고리즘 설명) — 문서와 라이브 실측이 배치**: 라이브 카운터(40개)는 실측이고 문서 문구는 마케팅 서술일 수 있다. **D-NAO-24의 근거(모델 grain은 키워드가 아님)는 라이브 실측 기반이므로 유지**하되, 문서상 반대 서술이 존재함을 병기(확정 불가 — §6).

### 4-4. §5(의도적 미채택) — 지지/뒤집기

- **URL/UTM 이상감지: 미채택 지지 강화** — 실체가 "20초 지연·HTTP 4종 코드·UTM 규칙 대조"로 확인. 우리 랜딩=스마트스토어(네이버 인프라)·UTM 미사용이라 위험 표면 자체가 없음.
- **품절 감지: 판단 재료 추가** — SPA 이상감지의 실체는 "매체가 보고하는 소재 연동 제한 상태"의 정기 조회+입찰 제외다(자체 재고 크롤링이 아님). 즉 네이버 API의 소재/연동 상태 필드를 읽으면 될 가능성 — G5(소재 grain) 채택 시 부산물로 저비용일 수 있음(API 필드 존재 여부는 **확인 안 됨** — G5 착수 시 실측). Jino 판단 사항 유지.
- **DEA: 미채택 지지** — §1-4. 목적 중복(저효율 발굴은 우리 진단보드가 손익 기준으로 수행) 재확인.
- **다매체: 유지** — Budget Opt 문서도 "매체 예산 자동 변경 미지원(추후 지원 예정)" 재확인. 전략 판단 불변.

## 5. 순서 결론 + 권고 (트랙 기획 변형 아님 — §8 큐 운용 제안, 결정은 Jino)

1. **X1b→X2→X3 순서를 바꿀 근거 없음 — 오히려 문서가 순서를 지지한다.** MOP의 유료 격차 구조 = ①입찰 실행·알고리즘 컨트롤(고급설정) ②당일성(매시간 갱신·시간단위 조정) ③분석 부가 기능(민감도·DEA·기여도·CSV) 순인데, 이것이 우리 X1b(손+가드레일)→X2(당일 플라이트)→§8(분석 부가) 순서와 정확히 정렬된다. 문서 전수 확인으로 새 필수 선행물은 발견되지 않았다.
2. **§8 검토 시점에 반영할 우선순위 신호 갱신**:
   - **G4 순위유지: 상향 유지+강화** — Basic부터 제공(기본기) + 이번에 설계 재료(진동 규칙·주기·실패모드) 확보로 원가 하락. 스코프는 검색광고 우선(쇼핑은 MOP도 중단).
   - **G5(소재 grain)+목표입찰 병합: 유지** — 컨트롤러 실체가 단순함이 확인돼 D-NAO-19 산식의 상위 호환 구현 가능. 품절(소재 연동 제한) 감지를 G5 부산물 후보로 함께 검토.
   - **G6 캠페인 생성: 근거 업데이트** — "MOP Pro 유료 = 가치 입증"에 **"스마트스토어는 MOP이 원천 미지원+커머스 연동 중단 = 시장 공백"**을 추가. 순위 자체는 Jino 결정(영구 Confirm 제약 불변).
   - **G7 기여도: 하향 지지** — 전제 조건(전환툴+UTM+다매체)이 전부 우리 스코프 밖임이 문서로 확정. G9(크로스미디어) 선행 없이는 실익 없음.
   - **G8 예산 민감도 곡선: "X2 부산물"로 재분류 권고** — response_curve_builder 완성 후 곡선 시각화만 추가하는 형태로 §8에서 재평가.
   - **CSV export: 신규 추가 유지**(ref 28 권고 2 그대로) — MOP 스펙(90/30일·일 3회 제한) 대비 우리는 무제약 저비용.
   - **신규 소항목 후보 2건(저비용)**: ⓐ change_log 기반 **"원복(undo)" 버튼**(MOP 복구 기능의 상위 호환 — 우리는 before/after 전건 보유라 최근 1건 제한 불필요. 단 X1b 가드레일·쿨다운과 상호작용 설계 필요) ⓑ 콘솔 엔진 카드에 **정량 카운터 추가**(계획 수립률·변경 필요 키워드 비율 등, §3 대시보드 항목 차용).
3. **D-NAO-13 재확인**: MOP FAQ가 "기존 입찰 솔루션 전부 중지" 요구를 명문화 — 카나리 전환 시 해당 캠페인의 MOP 유닛 종료 상태 확인 절차(이미 실측 완료: 전부 bidYn=N)의 근거가 문서로도 보강됨.
4. **운영 체크 1건**: Master Report 90개 쿼터와 우리 stat-report 생성의 관계는 확인 안 됨(§3 부수 발견) — MOP 병행 시나리오가 생기면 실측.

## 6. 정직한 잔여 미확인 목록 (추정 금지 — 전부 "문서에서 확인 안 됨")

**알고리즘 내부 (문서에도 없음)**:
- ML 예측 모델의 종류·피처·"광고별 수십~수백개"의 실체(라이브 카운터 40개와의 관계)
- 플래닝 최적화 산식("수많은 경우의 수 계산" 서술뿐 — 키워드당 ~350 경우의 수는 외부 기사(ref 25) 출처이지 공식 문서 아님)
- 예산 민감도 곡선 계산식, DEA의 투입·산출 변수 정의, 기여도 모델명("Last Click 아님"까지만)
- **"실시간 입찰가 보정"** — 전 플랜 제공 항목인데 정의가 어디에도 없음
- Smart Insight의 탐지 로직·임계값
- Flight의 시간 그룹(time group) 산정 방식
- TURBO/SPRINT 기능 플래그의 의미(ref 25 부록 A — 여전히 미상)

**문서 내부 불일치 (진실 미확정)**:
- 순위유지 Pro 한도: 20(구독 페이지) vs 50(순위유지 페이지)
- 목표입찰 Pro 한도: 제한없음(구독 페이지) vs 50(목표입찰 페이지)
- 제외키워드 페이지의 플랜표 라벨이 "캠페인 생성 기능"으로 오기(내용상 제외키워드 게이팅으로 추정되나 원문이 오염)
- 학습 주기: 애드써클 페이지 "매주 ML 학습" vs 에러 가이드 "Basic=2주, Pro=매주"

**문서-라이브 배치 (원칙 22 — 라이브가 진실일 개연성이 높으나 미확정)**:
- 이상감지 플랜 게이팅: 문서=Basic/Lite 하루 1회 제공 vs 라이브 Basic 계정=잠금 모달("Lite 플랜 알아보기")
- ML 모델 grain: 문서 "광고별 수십~수백" vs 라이브 카운터 40

**라이브 검증 자체가 불가한 것 (Pro 계정 미보유)**:
- Pro 전용 기능 전부의 실동작(민감도 곡선의 실제 형태, DEA 지수의 실제 분포, CPC Reboot의 실제 거동, 시간단위 조정의 실제 주기 등) — 이 문서의 §1 전체는 **문서 서술 수준의 확보**이지 실측이 아니다
- 서비스 중단 2건(네이버 커머스 연동·쇼핑 순위 타겟팅)의 재개 시점
