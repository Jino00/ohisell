## 3. 파서가 실무 양식을 견딘다 — 다만 두 번 고쳐야 했다

13개월 Drive 파일 30건 + 메일 14건을 돌리며 **양식 변종 4가지**가 드러났고 전부 고쳤다:

1. **열이 한 칸씩 밀린다** — 8/18 건 `D=품명·E=수량` / `SO-WSOH-114` 건 `C=품명·D=수량`. 초판은 열을 하드코딩해 **예외 없이** 품명 자리에 수량을, 수량 자리에 단가를 실었다. ⇒ 열을 **헤더 텍스트로** 찾는다.
2. **헤더 라벨 자체가 어긋난다** — 어떤 파일은 `Item` 라벨이 C인데 품목명은 D이고 C엔 분류어(`screen protector`)만 첫 행에 있다. ⇒ **헤더 라벨은 «힌트», 판정은 «데이터»가 한다**(`_resolve_item_col`).
3. **시트명이 `CI (2)`** — 엑셀 시트 복제 접미사. ⇒ 정확 일치 → 접두 일치 순으로 고른다.
4. **CI와 PL이 별도 파일** — `POST /parse`가 `pl_file`을 따로 받는다.

★그리고 **CI·PL에도 자기검산**(라인 합 == 총계 행)을 넣었다. 통관경비서엔 있었고 CI·PL엔 없어서 ①이 조용히 통과했다. **자기검산이 없는 파서는 «값이 있는데 틀린 것»을 만든다.**

## 7. Fable의 종합 판단 (2026-08-22, Jino가 직접 지목)

- **정본은 로트 실적**, 표준원가는 **견적 도구로 강등**. 단 표준원가의 계수는 사람이 아니라 **원장이 자동 갱신**한다. ⇒ 「CNY만 고정, 나머지는 업데이트」는 맞되 **업데이트의 주체가 사람과 엑셀이 아니라 원장**이어야 한다.
- **ⓐ(계수 갱신)는 수렴 불가** — 물류비율이 3배 차인데 어떤 «최근값»도 다음 로트에서 틀린다.
- **ⓑ(실적 단독)도 불가** — 로트 도착 전엔 실적이 없고, `cost_price`가 스칼라라 로트별 값을 직접 못 꽂는다. **로트→스칼라 변환 규칙(재고 평가층)이 반드시 사이에 있어야 한다.**
- **생산자는 하나여야 한다** — 통관 서류를 두 곳이 각자 파싱하면 같은 서류에서 다른 숫자가 나온다.
- **A′(엑셀 원가표 시스템화)의 전제 절반이 반증됐다** — D-CPP-31 초안의 「부자재 구성 × **공통 입력**」에서 «구성»은 유효하나 «공통 입력»은 공통이 아니라 **로트별**이었다.
- 제안 순서: **B → 층3-lite((a) 계열 한정 평가 규칙) → A′(구성) → C 나머지**.
- D-CPP-31 미해결 질문에도 부분 답: **구성(부자재 목록·수량)은 파싱 인정 가능, 단가·계수는 인정 불가**(실측과 어긋남이 확인됨).
