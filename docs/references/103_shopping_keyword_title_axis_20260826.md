## §5. ★광고 제목 — 쇼핑엔 없고, 파워링크엔 있는데 안 읽는다

### 쇼핑
소재 타입 `SHOPPING_PRODUCT_AD`. `referenceData.mallProductId`만 담는다 ⇒ **별도 광고 제목 칸이 없고 상품명이 곧 광고 제목**이다.
⚠️ `get_ads`의 `product_name`은 docstring이 자백하듯 *"확정 필드가 아니라 여러 후보 키를 시도하고 없으면 빈 문자열"* — **광고에 실제로 뜨는 제목을 우리가 확실히 읽고 있지 않다.**

### 파워링크
제목·설명·URL을 **우리가 직접 쓴다**(상품명과 무관).
★**그런데 수집하지 않는다** — `naver_sa_ad_fetcher.get_ads`가 *"mall_product_id가 있는 소재만 — 쇼핑 상품 소재가 아니거나 referenceData에 상품번호가 없으면 제외"*라 **파워링크 소재는 통째로 걸러진다.** 우리 DB에 파워링크 광고 제목 **0행**.
⇒ 같은 API 응답에 이미 실려 오므로 **추가 호출 0으로 읽을 수 있다**(D-NAO-127의 `editTm`·D-NAO-137의 `APPLY_TM`이 그렇게 추가된 전례).

### ★위험도가 다르다 (이게 실무적으로 제일 중요하다)

| | 상품명(=쇼핑 광고 제목) | 파워링크 광고 제목 |
|---|---|---|
| 파급면 | 광고 **+ 자연 검색 + 상품 정체성 + 리뷰** | **광고만** |
| 되돌리기 | 문자열은 복원되나 **순위·매칭 상태 복원 보장 없음**, 지연 [미상] | **즉시·완전** |

⇒ **파워링크 광고 제목이 «안전한 실험장»이다.** 제목이 성과를 바꾸는지 여기서 먼저 배우고 그 지식을 상품명으로 옮기는 순서가 성립한다. 그리고 파워링크엔 키워드도 있어 **제목과 키워드를 함께 만질 수 있는 유일한 자리**다.

## §9. Fable 구조 판정 (요지 — 원문은 세션 트랜스크립트)

- **판정: 반쪽 소관.** «어떤 단어가 돈이 되는가»의 지식(L1)·판정(L2)은 PAO 소관, **쓰기는 상품 축**. ⇒ **PAO는 지식과 제안서까지, 편집 실행은 PAO 밖.**
- **「쇼핑에서 존재하는 유일한 액셀이 제목·태그다」** — 현재 쇼핑 레버 셋 중 «어떤 검색어에 들어갈 것인가»를 정하는 액셀이 하나도 없다(제외=브레이크, 입찰=볼륨 다이얼). 승격 지혜 2건이 둘 다 브레이크인 구조적 이유.
- 검색어 97.4%가 토큰 1개라 개별 grain 판정 불가인데 **제목·태그는 정확히 토큰/의미 단위 grain에서 작동** ⇒ 새 판정 체계가 아니라 **의미 단위 사슬의 두 번째 소비처**(첫째는 제외).
- **제목·태그 변경 = 「되돌릴 수 없는 액션에 준하여」 취급.** 위험 서열 **태그 < 제목**.
- 권고 순서: **①스냅샷 동결 + 커버리지 인구조사**(시간 민감 — 누가 콘솔에서 만지는 순간 원복 좌표 소멸) ②단어→이익 재고 조사(C 라벨 필수) ③**태그만·한 기종 패밀리만** 파일럿, 짝 상품 무개입 대조.
- **기각**: 커머스 쓰기 API 구축 · **249종 일괄 정비**(현재 상태를 만든 병의 재연) · SERP 차단 우회 · 제목 최적화의 PAO 편입.
