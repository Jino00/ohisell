## 3. 한 문장 안의 두 요구는 «막힘»이 다르다 — 이 슬라이스 설계의 전부

```
① 파생 현재고 = 초기 실사 + 픽업 입고 − 판매      ← 「판매」에서 막힌다 (§1)
② 실사 표본 10 SKU 대조 오차                      ← ★막히지 않는다
```

②가 안 막히는 이유는 단순하다 — **ECOUNT가 말한 재고 ↔ 사람이 센 재고**의 차이라서 **판매 축을 타지 않는다.**

그리고 계약이 이미 ②를 S5의 문턱으로 지목해 뒀다(§2-7C ④):

> *"ECOUNT 오차의 크기는 §4 S4의 「실사 표본 10 SKU 대조」가 잰다. **그전까지 재고 기반 문턱을 추천에 싣지 않는다.**"*

⇒ ①은 `derived_quantity=None`(「산출 불가」)으로 **자백**하고, ②는 **끝까지 세웠다.** Jino가 10개를 세면 코드 수정 없이 그 자리에 오차가 뜬다(S2의 `payments=` 손잡이와 같은 모양).

## 4. 창고 5개는 합치면 안 된다 — 그래서 행 키에 넣었다

계약 §1의 Jino 진술 표가 정본이고 **데이터엔 안 적혀 있다**:

| 창고 | 역할 | 발주식에서 |
|---|---|---|
| 본사 | `own` | ★**차감항의 본체** — 파생 현재고의 유일한 기준 |
| 본사-포장 | `material` | 부자재(cleaning kit) — 강화유리 발주와 별개 |
| 쿠팡 제트배송 (`WH_CD 00020`) | `channel` | 판매 가능하나 **우리 창고가 아니다**. 정합성 미검증 |
| 반품창고 | `excluded` | 미사용 |
| 아마존 | `excluded` | 미사용 |

표에 없는 이름은 **`unknown`으로 갈라 자백**한다 — `own`으로 접으면 없던 재고가 생기고 `excluded`로 접으면 재고가 사라진다.

⚠️ `WH_CD` 코드는 **제트배송 `00020` 하나만** 문서에 남아 있다(ref 98 §8). 나머지 4개는 **[미상]**이라 역할 판정을 **이름**으로 건다.
