### 판정

1. **올리는 데는 4개 요건**(clk≥10 / conv≥2 / 캠페인 clk≥30 / 성적표 신선도), **내리는 데는 2개**(est_ROAS<BEP + 당일소진≥하루평균)이고 **표본 하한이 없다.**
2. ★★**전환이 0이면 `est_ROAS = 0 < BEP`가 자동 성립한다.** 즉 **「전환이 없다」는 사실이 내리는 쪽에서는 «트리거»이고, 같은 사실이 올리는 쪽에서는 «판단 보류»**다. **노출이 적어 표본이 없는 대상은 내려갈 수는 있어도 올라올 수 없다.** 07-29 실패 5건이 정확히 그 모양이었다(`추정ROAS 0.81 < BEP 1.9611`).
3. **표본 미달의 결과는 「그대로 둠」이 아니라 「올려줄 기회를 못 받음」**이다.
4. 다만 **나선은 무한이 아니라 바닥에서 멈춘다** — 시간당 레인의 `imp ≥ 30` 게이트가 **양방향 hold**라 노출이 마르면 하향도 멈춘다. 지금 이 소재가 그 상태로 보인다(233 imp/일에 제안 0건) 🧠.

## §7. 부수 정리 — 캠페인 ID 두 개는 어긋난 것이 아니다

앞선 조사에서 `optimizer='ours'` 캠페인(`…8425541`)과 `auto_operator.py::AD_BID_CANARY_CAMPAIGNS`(`…10769985`)가 달라 보였으나, **의미가 뒤집힌 상수**였다:

- `AD_BID_ROUTING_ENABLED = True` ⇒ `_ad_bid_canary()`가 **전 캠페인 True** 반환. 제안 «생성»은 이 상수를 더 이상 안 본다(D-NAO-125 📄).
- 지금 실제 사용처는 **두 곳뿐이고 둘 다 «제외» 방향** — `delegation_gate.py`(위임 자동승인에서 제외) · `expert_briefing_builder.py`(브리핑에서 제외).
- ⇒ **켜진 캠페인이 그 목록에 «없는» 것이 정상**이다. 있었다면 그 캠페인 전체가 Confirm-only가 되어 자동 실행이 죽는다. 코드 주석이 이 반전을 명시: *"한 이름으로 정반대 두 의미를 겸하고 있었다"*.
- 남은 `…10769985`는 캠페인이 **off**라 사실상 사문이다. 🧠 **이름이 현재 의미와 반대로 읽히는 것**이 혼란의 원인.
