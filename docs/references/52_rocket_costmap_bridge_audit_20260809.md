## 0. 왜 했나

원가 링크 172건이 `match_method='suggested'` — **상품 이름이 비슷하다는 이유로** 붙은 것이다.
D-CPP-25가 «값 층»(원가가 얼마)과 «링크 층»(그 원가가 이 상품 것인가)을 분리하면서
★**원가표가 정확해질수록 잘못된 링크의 오차는 커진다**는 것을 확인했고, 링크 전수 판정은
그때 이월됐다.

## 1. 방법 — 렌즈 둘, 축 여섯, 판정 여섯

**렌즈 ①결정적 브리지**: `coupang_rocket_sales_daily.option_id` →
`product_channel_mapping(channel_id=5)` → `product_master`.
이 매핑은 쿠팡이 주는 `externalVendorSku`가 `internal_sku`와 **정확일치**할 때만 생성된다
(`product_sync.py:_maybe_upsert_mapping`) — 이름 유사도가 아니라 코드 일치다.

**렌즈 ②제품 성격**: 쿠팡 상품명과 내부 상품명을 축별로 대조.

| 축 | 종류 | 값 | 비고 |
|---|---|---|---|
| `part` 부위 | hard | doorlock/case/lens/back/screen | ★**렌즈 vs 액정**이 지난 감사가 놓친 축 |
| `count` 매수 | hard | 정수 | 「1세트」의 1은 매수가 아니다 |
| `material` 소재 | hard | pet/tempered/tpu | ★**「유리코팅」을 강화유리보다 먼저** 본다(PET이다) |
| `privacy` 사생활 | hard | True/False/None | ★**유일한 판별자.** 무광·매트·저반사·지문방지는 같은 기능의 다른 표현이라 축이 아니다 |
| `magsafe` | hard | True/False/None | 「맥세이프 유/무」 |
| `model` 기종 | soft | 집합 | 「삼성 갤럭시 S25울트라」=「갤럭시S25울트라」 |

**둘 다 값이 있고 다를 때만** 충돌이다. 한쪽이 없으면 «모름»이지 «다름»이 아니다.

**판정**: `replace`(현재만 충돌) / `keep`(브리지만 충돌) / `label_only`(hard 전부 일치, 기종만 다름) /
`agree` / `undetermined:*`(브리지 없음·브리지 둘·이름 없음·둘 다 무충돌·둘 다 충돌).

## 4. 판정기가 실제로 잡은 자기 결함 (이 감사에서 고친 것)

1. **매수 정규식이 기종을 매수로 읽었다** — `(\d+)\s*(매|p|P|…)`가 「아이폰17 **P**ro」를 매수 17로,
   「S26 **P**lus」를 26으로 잡았다. `p`/`P` 뒤에 영문자가 오면 단위가 아니도록 고쳤다.
   ★거짓 충돌 축은 판정을 통째로 흔든다.
2. **`privacy`가 이름 없음을 False로 승격시켰다** — False는 「사생활 제품이 아니다」라는 주장이고
   None은 「모른다」인데, 이름 없는 후보에 False를 주면 없는 충돌이 생긴다. 3값 원칙 위반이라 고쳤다.
3. **요약 표가 새 판정값을 조용히 삼켰다** — `lens_tie`를 둘로 쪼갰더니 고정 순서 목록에 없는
   두 값 61건이 표에서 사라져 **합계가 172가 아니라 111로 보였다.** 표 어디에도 「빠졌다」는
   표시가 없었다. 데이터에 있는 값은 목록에 없어도 뒤에 붙이도록 바꾸고 **합계 행**을 넣었다
   — 잘림이 스스로 신고하게 만든 것이다(교훈 #175와 같은 형태).
