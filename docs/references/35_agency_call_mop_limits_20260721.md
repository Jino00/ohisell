# 35 — 대행사(아인스미디어 최현준 팀장) 통화: MOP 실체·한계 증언 (2026-07-21)

> 선행: ref 34(2026-07-20 대행사 쇼검·파워링크 플레이북). 이 문서는 대행사가 **경쟁사 MOP 운영을 관찰한 증언** = MOP 내부 동작·한계의 3자 검증.

## 1. 통화 맥락
- 경쟁사 3월 월 1.5억 매출 → 오하이 목표=그 이상. 신규 상품 출시 대응 약점 개선 논의.
- 그 경쟁사가 최근 2~3개월 MOP 사용 중 → 팀장이 MOP 실체·한계 설명이 통화 핵심.
- 경쟁사 MOP 성과: 30~40일 돌린 뒤 ROAS ~220%(매출 500 규모).

## 2. 팀장이 파악한 MOP 실체 = "CPC 조절기"
- MOP가 하는 일 = **입찰가(CPC) 조절뿐**. 노출 키워드 교체·소재 생성 아님. 정해진 키워드/소재 입찰을 5~10분 단위로 움직임.
- 입찰은 실시간이나 **판단 근거 = 과거 30/14/7일 데이터**. "미래 예측 아니라 과거 수익률 추종."
- (우리 D-NAO-4 "MOP도 최근 7일 평균 비교" 실측과 일치 = 교차검증.)

## 3. 팀장이 꼽은 MOP 단점 (핵심)
1. **반영 느림(최강조)**: LG CNS 내부 알고리즘이 7~30일 러프 평균 데이터 사용. **"어제 수정이 마음에 안 들어도 MOP 반영은 7~30일 기다려야."** 데일리 반영 사실상 불가. 평균값 추종이라 즉각 대응 안 됨.
2. **수렴 오래**: 원하는 수익률까지 5~6개월. 대행사 직접 운영 시 2~3달로도 목표 도달 케이스 적었음.
3. **"페이지" 개념 없음**: 순위 3등↔4등에서 검색결과 페이지가 넘어가며 노출·유입 급변하는 걸 계산 못 함. 노출량·수익률 숫자만 봄. "3등 안 고정" 같은 순위 목표 개념 부재.

## 4. 사람 손 vs MOP — 팀장 결론
- 사람 관리 방식(팀장 원문 취지): **"2순위 ROAS 나쁘면 3순위로 내리고, 3순위 ROAS 좋으면 2순위로 올리고 — 이 반복."** 즉각적, 페이지 전환 인지해 안전 순위로 즉시 수정.
- 결론: **사람 손이 MOP보다 빠르고 즉각적.**
- ★우리 관점: 팀장이 "사람 강점"으로 든 순위 조절 반복 = 우리가 **IU-R 순위 서보 + 이익 스팟 밴드로 자동화한 바로 그 로직**. 우리 = 사람의 즉각성 + 자동화의 24시간 지속.

## 5. 요금/버전
- 1년 1천만 원 멤버십. 프로/라이트 기능 차이 작고 **캠페인 개수 한도가 주 차이**. 캠페인 많으면 프로 필요.

## 6. MOP 약점 ↔ 우리 구현 대조
| 팀장 증언 MOP 약점 | 우리 구현 |
|---|---|
| 7~30일 지연·데일리 반영 불가 | 시간당 레인 + 2h 사이클(탐색 래더 포함) |
| 평균 추종·즉각 대응 불가 | 빠른 루프(시간)/느린 루프(학습) 분리 = D-NAO-4 |
| 2↔3순위 ROAS 왔다갔다(=사람 강점) | 순위 서보 IU-R + 이익 스팟 밴드(자동화) |
| **페이지 경계 비선형(3→4등 페이지 넘어감) 계산 못함** | **미구현 — 신규 통찰(§7)** |

## 7. ★신규 통찰 — 페이지 경계 비선형성 (D-NAO-74 백로그)
팀장: "순위 3등→4등이면 검색 페이지가 넘어가 노출·유입 급변." 우리 `bid_rank_curve`는 입찰→순위 반응을 **선형 기울기**로 다뤄 **페이지 경계(1p↔2p, 대략 순위 ~10 경계 + 노출 슬롯 배치)의 비선형 점프를 명시적으로 안 다룸**. MOP가 못 하는 이 지점을 잡으면 차별점. 후보: 순위 서보에 "페이지 경계 인지" 항 — 경계 근처에서 스텝을 크게(경계 넘기) 또는 보수적으로(경계 안 지키기). 실측 필요: 네이버 쇼핑검색 페이지당 노출 슬롯 수·순위→페이지 매핑, 페이지 전환 시 실제 클릭/노출 급변폭. (선행 IU-R·B-X·SS 이후.)
