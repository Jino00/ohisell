## 4. G2 화이트리스트 — 결정적 재측정 (초판 표를 폐기하고 다시 쟀다)

`_build_whitelist`(`search_term_judge.py:85-105`)는 `naver_product_bep`(has_cost) 상품명을 `[^0-9A-Za-z가-힣]+`로 쪼개 **길이≥2·비숫자 토큰을 전부** 보호 대상에 넣는다. 총 **378토큰 중 372개가 상품명 파생**이다(재현 확인).

### 4-0. ⚠️초판 표는 재현 불가였다 — 완료 QA가 잡았고, 지표를 바꿔 다시 쟀다

초판의 「토큰별 탈락 행수」는 시뮬레이터가 `for tok in tokens: if tok in normalized: return tok`로 **첫 매치 하나만** 귀속시켜 얻은 값이었다. `tokens`가 `set`이라 순회 순서가 프로세스 해시 시드에 좌우돼 **재실행하면 순위가 바뀐다**(완료 QA가 재실행으로 실증: 「필름 13,223」이 「보호필름 25,690」으로 뒤바뀜).
★**프로덕션 판정은 결정적이다** — 실코드 `_is_whitelisted`는 `any(...)`로 **bool만** 돌려주므로 통과/탈락은 흔들리지 않는다(G2 총계 100,163은 재실행에서 정확히 재현됐다). 비결정성은 **측정 도구가 「어느 토큰 탓인가」를 알아내려 넣은 승자독식 귀속**에서만 생겼다.
→ 귀속을 **두 개의 결정적 지표**로 대체했다(`whitelist_token_coverage.py`, 토큰을 `sorted()`로 순회):
- **`covers`** = 그 토큰을 포함하는 G1 생존 행수(토큰 간 중복 허용 → 합계 ≠ 총계)
- **`sole_blame`** = 그 토큰이 **유일한** 매치인 행수 = **그 토큰만 빼면 G2에서 풀리는 행수** ← 정책 재심의 실제 의사결정 수치

## 7. 미상 / 판정불능

1. **「개별 검색어 × 14일」 grain이 제외 판정 목적에 적절한 설계인가** — 설계 판단은 이 진단의 범위 밖(경계 지시).
2. **G2 과보호가 의도인가 미튜닝 부작용인가** — 코드 주석은 오컷 방지를 말하지만 일반 명사 보호까지 의도했는지는 문서 부재.
3. `naver_adgroup_product`의 누적 upsert(삭제 없음, `models.py:2312-2323`) stale 위험이 margin 계산에 섞였을 가능성 — 배제 못 했으나 **G4가 병목이 아니므로 결론에 영향 없음**.
4. `kst_now()`가 SQL의 하드코딩 `2026-08-17`과 같은 날짜를 반환하는지 코드 실행으로 직접 확인하지 않음(서버 UTC 14:44 → KST 23:44로 **간접 확인**).
