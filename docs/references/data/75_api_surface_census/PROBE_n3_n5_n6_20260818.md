## 0. 조사 방법·경계 준수 선언

PAO(`optimizer`/`auto_operate`) 상태는 건드리지 않았다(읽지도 않음 — 이번 조사 범위 밖).
- **쓴 콜 수**: 총 **190 GET 호출**(전부 200 OK, 4xx/5xx 없음). 내역:
  - 인증 sanity 체크 `GET /ncc/campaigns` × 1

  - 합계 1+32+8+87+2+60 = **190**

### grain 판정 + 근거

**광고그룹(adgroup) 단위 — 직접 도달, 변환 불필요.** 응답의 `ownerId` 필드가 곧 `nccAdgroupId`이고, 형식이 `band_group_total.csv`의 `adgroup_id`(`grp-a001-01-000000031116306` 꼴)와 **완전히 동일한 문자열 형식**이다(별도 ID 매핑 테이블 불필요). 이 계정에서는 campaignTp/ad 레벨 owner가 실측 0건이라 — 최소 이 계정에서는 — AdExtension이 사실상 100% adgroup-scoped다.

### 3값 처분

**개통** — 등급에 닿고 수집 가능. 선행조건: 계정 전체 확장소재를 얻으려면 `/ncc/ad-extensions?ownerId=` 를 **광고그룹마다 1콜씩** 호출해야 한다(계정 전체 일괄 리스트 endpoint 없음 — Criterion GET과 같은 모양). 예상 콜 수: 매트릭스가 다루는 482그룹 기준 **482콜**, 계정 전체(1,013그룹) 기준 **1,013콜**. `GET /ncc/inspect-history/{adExtensionId}`로 심사 코멘트까지 확장하려면 소재 건수만큼(확대 스캔 기준 광고그룹당 평균 6.3건 → 482그룹×6.3 ≈ 3,000콜) 추가 필요 — 단 N6 결과(§3)상 이 경로는 현재 코멘트를 못 얻는다.

### 매트릭스 #19 B1 서술 진위

**"주요 유형 API 생성 불가"는 이번 조사로 확정도 반박도 못 한다 — 단, 이 주장이 등급교차의 실제 장애물이 아님은 확인했다.** B1의 주장은 **생성(POST)**에 관한 것인데, 이번 프로브는 경계상 POST를 쓸 수 없어 생성 가능 여부를 직접 검증하지 못했다. 그러나 확인된 사실 3가지가 그 주장과 긴장 관계에 있다: ①Swagger에 CRUD 6개(POST/GET/PUT/DELETE 조합)가 실재(census 기존 확인) ②**조회(GET)는 완전히 작동**하고 계정에 이미 5개 타입(`SHOPPING_WEB`·`HEADLINE`·`POWER_LINK_IMAGE`·`DESCRIPTION`·`PRICE_LINKS`)이 실제 데이터로 살아있다(40개 광고그룹에서 253건 이상 확인) ③**grain이 광고그룹에 정확히·변환 없이 닿는다.** 즉 콘솔로 만들어졌든 API로 만들어졌든, **등급 교차 목적(수집·분석)에는 "생성 가능 여부"가 관건이 아니라 "조회 가능 여부"가 관건**이고 그건 이번에 확실히 "가능"으로 확인됐다. B1의 "생성 불가" 문구는 재검토 대상으로 남긴다(원인·근거 미상).

## 2. N5 — ProductGroup

### 실행한 호출 → 상태코드 → 응답 요약

`GET /ncc/product-groups`(파라미터 없음, 계정 전체 목록) → **200**, count=**3**(계정 전체에 이것뿐):

**교차 확인**: 계정 전체 광고그룹 1,013개(`WEB_SITE` 526 · `SHOPPING` 475 · `SHOPPING_BRAND` 3 · `BRAND_SEARCH` 8 · `BRAND_NEW` 1)의 `/ncc/adgroups` 응답 필드를 SHOPPING 타입 샘플로 직접 확인했으나 **`productGroupId`/`nccProductGroupId` 필드가 존재하지 않는다**(SHOPPING 타입 광고그룹 스키마: `nccAdgroupId·...·adgroupType·autobidStrategy·...` — product group 참조 필드 없음).

### grain 판정 + 근거

**상품군(product-group) 단위이고, 광고그룹으로 이어지는 키가 이 GET에는 없다.** `numberOfAdgroups`는 **개수만** 주고 실제 `nccAdgroupId` 목록은 안 준다. `/ncc/adgroups`(전체 1,013건 확인)에도 역방향 참조 필드가 없다. census §2-2가 지목한 `MasterReport item=ProductGroupRel`(광고그룹↔상품군 관계 전용 리포트)이 유일하게 이 연결을 줄 수 있는 표면으로 보이나, **그 생성 경로가 `POST /master-reports`라 이번 GET-only 경계에서 호출 불가**다.

### 3값 처분

**불가(원리, 이번 경계 안에서)** — grain을 광고그룹으로 못 내리는 GET 경로가 존재하지 않는다(확인함, `/ncc/product-groups` 자체도 `/ncc/adgroups`도 안 줌). 유일한 후보(`ProductGroupRel` MasterReport)는 POST 필요라 이번 조사 범위 밖. 부가로: 설령 연결이 뚫려도 **계정 전체에 상품군에 연결된 광고그룹이 최대 3개뿐**(전체상품 2 + 아이폰필름 1, 강화유리_아이폰13은 0)이라 — 매트릭스가 다루는 규모(482~1,013그룹)에 비하면 **등급 교차 축으로서의 실효성 자체가 낮다.**

## 3. N6 — InspectHistory(검수 이력)

### 실행한 호출 → 상태코드 → 응답 요약

`GET /ncc/inspect-history/{id}` — `id`에 서로 다른 4가지 타입을 넣어 총 **11회** 시도:

| 시도한 id 타입 | 예시 id | 상태코드 | 응답 바디 |
|---|---|---|---|
| `nccAdId`(정상 APPROVED 소재 3건) | `nad-a001-01-000000309838851` 등 | 200 | `{"id":"nad-a001-01-000000309838851"}` |
| `nccAdgroupId`(3건) | `grp-a001-01-000000031185769` 등 | 200 | `{"id":"grp-a001-01-000000031185769"}` |
| `nccAdExtensionId`(정상 APPROVED 4건) | `ext-a001-01-000000335810640` 등 | 200 | `{"id":"ext-a001-01-000000335810640"}` |
| `nccAdExtensionId`(**실제 PENDING/DISAPPROVED 1건**, 253건 표본 중 유일한 비정상) | `ext-a001-01-000000202734441`(type=PRICE_LINKS, `status=PAUSED`, `statusReason=AD_EXTENSION_DISAPPROVED`) | 200 | `{"id":"ext-a001-01-000000202734441"}` |

**전부 200이지만, `id`를 그대로 echo만 할 뿐 `pcInspectComments`/`mobileInspectComments`가 단 한 건도 채워지지 않았다** — 정상(APPROVED) 항목은 물론, 계정 표본(광고그룹 100개의 광고 ≈100건 전부 APPROVED, 광고그룹 40개의 확장소재 253건 중 PENDING 1건)에서 찾은 **유일한 비정상 항목조차** 빈 응답이다. 이 endpoint는 **어떤 문자열 id를 넣어도 404가 아니라 200 + `{"id": <echo>}`를 돌려준다** — 즉 존재하지 않는 id도 구분 못 하는 것처럼 보인다(혹은 코멘트가 없을 때의 정상 축약 표현일 수 있음, 판별 불가).

### grain 판정 + 근거

**판정불능 — 응답 스키마 자체에 광고그룹으로 이어지는 필드가 없다.** `InspectCommentResponse`(Swagger 정의)는 `id`(echo) · `pcInspectComments`(선택) · `mobileInspectComments`(선택) 3필드뿐이고, `nccAdgroupId`류 필드가 원리적으로 없다. grain은 **"무엇을 id로 넣었을 때 코멘트가 실제로 채워지는가"**에 달렸는데, 이번 조사로 그 어떤 id 타입도 코멘트를 못 끌어냈다.

### 3값 처분

**측정했으나 판정불능 — 더 필요한 것: 실제 DENIED 상태 항목의 id.** 근거: ①이 계정 표본(광고 ~100건 전부 APPROVED, 확장소재 253건 중 PENDING 1건뿐)엔 **완전 반려(DENIED)** 항목이 아예 안 걸렸다 — PENDING은 "심사 중"이라 아직 코멘트가 없을 수 있다(DENIED와는 다른 상태). ②유일하게 찾은 비정상 항목(PENDING 확장소재)도 코멘트가 비었으므로, "코멘트가 실리는 id 타입"을 이번 표본으로는 특정 못 한다. ③계정 전체를 더 넓게 뒤지려면(예: 키워드 단위 반려 이력) 광고그룹 1,013개 전수를 스윕해야 하는데 이번 예산 밖이고, 벌크 조회(`POST /ncc/inspect-history`, 배치 id 목록)는 경계상 금지라 더 넓게 탐색할 GET 수단이 없다. **해소 경로**: (a) DENIED 상태 광고/키워드/확장소재를 계정 전수에서 찾아 그 id로 재시도, 또는 (b) POST 배치 조회 승인을 받아 재실행.

## 4. 이번에도 확인 못 한 것

- **N6의 진짜 id 타입** — `nccAdId`·`nccAdgroupId`·`nccAdExtensionId` 4종 다 시도했으나 전부 빈 응답이라, 코멘트가 실제로 채워지는 id 타입(키워드? 소재 개별 검수 이력의 별도 id?)을 특정하지 못했다.
- **N5 ProductGroup↔Adgroup 관계의 정확한 스키마** — `MasterReport item=ProductGroupRel`이 유일한 후보이나 POST 필요라 이번 GET-only 경계에서 호출 자체를 안 했다(응답 스키마조차 못 봄).
- **N3 "생성 불가" 주장의 진위** — POST 자체를 안 써서 생성 가능 여부는 직접 검증 못 했다. 조회(GET)만 검증했다.
- **N6 DENIED 상태 항목 자체** — 이번 표본(광고그룹 100개의 광고, 40개의 확장소재)에 완전 반려 사례가 없었다. 계정 전체(1,013그룹)를 더 넓게 스윕하면 나올 수 있으나 이번 예산 밖.
- **N3 광고그룹 전수(482 또는 1,013개) 스윕은 안 함** — 샘플(광고그룹 최대 100개)만 확인. grain·존재는 확정됐으나 계정 전체 정확한 총량(확장소재 총 건수)은 이번 조사로 안 셈.
