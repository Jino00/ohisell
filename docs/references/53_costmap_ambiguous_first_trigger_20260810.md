## C. 교훈 소재 — 「우연히 맞은 것과 옳게 맞은 것은 다르다」

상세는 `.claude/memory/LESSONS_LEARNED.md` 교훈 #197. 요지:

- 종전 코드 `min(costed, key=lambda x: x[1])`는 `product_master.id`가 작은 쪽을 뽑았는데,
  갤럭시탭 S8·S10FE 두 건은 마침 정답 쪽(`OHI-0061`·`OHI-0075`)이 id가 작아 **우연히 정답을
  냈다.** 반대 순서였으면 조용히 틀렸을 것이고 배너에도 안 잡혔을 것이다.
- 매핑 후보를 찾는 가장 강한 단서 = **형제 옵션이 어느 마스터에 붙어 있나**. 플립8 건은
  형제 6기종(플립7FE·7·6·5·4·3)이 전부 1,645원, 폴드 계열은 2,666원으로 갈려서 즉시 확정됐다.
- 이름 함정: 「고투명」=「맥스 클리어」(같은 표현), 「사생활보호 프라이버시」는 **다른 제품**
  (4,880원) — `film-privacy-vs-antifingerprint`와 같은 계열.

## E. 되돌리는 법

각 매핑ID를 원상태로 되돌리려면:

```
PATCH /api/products/{product_id}/mappings/{mapping_id}
Body: {"is_active": true}   # 비활성화를 되돌릴 때
Body: {"is_active": false}  # 신규 생성한 연결을 끌 때
```

| 매핑ID | product_id | 되돌리는 동작 |
|---|---|---|
| 2324 | `OHI-0756`의 product_id | `is_active: true`로 복원 |
| 2903 | `OHI-0756`의 product_id | `is_active: false`로 비활성화(신규 생성분 되돌림) |
| 2904 | `OHI-0902`의 product_id | `is_active: false`로 비활성화(신규 생성분 되돌림) |
| 302 | `OHI-0062`의 product_id | `is_active: true`로 복원 |
| 348 | `OHI-0076`의 product_id | `is_active: true`로 복원 |

되돌리면 `_relink_after_mapping`이 다시 돌지 않으므로(비활성화만으로는 소급연결이 자동
역행하지 않음), 과거 주문의 원가 귀속을 완전히 원복하려면 반대 방향 매핑을 다시 활성화한
뒤 관련 옵션의 과거 주문을 수동으로 재확인해야 한다. 이 문서 작성 시점 기준으로는 되돌릴
필요가 없다고 판단됨(라이브 검증 §B 통과).
