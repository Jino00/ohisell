### 8-1. ★ 색: 두 축을 분리한다 (인벤토리가 드러낸 진짜 문제)

인벤토리 결과 **서로 모순되는 색 규약 4개가 동시에 살아있다**:

| 위치 | 규약 |
|---|---|
| `NaverOps.tsx:64` `CoupangOps.tsx:44` `profitColor` | 이익 **양수=파랑** / 음수=빨강 |
| `Dashboard.tsx:~115` 인라인 | 이익 **양수=초록**(▲) / 음수=빨강(▼) |
| `Dashboard.tsx:120` `profitRateColor` | 이익률 **구간별** 초록/노랑/빨강 |
| `NaverAdReport.tsx:61` `mopDelta` | **증가=빨강 / 감소=파랑** (주석: *"MOP 관례: 증가=▲빨강 / 감소=▼파랑"*, 비용 지표는 invert) |

**이건 "누가 틀렸나"가 아니다. 서로 다른 두 가지를 같은 색으로 칠하려다 충돌한 것이다.**

- **방향(direction)**: 숫자가 올랐나 내렸나. **가치판단 없음.** 한국 증시·MOP 관례 = 상승 빨강 / 하락 파랑.
- **판단(judgment)**: 그게 좋은가 나쁜가. ROAS가 BEP 위인가 아래인가, 적자인가.

**노출이 +28% 올랐다**는 방향이고, **그게 좋은지는 별개**다(비용이 같이 올랐으면 나쁨). 한 색으로 둘 다 표현하려니 `invert` 플래그 같은 땜질이 나온 것.

→ **토큰을 두 벌로 분리한다. 이게 이번 색 설계의 전부다.**

```css
/* frontend/src/index.css — @theme 추가 (기존 1줄 @import 유지) */
@theme {
  /* 축 1: 방향 — 가치판단 없음. MOP/한국 증시 관례 */
  --color-dir-up: var(--color-red-600);      /* ▲ 증가 */
  --color-dir-down: var(--color-blue-600);   /* ▼ 감소 */
  --color-dir-flat: var(--color-gray-400);   /* 변화 없음 */

  /* 축 2: 판단 — 좋은가 나쁜가 */
  --color-judge-good: var(--color-emerald-600);
  --color-judge-bad: var(--color-red-600);
  --color-judge-warn: var(--color-amber-500);
  --color-judge-idle: var(--color-gray-400);  /* ★"0회"·"막힘" — D-47-h의 색 */

  /* 관리주체 3열 대조 (1층 ①) — 고정 배정 */
  --color-owner-ours: var(--color-blue-600);
  --color-owner-mop: var(--color-gray-500);
  --color-owner-manual: var(--color-gray-300);
}
```

**규칙 3개:**
1. **방향과 판단을 한 요소에 겹쳐 칠하지 않는다.** 델타 숫자는 방향색, 그 옆 판단 배지는 판단색. 겹치면 읽는 사람이 뭘 보는지 모른다.
2. `dir-up`/`dir-down`은 **`invert` 없이** 쓴다. `mopDelta`의 invert 플래그는 "비용 증가는 나쁨"이라는 **판단**을 방향색에 섞은 것 → 판단은 판단 토큰으로 옮기고 invert는 제거.
3. **`judge-idle`(회색)이 D-47-h의 색이다.** "우리 조작 0회"는 나쁜 게(빨강) 아니라 **아직 일어나지 않은 것**이다. 빨강으로 칠하면 고장난 것처럼 보이고, 초록으로 칠하면 거짓말이다. 회색 + 이유 텍스트가 정답.

**gray 13단계 → 5단계로 축소**(신규 코드 한정): `gray-50`(면) `gray-200`(선) `gray-400`(비활성/보조) `gray-600`(본문 보조) `gray-900`(본문). 나머지 8단계는 신규 코드에서 사용 금지. *(기존 화면은 8-0에 따라 그대로 둔다.)*

**만들지 않는 것**: 폰트 토큰(시스템 폰트 유지 — `:40` 제한), spacing 스케일(Tailwind 기본으로 충분), 다크모드(현재 0건, 스코프 밖).

### 8-2. ★ `lib/format.ts` — 경계를 넘지 않는 통합 (100배 오류 함정)

**인벤토리가 찾아낸 함정**: `pct()`가 **서로 호환되지 않는 입력 계약 2종**으로 존재한다.

| 계열 | 파일 | 입력 | 동작 |
|---|---|---|---|
| **분수 계열** | `NaverAdReport:48` `NaverAdDiagnosisBoard:30` | 0~1 | `(n*100).toFixed()` |
| **이미 스케일된 계열** | `NaverOps:60` `CoupangOps:40` `AdReport:19` | 0~100 | `n.toFixed()` — ×100 **안 함** |

**두 계열을 순진하게 하나로 합치면 `5%`가 `0.05%`로, 또는 `500%`로 조용히 렌더된다. 타입 에러도 안 난다.** `fmt()`도 6정의 중 `Dashboard:214`는 아예 **차트 값 포매터**로 이름만 같고 의미가 다르다.

→ **통합을 8-0의 리스킨 경계와 정확히 일치시킨다. 경계를 넘지 않는다.**

- `lib/format.ts`는 **분수 계열 계약만** 채택(naver-ad 4파일이 이미 쓰는 계약 = 이동 시 동작 불변).
- **import하는 파일 = naver-ad 4파일뿐.** `NaverOps`/`CoupangOps`/`AdReport`/`Dashboard`의 로컬 정의는 **건드리지 않는다** → 함정 자체가 발생하지 않는다.
- 이름으로 계약을 못 박아 재발을 막는다: **`pct()`라는 모호한 이름을 쓰지 않는다.**

```ts
// frontend/src/lib/format.ts — naver-ad 화면 전용. 다른 화면에서 import 금지(로컬 정의 유지).
export const NO_DATA = "—";                      // ★ 기존 naver-ad는 "-"(하이픈). 의도적 변경(8-2 주석 참조)

export function isoKST(d: Date): string          // 6곳 byte-identical → 무손실 이동
export function num(n: number | null | undefined): string          // 기존 fmt() — 이름만 명확히
export function won(n: number | null | undefined): string          // `${num(n)}원`
export function pctFromFraction(n: number | null | undefined, digits = 2): string  // 0.05 → "5.00%"
export function roasX(n: number | null | undefined): string        // `${n.toFixed(2)}배`
```

- **`pctFromFraction`** — 이름이 입력 계약을 선언한다. 스케일된 값을 넣는 실수를 이름이 막는다. (스케일 계열이 나중에 필요해지면 `pctFromScaled`를 **별도로** 추가하지, 절대 `pct` 하나로 합치지 않는다.)
- **`num`**: 기존 `fmt` 3정의는 동일 → 무손실. `Dashboard`의 동명이의 `fmt`(차트 포매터)와 이름이 갈라져 혼동 제거.
- **`NO_DATA` = `—`(em-dash)**: 기존 naver-ad는 `-`(하이픈), 쿠팡 계열은 `—`. 스코프 안에서 통일하며 타이포그래피상 옳은 `—`를 택함. **눈에 보이는 의도적 변경**(원칙22: 이건 리팩터가 아니라 UI 변경이라고 미리 못 박음).

**금지**: `lib/format.ts`를 스코프 밖 파일에 "겸사겸사" 적용하는 것. 그 순간 `pct` 함정이 살아난다. **구현 에이전트에게 이 문장을 그대로 전달할 것.**

### 8-3. ★ 공통 컴포넌트 — D-47-h를 API로 강제한다

MOP의 최대 실패는 **"빈 상태 설계 없음"**(§2-3: KPI 8칸 전부 0인데 이유 미설명)이고, 우리 1층은 대부분 0으로 채워진다(§6-2). **문서에 "이유를 쓰자"고 적어두면 지켜지지 않는다. 컴포넌트 API가 강제해야 한다.**

`frontend/src/components/ui/` 신규:

| 컴포넌트 | 계약 | 왜 |
|---|---|---|
| **`<Stat>`** | `value` 가 `0`/`null`이면 **`reason` prop 필수**(TS 유니온으로 강제) | ★**D-47-h를 타입으로 못 박음.** 이유 없는 0은 컴파일이 안 된다 |
| **`<EmptyState>`** | `reason: string` **필수**(optional 아님) | "데이터 없음" 단독 렌더 불가 |
| **`<Card>`** | `bg-white rounded-lg border border-gray-200` 1종 | 현재 카드가 **5가지로** 쓰임(`rounded-lg`/`rounded-xl`, `border`/`border-gray-200`, 패딩 제각각) |
| **`<Table>`** | `<Th>`/`<Td>`. **`total > pageSize`면 페이지네이션 필수** | ★§9 라이브: 진단보드가 489행 무페이징 → **스크롤 27,305px**. ⑨는 91,005행 |
| **`<Button>`** | `primary`/`secondary`/`ghost` 3종 | 인라인 조합 11+3회 반복 |
| **`<Badge>`** | `tone: 'dir' \| 'judge' \| 'owner' \| 'neutral'` | 8-1 두 축을 타입으로 분리 |
| **`<Delta>`** | `direction` 전용. **`invert` prop 없음** | 8-1 규칙 2를 API로 강제 |
| **`<Loading>`** | 스켈레톤 | ★§9 라이브: 진단보드 **5~8초 백지**(스피너 없음) |
| **`<CoverageBar>`** | ours/mop/manual 3분할 | 1층 ① 커버리지(현 1.15%) |

**만들지 않는 것**: Modal(1층~3층에 모달 없음 — `NaverOps`가 12회 쓰지만 스코프 밖), Tooltip, Tabs(URL 라우팅으로 대체 — §8-4), Form 입력류(콘솔 기존 것 유지).

> **`<Stat>`의 `reason` 강제가 이 설계에서 가장 중요한 한 줄이다.** MOP는 0을 찍고 침묵했고(§2-3), ref24가 지적한 MOP의 최대 공백은 "무엇을 왜"가 없는 것(§2 결정적)이다. 우리도 지금 비어 있다. **타입 시스템이 그 침묵을 금지한다.**

### 8-4. 라우팅 — 탭을 URL로

§9 라이브 확인: 탭 3개 전부 `/naver-ad` 한 URL, React state로만 전환 → **딥링크·북마크·새로고침 복원 불가.** 3층 구조를 만들면서 이걸 두면 "3층 원자료 탐색 보여줘"를 링크로 못 준다.

→ `/naver-ad`(1층) · `/naver-ad/report` · `/naver-ad/diagnosis` · `/naver-ad/console` · `/naver-ad/raw`. react-router-dom 7.13.2 이미 있음(신규 의존성 0).

### 8-5. 신규 의존성 = 0

UI 라이브러리(shadcn/Radix 등) **도입하지 않는다.** 컴포넌트 9개가 전부 `div`+Tailwind 수준이고, 현재 UI 라이브러리 0개인 코드베이스에 런타임 의존성을 들이는 비용이 이득보다 크다. 아이콘도 현행 이모지 유지(§1-6).

### 8-6. recharts

- **Y축은 이미 0에서 시작**(§9 라이브 실측: 좌 0/200/400/600 · 우 0/50000/100000/150000). recharts 기본 domain이 `[0,'auto']`이라 코드에 `domain` 미설정(전 차트 0건)인데도 0에서 시작한 것. **§2-2 우려는 해소 — 고칠 것 없음.**
- 다만 **기본값에 의존 중**이므로 신규 차트에 한해 `domain={[0, 'auto']}`를 **명시**한다(의도를 코드에 남김 · MOP가 저지른 §2-2를 우리가 실수로 재현하는 걸 방지). 기존 차트는 동작이 이미 옳으므로 건드리지 않음.
- 축 색: 현재 차트마다 hex 직접 지정(`#2563eb`/`#dc2626`, fontSize 11 vs 12 제각각) → 신규 차트는 8-1 토큰 참조.

### 8-7. 완료 기준

- `tsc` 통과 · `build` 통과 · **`grep -r "dark:" ` 0건 유지**
- **`grep`으로 검증**: naver-ad 4파일에 `isoKST`/`fmt`/`won`/`pct`/`roasX` **로컬 정의 0건**(전부 `lib/format.ts` import)
- **스코프 밖 파일 diff 0줄**(8-0 표의 "손대지 않음" 목록) — `git diff --stat`으로 확인
- 프론트 테스트 파일이 현재 **0개** → `lib/format.ts`는 **신규 유닛테스트 필수**(특히 `pctFromFraction` 계약)
- 라이브 확인: 배포 후 `/browse`로 1층 렌더·딥링크 5개 URL 왕복(원칙22)
