## §1. 목표 / 이번에 안 하는 것

### 목표

트랙 목표 원문(D-NAO-59, Jino 2026-07-19):

> *"무조건 이익스팟 순위에 있어서 매출 증가가 없는것보다 Roas는 떨어지지만 매출이 늘어서 총 이익이 늘어나는 경우, 구간도 분명히 있거든. 우리의 최종목표는 이거야. 이게 우리가 만든 MOP프로그램의 최종 목적이고 목표야."*

M2는 그 목표의 **L2(판단층)를 여는 칸**이다(북극성 ref 82 §2·§6). 총이익 방향의 자동화(L3·M4)가 서려면 판정이 먼저 있어야 하고, 판정이 서려면 신호가 두꺼워야 한다 — 논문 채택 13항목 중 **「신호 두께」 3종([9] 계층 풀링 · [8] n-gram→의미 단위 마이닝 · [10] 시간대 풀링 판독)이 전부 M2에 몰려 있다**(ref 82 부록 A). 구체적으로 이 계약은 ref 65의 **S1(판독·풀링: ⓐbidWeight 판독 ⓑ[9] 배선 ⓒ[8] 의미 단위 회수 ⓓBRAND_SEARCH 등록 공백 해소 ⓔ쇼핑 제외 후보 생성 잔재 수리)** 과 **S2(판정면 정비: ⓐ주말·공휴일 라벨 ⓑ하한 게이트 ⓒGAVE 성적표 축 ⓓWEB_SITE 비용 축 회수 후보 ⓔ조치×환경 채점 1라운드)** 를 집행한다. 전부 **재가동 불요 · 신규 자동 쓰기 0건** 축이라(ref 65 §7-A) M4의 Jino 결정 2건에 막히지 않는다.

이게 되면 달라지는 것: 주 15전환 이상 광고그룹이 3/494(0.6%, 90일 창)인 우리 규모에서 **그룹·검색어 단위 판단이 처음으로 원리적으로 가능**해지고(풀링), 26일간 0건이던 쇼핑 검색어 제외 후보가 pending까지 흐르기 시작하며(ⓒ→ⓔ, D-NAO-190), 확정 지식(주말·공휴일)이 문서가 아니라 판정 코드에 실린다.

## §2. 판단기준 ("항상 A, 왜냐하면")

1. **항상 ref 65 원문이 합격의 정의다** — 기준이 거칠어 보여도 다듬지 않고, 애매하면 애매하다고 §8에 올린다. 왜냐하면 D-NAO-213·북극성 §6이 재규정 금지를 못박았고, «몰래 고쳐 쓰기»가 이 프로젝트의 반복 사고이기 때문이다(ref 68 사고 · 미달 후 기준 인하 금지 규율).
2. **항상 기존 표면·기존 상수의 재사용을 신설보다 먼저 실측한다** — 왜냐하면 ref 65가 「새 상수·새 문턱을 만들지 않는다」를 설계 원칙으로 박았고, S1-ⓐ가 요구하는 `/ncc/targets` 판독 표면은 **D-NAO-201(2026-08-19)이 이미 `naver_adgroup_target_current` 1,013행으로 일부 만들어 뒀기** 때문이다(ref 65는 08-17 문서라 이 존재를 모른다 — §8-Q2).
3. **항상 착수 첫 작업은 실행이 아니라 숫자 재측정이다** — 왜냐하면 이 계약이 옮겨 적는 근거 숫자(385그룹·PAO 7 중 5개·`clk≥10` 11건 등)는 90일/14일 창의 **시점 실측**이라 판정 시점엔 낡아 있을 수 있기 때문이다([[handoff-lists-must-be-remeasured]] — 이 리포지토리에서 미결 8건 중 4건이 유령이었던 전례).
4. **항상 판정층까지만 만들고 실행은 기존 잠김에 맡긴다** — 왜냐하면 M2의 정체성이 «쓰기 없는 배선»이고, 잠김 2(승인원)·잠김 3(optimizer, `naver_execution_harness.py:2490` OptimizerGuardError)이 살아 있는 것 자체가 S1 합격기준 ⑤의 라이브 증거이기 때문이다.
5. **항상 라이브 증거로 닫는다 — 격리(테스트) 성공은 필요조건일 뿐이다** — 왜냐하면 바로 직전 칸(C10, D-NAO-212)에서 테스트 13종·변이 25종이 **원리적으로 못 잡는** 결함이 prod 첫 트리거에서 터졌기 때문이다(가짜 클라이언트 주입 사각).
6. **항상 ⓒ([8])를 ⓔ(잔재 수리)보다 먼저 한다** — 왜냐하면 D-NAO-190이 「ⓔ만으로는 후보가 0이다(정상 0) — 실제 해제 레버는 ⓒ」를 실측으로 확정했기 때문이다. ⓔ를 먼저 하면 «수리했는데 산출 0»이라는 거짓 실패 신호가 남는다.

## §3. 금지선 (prod 실광고비가 걸린 코드다)

- **입찰·예산·제외의 신규 자동 쓰기 0건.** S1-ⓔ 복원 후보는 **pending까지만** 흐른다. `APPROVAL_SOURCE_SS_EXCLUDE`(`search_term_judge.py:38`)를 자동 승인에 배선하는 것 절대 금지 — 코드 주석 원문 그대로 「활성화는 라이브 실측 후 Jino 승인 대상」.
- **`optimizer='none'` 7/7 불변.** 재가동을 실행·전제·촉구하지 않는다(D-NAO-132 ④). OptimizerGuardError 경로(`naver_execution_harness.py:2490`)를 우회·완화하는 어떤 변경도 금지.
- **bidWeight 적용(쓰기) 금지** — 판독·적재만(D-NAO-3 재심 전). `/ncc/targets` **PUT은 이 계약에서 0회** — GET만.
- **순위 서보 구현 금지**(D-NAO-124 미구현 유지) · **창 길이(7일 롤링) 변경 금지** · **Phase 구조·개방 순서(제외키워드→정지재개→입찰) 임의 변경 금지**(스프린트 X 금지선 승계).
- **ref 65 밖 기법·새 상수·새 문턱 발명 금지** — 문턱이 필요하면 기존 상수 계열(`_MIN_CLICK_*`·`_SS_WINDOW_DAYS` 등)을 재사용하고, 재사용이 불가능하면 구현을 멈추고 §8 경로로 올린다.
- **판정면 주입은 A/B(확정 지식)만** — C(미검증 가설) 주입 금지(ref 82 §5-3·§7). 미확정 환경(출시·휴가)은 층 승격 금지, 라벨만(ref 65 S2 「안 함」).
- **문턱을 「후보가 나오게」 조정하는 것 금지**(D-NAO-190의 규율 승계) — 산출 0이면 0이라고 기록한다.
- **DB 스키마는 마이그레이션으로만** + 배포는 `scripts/safe_deploy.sh` 전용(§7). 직접 scp/rsync 금지.
- **합격기준 미달 시 기준 인하 금지** — 목적 전환 선언 없이는(전역 §2). 미달은 유효한 종결 상태다.
