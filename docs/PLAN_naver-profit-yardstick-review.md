## §0. 북극성 궁극 목표 원문 + 이 계약이 미는 것

정본 `docs/references/82_pao_north_star_20260819.md` §1 원문 그대로:

> **PAO의 궁극 목표는, 네이버 광고·스마트스토어 API가 주는 모든 지표와 4등급 성과등급 사이의 «개연성(연관)»을 홀드아웃 검증까지 통과한 지식으로 확정하고(①), 논문에서 채택한 기법(ref 26 TOP5 + ref 33 [0]~[10])과 이 트랙이 이미 세운 실행 구조(레인·가드레일·고삐·확장압력) 위에서(②), 우리가 운영하는 모든 광고 형태(SHOPPING·WEB_SITE·BRAND_SEARCH — ADVoost·GFA는 성과 관측이 원리적으로 막혀 있어 별도 취급, §8-④)를 총이익 절대액이 최대가 되는 방향으로(③, D-NAO-59) 자동화 운영하며(④), 운영의 매 행위와 결과를 일기→반성→지혜 승격의 학습 사슬에 태워 어느 지점을 배우면 성능이 더 오르는지를 스스로 찾아, 신호가 허락하는 최단 주기로 성능개선을 반복 시도하는 것(⑤)이다.**

트랙 최상위 목표 — Jino 원문 (D-NAO-59, 2026-07-19):

> *"무조건 이익스팟 순위에 있어서 매출 증가가 없는것보다 Roas는 떨어지지만 매출이 늘어서 총 이익이 늘어나는 경우, 구간도 분명히 있거든. 우리의 최종목표는 이거야. 이게 우리가 만든 MOP프로그램의 최종 목적이고 목표야."*

## §1. 문제 — 지금 무엇이 틀렸나 (전건 출처 좌표 병기)

### §1-1. 구조: 보정계수는 「100% 견인 가정」과 동치다

```python
# backend/app/services/naver_ad/diagnosis.py:19-47
def correction_factor(db, date_to) -> dict:
    earliest_real = diag.earliest_real_data_date(db, date_to, 30)   # 창 최대 30일
    revenue = naver_order_revenue(db, date_from, date_to)["revenue"]          # ← 분자
    totals  = metrics_aggregator.aggregate(db, date_from, date_to, grain="date")["totals"]
    naver_conv_amt = totals["conv_amt"]                                       # ← 분모
    factor = (Decimal(revenue) / Decimal(naver_conv_amt)).quantize(Decimal("0.0001"))
```

```python
# backend/app/services/naver_ad/actual_revenue.py:18-40  ← 분자의 정체
def naver_order_revenue(db, date_from, date_to) -> dict:
    base = db.query(Order).filter(
        Order.channel_id == 6,                      # 네이버 채널
        Order.status.notin_(tuple(REVENUE_EXCLUDED)),
        Order.order_date >= start, Order.order_date <= end,
    )
    # → 광고 귀속 조인이 «전혀 없다». 네이버 채널 전체 주문매출.
```

- 분자 = 네이버 채널 **전체** 주문매출 (광고 귀속 조인 0)
- 분모 = 광고 전환매출 conv_amt (직접+간접)
- ⇒ 정의상, 광고 전환매출에 이 계수를 곱해 전부 더하면 결과는 **정확히 채널 전체 매출**이 된다. 현재 구조는 **「스토어 매출 100%를 광고가 견인했다」는 가정**과 수학적으로 동치다.

## §3. 판단기준 ("항상 A, 왜냐하면 ○○")

1. **항상 「모른다」를 정직하게 표현하는 자를 목표로 한다**, 왜냐하면 주문에 광고 귀속 키가 없어(§1-7) 진짜 귀속은 원리적으로 불가능하고, 점추정 하나로 덮으면 「100% 견인」 같은 숨은 가정이 수학에 굳는다(§1-1) — `today_proxy_revenue`가 이미 세운 「0 대신 None+사유」 규율의 계수판이다.
2. **항상 계수를 손대기 전에 9개 소비처의 이동 방향·건수를 먼저 센다**, 왜냐하면 같은 계수가 브레이크(정지 판정)와 액셀(입찰 상한·확장 배분)을 반대 방향으로 움직여, 세지 않고 고치면 D-NAO-85(ROAS +7%·매출 −52%)를 계수로 재현한다(§1-6).
3. **항상 자 교정과 액셀 재조정을 한 배포 단위로 묶는다**, 왜냐하면 계수 하향은 브레이크 자동 강화와 동치라(§1-6), 교정만 단독 배포하면 그 배포 자체가 ROAS 방어로의 표류다.
4. **항상 경영 판단(광고 견인 가정)은 선택지+귀결로 Jino에게 올린다**, 왜냐하면 데이터가 답할 수 없는 질문의 답을 코드 기본값이 대신 정하면 그것이 곧 선언 없는 결정이고, D-NAO-21도 Jino가 고른 결정이었다(§1-4).
5. **항상 설계 의도는 결정 기록(D-N·계약)으로만 확정하고, 확정 안 되면 [미상]으로 남긴다**, 왜냐하면 주석은 시점의 화석일 수 있음이 이 건 자체로 실증됐다(§1-4 — 같은 공식에 반대 방향 주석 둘).
6. **항상 계수(및 그 파생 총이익·보정ROAS)는 가정·창·분모와 함께 표면에 내보낸다**, 왜냐하면 D-NAO-21의 「양쪽 병기(왜곡 방지)」가 원 결정에 이미 있었고, 단독 숫자는 부호까지 가르는 이 계수(§1-3)의 불확실성을 숨긴다.
7. **항상 문턱값·비교의 근거 숫자는 창·분모를 다시 세고 쓴다**, 왜냐하면 표본이 준 결정을 전수로 굳히지 않는 것이 북극성 §7의 규율이고(A6: 표본 98.5% vs 전수 78.0%), 이 계수 자체가 롤링 창이라 어제의 값이 오늘의 값이 아니다(§1-2).

## §4. 선택지 — Jino가 고를 것 (최소 결정 1건: 안1~안4 중 하나)

각 안에 ①9개 소비처 영향 ②M4 카나리 판정 영향 ③구현 난이도 ④「모른다」의 정직성을 병기한다. **공통 전제: 어느 안을 골라도 산출물 A(전수표)·B(주석 처분)·D(북극성 개정)는 실행된다.**

### 안1 — 현행 공식 유지 + 가정의 «명문화·전면 병기»

「보정계수 = 채널 전체 매출 ÷ 광고 전환매출」을 그대로 두되, **「이 자는 채널 매출 100%를 광고 성과로 간주한다」를 공식 가정으로 선언**하고, 표면(진단 보드 카드·profit_scorecard 응답)에 가정·창·보정 전 값을 항상 병기한다. `diagnosis.py:22` 화석 주석을 「공식은 방향 중립 — 창의 데이터가 방향을 정한다」로 정정.

- ① 소비처 영향: **코드 판정 로직 변화 0** — 9개 소비처 전부 현재 값 유지. 표면 표기만 는다.
- ② M4 영향: 카나리 성적이 지금과 같은 자로 재짐 — **부풀 위험이 그대로 남되, 부풀어 있음이 화면에 보이게 된다.** M4 합격기준에 「보정 전 총이익 병기」를 붙이는 후속 개정이 사실상 필수.
- ③ 난이도: **하** — 주석·표면 표기·문서만.
- ④ 정직성: **중** — 가정을 자백하지만 숫자 자체는 여전히 100% 견인 가정치다.

### 안2 — 귀속 가능한 부분집합으로 분자·분모를 좁힘

분자를 「`naver_adgroup_product` 매핑이 있는 상품의 주문매출」로, 분모를 「해당 그룹의 conv_amt」로 좁혀 **매핑 가능한 SHOPPING 지면만으로 계수를 만든다.** 매핑 불가 지면(파워링크·브랜드검색)은 §1-7 규율대로 보정 없이 raw + 「귀속 불가」 사유 표기(또는 계수 1.0 고정 + 사유).

- ① 소비처 영향: 계수 값이 바뀌므로 **9개 전부 움직인다** — 방향·폭은 산출물 A가 사전 실측. SHOPPING/비SHOPPING이 다른 자를 쓰게 되므로 캠페인유형 혼합 비교 지점(계정 단위 소비처)은 재설계 필요.
- ② M4 영향: 카나리가 SHOPPING이면 **가장 정직한 자로 채점**된다. 비SHOPPING 카나리면 무보정 채점.
- ③ 난이도: **상** — `correction_factor`의 시그니처(계정 단위→유형/그룹 단위)가 바뀌어 9개 소비처 수정 + 매핑 커버리지 사전 조사 필수(**커버리지 [미상]**, §8-3 — 커버리지가 낮으면 이 안은 표본 자 위에 서게 되어 §3-7 위반).
- ④ 정직성: **상** — 아는 부분만 재고 모르는 부분은 모른다고 말한다. 단 「매핑 있는 상품의 전체 판매액」도 여전히 상한 프록시임(§1-7 정직 경계)은 남는다.

### ★★안3 — 점추정을 버리고 «구간 자»로 전환 — **← Jino 채택 (2026-08-23, D-NAO-230)**

계수를 단일 값이 아니라 **[하한, 상한] 구간**으로 표현한다: 하한 = 1.0(보정 없음 — 광고 전환매출을 그대로 믿되 상향 보정은 하지 않음), 상한 = 현행 채널 전체 계수. 소비처별로 «어느 끝을 쓰는가»는 산출물 A의 액셀·브레이크 분류에 따라 규칙으로 정한다 — 예: **브레이크(정지 판정)는 상한으로**(총이익을 후하게 봐서 살릴 수 있는 캠페인을 죽이지 않음 = D-NAO-59 방향), **액셀(입찰 상한·확장)은 하한으로**(자동 실쓰기의 상한은 보수 — exploration.py:332가 이미 세운 규율의 일반화). 표면에는 구간 양끝 병기.

- ① 소비처 영향: **소비처별 사용 끝(端) 표가 곧 변경 명세**가 된다 — 산출물 A 없이는 착수 불가. 브레이크 판정은 현행과 유사(상한=현행), 액셀은 보수화.
- ② M4 영향: 카나리 성적이 **구간으로 나온다** — 「하한으로도 흑자」가 새 합격 표현이 될 수 있음(M4 합격기준 개정과 연동, §4-5).
- ③ 난이도: **중** — 공식은 그대로 두고 소비처 호출부에 끝 선택 규칙을 얹는다. 시그니처 변경은 반환 dict 확장으로 흡수 가능.
- ④ 정직성: **상** — 「모른다」를 구간 폭 그 자체로 표현한다. 단 하한 1.0의 근거(convAmt를 그대로 믿는 것)도 하나의 가정임을 병기해야 한다 — D-NAO-7은 convAmt가 과대일 수도 있음을 실증했으므로 진짜 하한은 1.0 미만일 수 있다(**하한을 어디에 둘지가 이 안의 내부 [미상]**, §8-8).

### 안4 — §8-⑤(스마트스토어 광고 밖 수요 대조축)와 «한 결정»으로 묶음

북극성 §8-⑤ — *"스마트스토어 주문을 «광고 밖 수요» 대조축으로 개통할지 (간극 5의 우회로 · 기존 결정 대기, 창 5.5개월)"* — 는 이 문제와 본질이 같다(「광고 밖 수요를 어떻게 가르나」). 이 안은 **⑤를 지금 개통하기로 같이 결정**하고, 광고 밖 수요를 실측으로 갈라 분자를 정련하는 것을 최종 형태로 삼되, 개통 전까지는 안3(구간)을 임시 자로 쓴다.

- ① 소비처 영향: 단기는 안3과 동일, 개통 후 재수렴.
- ② M4 영향: 단기는 안3과 동일. 장기적으로 가장 좋은 자.

## §6. 금지선

1. **Jino 선택(산출물 C의 D-N 기록) 전에 계수 공식·소비처 코드를 변경하지 않는다.** S1(전수·감도 실측)은 전건 읽기 전용이다.
2. **자 교정을 단독 배포하지 않는다** — 계수를 낮추는 변경은 액셀 재조정(또는 「액셀 판정 불변」의 실측 확인)과 같은 배포 단위로만. 위반은 D-NAO-85 재현 경로다(§1-6).
3. **판정면 주입은 A/B(검증 통과 지식)만** — 미검증 가설을 계수·문턱값의 근거로 소비하지 않는다 (북극성 §7).
4. **표본이 준 숫자를 전수로 굳히지 않는다** — 안2의 매핑 커버리지, 안3의 하한 등 문턱값 근거는 창·분모를 다시 세고 쓴다 (북극성 §7).
5. **되돌릴 수 없는 액션은 승인 지점을 상속한다** — 신규 캠페인 생성·예산 상한 인상은 사람 Confirm · 위임 스위치는 Jino만 · `optimizer='ours'` 아닌 캠페인에 쓰기 절대 금지 (북극성 §7).
6. **계수·총이익·보정ROAS를 가정·창 병기 없이 새 표면에 내보내지 않는다** (§3-6).
7. **과거 판정·지혜 승격을 소급 자동 재채점하지 않는다** — 발견은 `## 이월`에 기록만 (§2 비목표).
8. **「전수 조사 완료」·「연관 규명 완료」라고 쓰지 않는다** (북극성 §7).
9. prod 배포는 `scripts/safe_deploy.sh`로만, DB 변경은 `--migrate` 순서로만, PR 병합은 `scripts/safe_merge.sh`로만 (프로젝트 금지선 상속).
