# 배선 안 됨이 기본 상태다

## 패턴

코드·모델·docstring·문서에 존재하는 기능이 **실제 계산 경로에 연결돼 있을 확률은 기본값이 아니다.**
"파일이 있다" → "함수가 호출된다" → "그 결과가 판정을 바꾼다" 는 **세 개의 별개 사실**이고,
각각 따로 증명해야 한다.

## 이 repo의 목록 (실측된 것만)

| 표방 | 실제 | 확인 방법 |
|---|---|---|
| `NaverCampaignSettings.mode` 다이얼 4종 | 저장만 되고 **소비처 0건** | `backend/app` 전체 grep |
| `gave_score.compute_gave_score()` | 정의·테스트는 있는데 **파일 밖 호출 0건** | grep (자기 파일 84행 자기참조뿐) |
| PAO 입찰 집행 59건 | **옥션 무접촉**(그룹 레이어에 씀, 실효는 소재) | `use_group_bid_amt` 36/36 + CPC 추이 |
| `today_proxy_revenue` | 함수 존재·화면·예산 페이싱엔 연결, **auto_operator만 미연결** | 호출부 grep (P0-a가 이 배선) |
| `change_log` 쓰기 규약 | 규칙을 **아는 사람만** 지킬 수 있음(가드 없음) | 교훈 #196 — 내가 action 이름을 지어냄 |
| 집계 정본 규칙 | 서비스 코드는 지키나 **조회·분석 경로엔 가드 0** | 교훈 #195 — 두 세션 연속 사고 |

## 세 단계 증명

1. **존재**: 파일·심볼이 있다 → `ls`/grep
2. **호출**: 실행 경로에서 불린다 → 호출부 grep, 또는 로그/카운터
3. **영향**: 그 결과가 **판정을 바꾼다** → 값을 반대로 바꿔도 결론이 같으면 배선 아님
   (변이 주입이 이 단계의 도구다 → [[green-does-not-mean-verified]])

3단계를 건너뛴 것이 교훈 #202다 — 쓰기는 존재하고 호출됐지만 **영향이 0**이었다.
