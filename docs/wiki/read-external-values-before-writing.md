# 외부가 정하는 값은 먼저 읽고, 그 다음 쓴다

## 패턴

번호·해시·ID·규약 이름처럼 **내가 정하지 않는 값**을 쓸 때,
「계산하는 명령」과 「쓰는 명령」을 한 호출에 묶으면
**도구의 답이 도착하기 전에 답을 지어낸 꼴**이 된다.

## 이 repo의 사례

- **교훈 #201 (번호 충돌 4번째)**: `next_ids.sh && cat >> LESSONS…`를 한 명령으로 돌렸다.
  스크립트는 「다음은 #198」이라고 **정확히** 말했는데, 같은 호출이라 그 출력을 볼 기회가
  없었고 heredoc 안엔 이미 #195~#197이 박혀 있었다. ★도구는 제 일을 했다 — **부르는 순서**가 틀렸다.
- **교훈 #196**: change_log에 `manual_loss_stop`이라는 **없는 action 이름을 지어냈다.**
  규약(`OURS_ACTIONS_BY_AXIS`)은 코드에 있었는데 읽지 않고 썼다 → 다음 감사에서 「대행사 조작」으로 잡혔을 것.
- **2026-08-10 `changed_at` UTC 사고**: 네이버 `editTm`의 Z 시각을 KST 규약 컬럼에 그대로 넣었다.
  같은 테이블의 기존 행들이 KST라는 사실을 **먼저 읽었으면** 안 났다.
- **D-NAO-163 P1-1**: 결정 원장에 «추가»하면서 Edit의 `old_string`으로 남의 헤딩을 잡아 **치환**했다.
  → 편집 후 `git diff | grep '^-'`로 삭제줄 0을 확인하는 습관이 대응책.

## 왜 `principle`인가 (그리고 왜 그게 문제인가)

현재 처분은 **원칙**뿐이다. 그런데 [[text-rules-fail-build-tools]]에 따르면
**같은 태그로 4회 재발했으면 이미 도구가 있어야 한다.** 이 항목은 승격 후보다.

승격 아이디어(감사에서 결정할 것):
- `next_ids.sh --reserve`가 번호를 원장에 자리표시자로 **미리 써 두기**
- pre-commit 훅이 `LESSONS_LEARNED.md`·트랙 파일의 **중복 번호를 거부**
- 편집 후 삭제줄 0 확인을 훅으로
