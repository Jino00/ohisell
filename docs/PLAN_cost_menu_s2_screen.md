## Q1. 첫 화면 — 「보드 + 할 일 인박스」 레이아웃

### 무엇이 보드이고 무엇이 인박스인가

- **보드** = «지금 어디까지 왔나»의 숫자 스트립. 읽기 전용, 항상 위에. 재고: 단가 있는 종 75/139 · 계산된 레시피 20/100 · 승인 레시피 20 · 원가 있는 SKU 448/924 · 마지막 업로드 시각(2026-08-27 22:30 KST 형식). 각 숫자는 해당 드릴다운으로 가는 링크다.
- **인박스** = «사람이 손대야 움직이는 것»의 목록. **새 개념이 아니다 — 이미 DB에 쌓인 여섯 재고를 처음 한 곳에 세우는 것이다**(실측 1-1절). 항목을 누르면 그 일을 «하는 자리»(드릴다운)로 간다.
- **왕복 표** = 첫 화면의 본문. 부자재 139행. Q3에서 확정한다. [다운로드] 버튼이 이 표 머리에 붙는다(S3에서 활성화 — S2에서는 자리만 서고 비활성 + 「S3에서 만든다」 표기).

### 인박스 묶음 — 여섯 재고를 넷으로 접는다

| 묶음 이름 (화면 문구) | 원천 | 건수(08-28 실측) | 누르면 가는 곳 |
|---|---|---|---|
| **「모순 — 사람이 고른다」** | `cost_recipe.anomaly_flag`의 `price_conflict` (레시피 단위) | **2** (레시피 45·97) | Q6의 모순 상세 |
| **「단가 없음 — 빈 칸이지 0원이 아니다」** | 단가 없는 종 | **64** | 왕복 표(단가 없음 필터 적용) → 행 클릭 → 부자재 드릴다운 |
| **「구성 없음 — 원가표와 못 이었다」** | `no_recipe_match` 80 + `needs_manual_lines` 3 | **83** | 레시피 드릴다운(해당 레시피 필터) |
| **「원가표 항목 — 픽·이상 확인 대기」** | 픽 안 된 항목 50 + `cost_table_item.anomalies` 10 | **≤60** (중복 접기 후, 아래 주의) | 레시피 드릴다운의 CostTablePicker |

- **왜 넷인가**: 묶음의 기준은 원천 테이블이 아니라 **「사람이 하는 일의 종류」**다 — ①고른다(모순) ②넣는다(단가) ③잇는다(구성) ④확인한다(픽·이상). 여섯 원천을 그대로 여섯 줄로 세우면 같은 사건이 두 줄에 선다(아래).
- ⚠️ **중복 접기 규칙**: 레시피 45·97의 price_conflict는 `cost_recipe.anomaly_flag`와 `cost_table_item.anomalies` **양쪽에 기록돼 있다**(실측 1-2절). 인박스는 «사건» 단위다 — price_conflict는 레시피 묶음(2건)으로만 세고, 항목 anomaly 10건 중 같은 원인 건은 넷째 묶음에서 뺀다. (10건의 내역 분해는 미상 — 구현 시 anomalies 문자열을 실제로 갈라 세야 한다. ★확인 못 한 것 ③)
- **「없음」 표시**: 묶음 건수가 0이면 줄을 감추지 않고 `— 없음`으로 남긴다. 「빈 인박스」와 「인박스가 안 뜸」이 같은 화면이 되면 안 되기 때문이다(「없음」≠표시 안 함 — 기존 금지선의 결).

## Q3. ★왕복 표 — 행·열 확정 (S3 파일 포맷이 여기서 결정된다)

**행** = `cost_material` 139종. 부자재 한 줄 = 식별자 있는 한 행(계약 §4 S2 ③ 원문).

### 키 결정: `cost_material.id`

- **왜 이름이 아닌가**: 이름은 파일에서 바뀐다(오타 수정·개명이 왕복의 정당한 용례다). 이름을 키로 쓰면 개명이 「행 사라짐 + 새 행」으로 오독되어 S4의 「사라짐 → 비활성」 경로가 멀쩡한 종을 죽인다.
- id를 키로 두면 개명은 **같은 행의 `이름` 열 변경 1건**으로 선다. S4의 3-방향 diff(DB 현재 ↔ 스냅샷 ↔ 업로드 파일)가 전부 이 id 위에서 돈다.
- 파일에서 id가 비거나 모르는 값인 행 = **「신규 종 후보」 묶음**으로 확인 화면에 선다(자동 생성 금지 — 확인 클릭이 생성이다). id 중복 행 = 「모순」 묶음.

### 열 12개

| # | 열 이름 | 원천 | 수정 가능 | 빈 칸일 때 |
|---|---|---|---|---|
| 1 | `ID` | `cost_material.id` | **불가** (키) | 없음 — 항상 있다. 파일에서 비면 「신규 종 후보」 |
| 2 | `이름` | `name` | **가능** | 불가(필수) |

| 4 | `부품` | `part` | **가능** | 화면 `(부품 미지정)`(기존 2434) / 파일 빈 칸 |
| 5 | `단위` | `unit` | **가능** | 파일 빈 칸 |

- **수정 가능 열은 5개뿐이다**(이름·폼팩터·부품·단위·단가ex·발효일·비고 중 단가 관련을 하나로 세면). 나머지는 전부 파생·미러·키다.
- **읽기 전용 열의 파일 표시**: 헤더에 `«읽기전용»` 접미(예: `단가 (VAT 포함) «읽기전용»`). 시트 보호(잠금)는 쓰지 않는다 — 엑셀 잠금은 사용자가 풀 수 있어 방어가 아니고, **진짜 방어는 S4 diff가 읽기 전용 열 변경을 「반영 불가」 묶음으로 세우는 것**이다(무시하지 않고 보인다 — 조용한 드롭은 자동 병합의 사촌이다).
- **「없음」≠「0」**: 화면은 기존 문구 `(빈 칸이지 0원이 아니다)`(499)가 계속 그 일을 한다 — 이 문구를 왕복 표의 단가 없음 행 툴팁으로 «이동»한다(삭제 아님). 파일은 빈 칸으로 내려간다 — 엑셀에서 빈 칸과 0은 다른 값이고, S4 파서는 `0` 입력을 「0원으로 바꾸겠다는 주장」으로 diff에 세운다(빈 칸→0도 변경 1건이다).
- **VAT ex/inc 둘 다 싣되 수정은 ex만**: 이 저장소의 단가 입력 경로가 전부 ex 기준이고(수동 프롬프트 3019 「VAT 제외」), inc는 저장값 또는 ×1.1 파생이라 «어느 쪽이 원본인지»가 행마다 다르다. 둘 다 수정 가능이면 한 행에서 ex·inc가 서로 모순되게 고쳐질 수 있다 — 그 모순의 심판 규칙을 만드는 순간 자동 병합 금지선에 닿는다. inc는 표시 전용 + `×1.1 파생` 배지(D-CPP-51 「제외값은 옆 칸에 함께 표시」의 연장).
- **원장 정본 종**(수입 종 — 실측: 원장 파생 최신단가 4종): 단가 열은 값이 내려가되 셀에 `[원장]` 접두(출처 열과 이중 표시). 파일에서 이 칸을 고치면 S4 확인 화면의 **「반영 불가 — 정본이 원장」** 묶음에 선다 — 적용되지 않고, 보인다. 이것은 자동 병합이 아니라 계약 §2 「정본은 원장」 규칙의 집행이다(값을 고르는 게 아니라 경로를 막는 것).
- **스냅샷 ID 자리**: 데이터 시트를 오염시키지 않도록 별도 시트 `_meta`(snapshot_id·생성 시각 KST·행 수)를 예약한다. 구현은 S3 몫이되 **표 설계가 지금 자리를 확정해 둔다** — S4 diff의 «스냅샷» 축이 이 값을 읽는다.
- **패키지 flip/fold가 왜 두 행인가**: §0-A‴의 「단가의 소재지가 종인지 (종,제품)인지」 질문에 대한 이 표의 답은 **「종 = 행」 유지**다. 폴드 사건의 처분이 「새 종 신설이 아니라 구성이 flip 종을 가리키게」(Jino 22:44)였으므로, 축 늘리기는 «레시피 구성이 어느 종을 가리키는가»(Q6)에서 해결되지 표에 (종,제품) 차원을 넣지 않는다.

## Q6. 레시피 45·97 「종 가르기」 — 인박스 「모순」 상세

**인박스의 실제 항목이 이것이다** — `price_conflict:부착 안내문:55.0≠30.0,…`가 이미 DB에 앉아 있다(실측 1-2절).

**누르면 보이는 것** (레시피 단위 상세, §4 S4 규칙 준용 — **추천하지 않는다**):

```
레시피 45 「갤럭시Z 힌지 보호 필름 2매」(fold) · SKU 5개 · 지금 표준원가 1,120.70(+VAT)
이 레시피의 픽(원가표 항목 34)이 말하는 값과, 구성이 가리키는 종의 단가가 다르다.
┌────────────┬──────────────────────────┬──────────────────────────────┐
│ 구성 라인   │ 픽이 가져온 원가표 라인 값 │ 지금 구성이 가리키는 종의 단가 │
│ 부착 안내문 │ 30  (원가표 항목 34의 라인) │ 55  (종 #48 「부착 안내문」 fold)│
│ 비닐(16*23+4)│ 10  (〃)                  │ 15  (종 #53)                  │
│ 패키지      │ 171 (〃)                  │ 320 (종 #54)                  │
└────────────┴──────────────────────────┴──────────────────────────────┘
라인마다: [이 라인이 가리키는 종을 바꾼다 ▾]  ← 같은 이름의 다른 종이 값·폼팩터와 함께 나열된다.
          어느 쪽이 맞는지는 화면이 고르지 않는다 — 값과 출처만 보인다.
[그대로 둔다 — 보류 유지]
```

- **무엇을 고를 수 있는가**: 라인별 「가리키는 종 바꾸기」(드롭다운 — 후보는 이름 유사 종 전부, 각 후보에 단가·폼팩터 병기, 정렬은 이름순·추천 배지 없음). 종을 바꾸면 표준원가가 재계산되고 anomaly_flag의 해당 `price_conflict:` 조각이 내려간다. 승인된 레시피(45)는 기존 규칙대로 **먼저 승인 해제**가 필요하다(2031 문구 그대로 적용).
- **무엇은 못 하는가**: 이 화면에서 종 단가를 고치는 것(그건 왕복 표·수동 입력의 일 — 한 화면에 두 종류의 쓰기를 섞으면 「어느 쪽을 골랐나」가 흐려진다) · 새 종 신설(Jino 22:44 처분 원문 *"같은 부자재가 다른 값이 아니고, 다른 부자재인거지"* — 이미 있는 flip 종 #18·#23·#24가 후보에 뜬다).
- **출처(행 번호) 표시**: 픽 쪽 값에는 원가표 항목 id·항목명을, 종 쪽 값에는 종 id를 병기한다. §0-A′ 교훈(엉뚱한 비교에 처분 적용) 때문에 «이 값이 어디서 왔는가»가 값 자체만큼 중요하다. ⚠️ 파일 «행 번호»는 `cost_table_line`에 저장돼 있는지 미확인(★확인 못 한 것 ④) — 없으면 항목명·라인명 좌표로 대신하고 그 사실을 화면에 적는다.
- **신규 API가 필요하다**: 「구성 라인의 material_id 교체」 엔드포인트는 현행에 없는 것으로 보인다(실측 2-2절 API 28종 목록에 해당 동작 부재 — ★확인 못 한 것 ⑤). 교체는 확인 1클릭 후에만 쓰고, 교체 이력을 note 또는 별도 기록으로 남긴다(사후 가시성).

## Q7. `material_refs` — 업로드 결과 화면의 어디에 그리는가

**백엔드는 결함이 없다** — 347(원가만)·533(양쪽) 두 갈래 모두 응답에 싣는다(실측 4-②). 할 일은 프론트 배선 한 구간이다.

- **타입**: `frontend/src/lib/api.ts`의 `CostImportResult`(6149–6171)에 `material_refs?: { refreshed: …[]; refreshed_count: number; conflicted: …[]; conflicted_count: number }` 추가. (원소 형상은 `recipes.py` 680–811의 실제 payload를 보고 확정 — ★확인 못 한 것 ⑥)
- **자리**: `RecipeImportPanel` 결과 블록(1629–1694) 안, `cost_table_anomalies`의 `<details>`(1669–1680) **바로 위**에 `<details>` 2개:
  - `<summary>참고값 갱신 {refreshed_count}건</summary>` — 행마다 `{종 이름} · {옛값} → {새값}` (S1 리뷰 조건 ①「옛 값이 어디에도 안 남고」의 답 — 옛 값이 이 리포트에 남는다)
  - `<summary>참고값 모순 보류 {conflicted_count}건</summary>` — 행마다 두 값과 좌표, 어느 쪽도 추천 없음
- **왜 그 자리인가**: 「원가표 이상」·「매핑 이상」과 같은 문법(접힌 `<details>`)·같은 자리에 서야 «업로드가 한 일의 전모»가 한 블록에서 읽힌다. S1 리뷰 원문이 요구한 것이 정확히 「미러라는 걸 사람이 볼 수 있을 때」다.
- **0건일 때도 그린다**: `참고값 갱신 0건` — 「안 실림」과 「0건」이 같은 화면이 되면 리뷰 조건 ③(두 파일 경로에서 리포트가 안 실려도 아무도 모름)이 재발한다. `material_refs` 필드 자체가 응답에 없으면(구버전 백엔드) `⚠ 참고값 리포트 없음 — 백엔드 버전 확인`을 세운다.
- **테스트**: 347(원가만 업로드)·533(원가+매핑 동시) **두 갈래를 각각 밟는** 테스트 필수 — 적대 리뷰 변이 MB1이 실증한 구멍이 「동시 업로드 경로를 테스트가 안 밟는다」였다. `costMaterialsSurface.test.tsx:445`의 자백 주석(「S4 몫으로 이월」)은 이 배선이 S2로 당겨졌음을 반영해 갱신한다(주석 갱신은 문구 삭제가 아니다 — 테스트 주석은 사용자 표면이 아니다).

- **MaterialList를 개조해 왕복 표로 쓴다** — 버림: 장문·버튼이 섞인 목록을 «파일과 같은 모양»으로 만들려면 결국 다 뜯게 되고, 파일에 없는 열이 표에 남아 「표=파일」 등식이 처음부터 깨진다.
- **키를 이름(또는 이름+폼팩터)으로** — 버림: 개명이 「사라짐+신규」로 오독되어 S4 비활성 경로가 멀쩡한 종을 죽인다.
- **VAT inc 열도 수정 가능** — 버림: 한 행에서 ex·inc가 모순되게 고쳐질 수 있고, 그 심판 규칙이 곧 자동 병합이다.
- **엑셀 시트 보호(셀 잠금)로 읽기 전용 집행** — 버림: 사용자가 풀 수 있어 방어가 아니다. 방어는 S4 diff의 「반영 불가」 묶음이 한다(잠금은 해도 좋지만 근거로 삼지 않는다).
- **표에 (종,제품) 차원 추가**(§0-A‴의 축 질문에 대한 다른 답) — 버림: Jino 처분 원문이 「다른 부자재」 — 축은 레시피 구성의 참조 교체(Q6)로 해결되고, 표에 차원을 넣으면 행 수가 곱으로 늘어 왕복 파일이 사람 손을 벗어난다.
- **인박스를 여섯 원천 그대로 여섯 줄** — 버림: 같은 사건(45·97)이 두 줄에 서고, 묶음 이름이 테이블명이 되어 사람의 일 종류와 어긋난다.
- **탭 전면 재편(3탭 폐지, 홈 단일 화면)** — 버림: 익숙한 직행 경로가 죽고, 3,337줄 «재사용»이 아니라 «재배치»가 되어 예산(S2 최대 2세션)을 넘는다. 입구만 바꾼다.
- **URL 라우터 도입(딥링크용)** — 버림: 기존 페이지가 상태 기반이라 라우터 도입은 개편 반경을 앱 전체로 넓힌다. 탭 전환+상태 주입으로 충분하다.
- **승인(종·레시피)을 인박스에서 일괄 처리** — 버림: 두 승인은 다른 질문이고(단가 신뢰 vs 구성 신뢰), 일괄 버튼은 「Jino 확인=승인」의 확인을 형식화한다.
- **NotYetPanel 문구를 다른 자리로 이식 후 제거** — 버림: 취지(빈 칸≠0)는 499가 이미 담당하고, 닿지 않는 문구의 이식은 «소실 0건»을 형식으로만 지키는 것이다. 죽은 코드 명시 후 제거가 정직하다.
