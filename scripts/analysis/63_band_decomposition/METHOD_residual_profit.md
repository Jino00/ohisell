# 방법 설계 — 「외부 요인을 제거하고도 남는 흑자/적자」 (2026-08-17, Opus 판단)

> 이 문서는 Stage B/C 구현 스펙이다. 새 숫자를 발명하지 않는 것이 규율 — 파라미터는 전부
> 이미 확정된 값(BEP 1.711 · 휴가창 7/20~8/15 · F2 28일 · F3 180일)에서만 온다.

## 0. 왜 ROAS가 아니라 «이익 절대액»이 분해의 축인가

Jino의 질문은 「흑자패턴 / 적자패턴」이고 PAO의 목적함수는 **총이익 절대액**(D-NAO-59)이다.
ROAS는 비율이라 **더할 수 없다** — 요인별로 쪼개 합산하려면 가법(加法) 지표여야 한다.

BEP RoAS 정의(= 판매가 ÷ 공헌이익)에서 공헌이익률 = 1/BEP 이므로:

```
ad_profit(원) = conv_amt / 1.711 − cost
```

- ROAS ≥ 1.711 ⟺ ad_profit ≥ 0 이라 **밴드 판정과 완전히 정합**한다(경계 재발명 0).
- 날짜·그룹·요인 층 위에서 **그냥 더해진다** → 「이 요인이 몇 원을 만들었나」가 바로 나온다.
- 한계 명시: ⓐ1.711은 계정 블렌디드라 저마진 상품은 넘겨도 적자일 수 있다(→ §4 상품 BEP 재판정)
  ⓑ네이버 광고 전환액 ≠ 스마트스토어 실주문 매출 ⓒBEP는 현재값(시대착오, ref 59 ②-5).

## 1. 분해 항등식 (이것이 산출물의 뼈대)

그룹 g, 날짜 d. `평시(baseline) 날짜` = 평일 ∧ 단독공휴일 아님 ∧ 명절연휴 아님 ∧ 휴가창 밖
∧ launch_phase = none ∧ data_gap 아님 ∧ mature.

```
b_g            = 평시 일평균 ad_profit (그룹 g)            ← 그룹의 «구조적» 흑자/적자율
residual_g     = b_g × (그룹 g의 관측일수)                 ← 외부 요인을 제거하고도 남는 것
excess_{g,L}   = Σ_{d ∈ L} ( ad_profit_{g,d} − b_g )       ← 요인 L이 만든 초과분(±)
총 ad_profit_g = residual_g + Σ_L excess_{g,L}             (라벨은 상호배타로 강제)
```

★**라벨 상호배타 강제**: 한 날짜가 여러 요인에 걸리면(주말×휴가창×F2) 이중계상된다.
우선순위를 **한 번** 못 박고 그 순서로 단일 라벨을 배정한다 — 그리고 그 선택이 결론을
얼마나 바꾸는지 순서를 바꿔 재계산해 민감도로 병기한다(파라미터 자백).
기본 우선순위: `F2 > F1b > F1a > 명절연휴 > 단독공휴일 > 휴가창 > 주말 > F3 > 평시`
(이유: 창이 좁고 사건성이 강한 것부터. F3은 180일이라 «평시의 배경»에 가까워 맨 뒤.)

**요일(F9)은 이 항등식에 안 넣는다** — 평시 안의 요일 편차로 따로 잰다(주말과 이중계상 방지).

## 2. 두 가지 baseline (둘 다 내고 갈리면 갈린다고 적는다)

| 변형 | b_g 정의 | 잡는 것 / 못 잡는 것 |
|---|---|---|
| **V1 전기간** | 창 전체 평시 일평균 | 단순·표본 두꺼움 / 1년 추세·BEP 변동을 요인에 뒤집어씌울 수 있다 |
| **V2 분기국소** | 같은 분기 평시 일평균(표본 <5일이면 V1로 폴백, 폴백 라벨 남김) | 추세 흡수 / 휴가창(7~8월)이 통째로 든 분기에서 **요인이 baseline에 먹힌다** |

★V2의 이 결함은 제거 불가다(휴가창 26일 vs 분기 91일). 그래서 **휴가창·출시 축은 V1을 정본으로,
요일·주말·공휴일 축은 V2를 정본으로** 삼고 표에 어느 쪽을 썼는지 열로 남긴다.

## 3. 「제거하고도 남는 흑자/적자」의 산출 형식

그룹별 1행: `residual_profit(원)` 내림차순 · `총 ad_profit` · `요인별 excess` · `cost` ·
`conv_amt` · `평시 관측일수` · `밴드(전기간)` · `밴드(평시만)` · `model` · `data_gap 포함 여부`.

- **적자 목록 = residual_profit < 0 인 그룹**, 절대액 병기. 이게 「달력 탓이 아닌 적자」다.
- **밴드(전기간) ≠ 밴드(평시만)인 그룹 목록**을 따로 낸다 — 「외부 요인이 판정을 뒤집은 그룹」.
  이 목록 자체가 Jino 질문(「외부정보가 혼합되어야 정확한 성과 측정」)의 직접적 답이다.
- 표본 얇은 그룹은 밴드④ 규칙(ref 59 ②-4)이 이미 거른다 — 새 문턱 만들지 않는다.

## 4. 상품 BEP 재판정 (계정 1.711과 갈리는 지점)

`naver_adgroup_product`(1,761행) × `naver_product_bep`(758행) → 그룹별 bep_roas.
기존 코드 규약을 그대로 쓴다: `search_term_exclusion_list._bep_map`이 **그룹 내 최소 bep_roas**를
쓰고 원가 미확인 상품은 자연히 빠진다. 같은 규약으로:
`ad_profit_prod = conv_amt / bep_g − cost` (bep_g 없으면 판정 안 함 — 1.711로 대체하지 않는다).
산출: **계정 BEP 판정과 상품 BEP 판정이 갈리는 그룹 목록**(ref 59 ⑤-3의 처리안 그대로).

## 5. X0 — Z폴드8 3중첩 분해 (ref 62 §4의 4법을 그대로 집행)

1. **비-Z폴드8 대조군**: 같은 기간(2026-07-28~08-16) Z폴드8·플립8 그룹 vs 나머지 그룹의
   `ad_profit/일` 변화를 **각자의 평시 baseline 대비**로 잰다. 전 그룹이 같이 나빠졌으면 휴가·계절,
   Z폴드8만 나빠졌으면 출시구간 또는 조치.
2. **작년 같은 위상**: Z폴드7 출시(2025-07-25) 그룹의 D0~D+10 프로파일과 대조 →
   「Z 시리즈 출시 직후의 통상 프로파일」. ★이건 **분리가 아니라 합성 효과의 기준선**이다(X5 준-공선).
3. **조치 시점 분리**: `naver_agency_op`(2026-07-23~08-16, 458건)를 Z폴드8 그룹에 붙여
   조치 전후로 잘라 본다. 창 내 4이벤트 중 **이 판별이 가능한 유일한 이벤트**다.
4. **F2 미완 라벨**: 오늘 D+10, mature 컷은 D0−8=2026-08-09 → **F2 28일 중 3일만 성숙**.
   부분창 라벨을 강제하고, 결론에 「진행 중」을 붙인다.

**출력 규율**: 위 4법의 결과가 갈리면 «분리 불가(합산 효과로 기술)»라고 쓴다.
n=1~2 교란쌍(X1·X5·X6)은 이번 라운드에서 «분리했다»고 쓰지 않는다(ref 62 §4 공통 규율).

## 7. 이 방법이 틀릴 수 있는 경로 (먼저 적고 시작한다)

1. **2026-03 공백** — 구멍이 baseline을 오염시킨다. 전 계산에서 `data_gap` 날짜를 **제외**하고,
   제외 사실과 제외 일수를 표에 명시. 구멍의 정체는 별도 조사 중.
2. **그룹 수명 편차** — 창 일부만 산 그룹의 residual은 일수로 나눠 비교(원단위 총액과 일평균 병기).
3. **역인과** — 「휴가창에 적자」가 요인 탓인지 그때 대행사가 무리한 탓인지 이 데이터로는 못 가른다.
   조치 축(27일)이 겹치는 구간에서만 부분적으로 갈린다. 나머지는 「합성」 라벨.
4. **전환 귀속** — 파워링크 검색어 grain은 전환 원리적 불가(모집단 제외, 규모만 집계).
5. **다중비교** — 요인 축이 7개다. 탐색창(앞 274일)/검증창(뒤 91일) 분할 재현 게이트(ref 59 ⑤-9)를
   요인 효과 «방향»에 적용한다. 단 휴가창·출시는 검증창에 표본이 몰려 있어 게이트가 성립 안 하는
   축이 있다 — 그 축은 「게이트 미적용」을 라벨로 남긴다(통과했다고 쓰지 않는다).
